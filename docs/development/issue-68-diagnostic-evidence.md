## Локальная проверка

1. На Windows: git fetch origin; git switch -C feature/issue-68-diagnostic-evidence origin/feature/issue-68-diagnostic-evidence. Ветка перенесена на актуальный main с переписанной историей; не делать обычный pull поверх локальной старой версии.
2. Запустить PostgreSQL. В каталоге backend выполнить mvn spring-boot:run; Flyway применит V13 после V10/V11 и V12 задачи #16.
3. Разрешить только локальные тестовые загрузки установкой GUITAR_MENTOR_ENABLE_UPLOADS=true. По умолчанию отключено. Настоящие личные медиа не использовать до реализации авторизации #38.
4. Внутренние каталоги: GUITAR_MENTOR_MEDIA_PATH для аудио и GUITAR_MENTOR_SCORE_PATH для PDF/JPG/PNG (по умолчанию ./.local-media/attempts и ./.local-media/scores). Доступа к сырым файлам по HTTP нет.
5. Нужен ffprobe из FFmpeg в PATH для проверки длительности и целостности аудио; можно задать GUITAR_MENTOR_FFPROBE.

## Тестирование владельцем

- Новичок: создать диагностическую сессию, не добавлять записи, сразу перейти к заданиям. Никакого штрафа навыкам.
- Загрузить запись знакомого произведения с названием, необязательным автором и PDF; прослушать перед отправкой. Убедиться, что появился один элемент с двумя материалами.
- Добавить вторую запись без PDF; F5: два отдельных элемента, стабильные названия, статус только технический.
- Перейти к заданиям: форма добавления скрыта, история остаётся доступна для чтения; прежние назначенные упражнения и попытки работают.
- Пустой/ложный PDF, перелимитный файл, 11-й пример и отключённые uploads отклоняются безопасно; продолжение без записи остаётся.
- Настоящий микрофон/отмена записи/прослушивание и очистка имени file input проверяются вручную.
- TTL из #21 удаляет аудио и ноты через 48 ч после финализации, но не удаляет название, метаданные и учебный каталог. Тестировать управляемым Clock или тестовыми timestamp.

## API для Postman

Префикс: /api/v1/learners/{learnerId}/diagnostic-sessions/{sessionId}/evidence

GET /capabilities: флаг enabled, форматы и лимиты.
GET /: список EvidenceView без storage_key/путей/байтов.
GET /{evidenceId}: один принадлежащий сессии пример по Location после POST.
POST /: multipart с requestId UUID, title строка до 200, composer опционально, comment опционально, audio file обязательно, score file опционально. Новый пример 201, повтор с прежним requestId 200, без новой записи.
Ошибки: 400 для форматов/лимитов и обязательных параметров, 403 отключено, 404 чужая сессия, 409 неверное состояние/лимит примеров и `IDEMPOTENCY_PAYLOAD_MISMATCH` при повторном UUID с отличающимися файлами или полями.

## Поправки после код-ревью 20.10.2026

- **P1 защита черновика:** дочерняя панель немедленно отправляет родителю агрегированное состояние active record/upload и локальных изменений; «Перейти к заданиям» недоступно при записи/загрузке, а несохранённый материал требует подтверждения отказа. При ошибке POST файлы и requestId остаются для безопасного повтора.
- **P1 отсутствие starvation TTL:** 25 повторных попыток удаления и до 50 впервые просроченных файлов выбираются независимыми SQL-запросами, с упорядочиванием повторных попыток по минимальному `delete_attempts`. Регрессионный PostgreSQL-тест создаёт 60 DELETE_PENDING и 1 новый expired; доказывает выбор нового и прогресс среди pending.
- **Интеграция:** #21 принята, V10/V11 находятся в main; V13 принадлежит #68; V12 принадлежит #16. При переносе сохраняются рекомендации диагностических упражнений из #16 и обе локали. PR не объединять без нового CI и повторного ревью.

### Ручные регрессионные сценарии защиты черновика

1. Начать запись с микрофона и нажать «Перейти к заданиям» → кнопка заблокирована, рекордер остаётся открытым. Остановить запись → появляется прослушивание и подтверждение при уходе; отмена подтверждения сохраняет запись.
2. Начать отправку аудио с искусственно замедленным POST → кнопка перехода заблокирована до ответа. Ошибка POST → выбранное аудио, ноты, название и requestId сохраняются для повтора.
3. Успешно отправить аудио → после подтверждения и окончания запросов перейти к заданиям без предупреждения. После F5 список остаётся доступен только для чтения.
4. При пустой форме переход без записи сразу работает.

## Защита выхода из формы после повторного код-ревью (#68)

- Навигация по `Назад`, логотипу, пунктам шапки, `router.push` и истории браузера через Vue Router контролируется `onBeforeRouteLeave`. Если микрофон активен или POST ещё выполняется, переход блокируется с понятным сообщением. Во время записи доступны остановка и отмена в `MicrophoneRecorder`.
- При несохранённом выборе аудио/нот или введённом тексте уход разрешён только после отдельного подтверждения. Отказ от подтверждения оставляет форму и файлы нетронутыми.
- `beforeunload` защищает F5 и закрытие вкладки стандартным браузерным предупреждением (окончательное решение о показе диалога принадлежит браузеру). Не считать это гарантией сохранения файлов после принудительного завершения браузера.
- Во время загрузки есть кнопка «Отменить загрузку»: `AbortController` прерывает клиентский запрос, но **не гарантирует откат на сервере**; введённые данные, выбранные файлы и прежний `requestId` сохраняются для идемпотентного повтора. Пока abort ещё не завершился, попытки покинуть страницу блокируются.
- Проверки: `npm run test:intake` запускает policy/router и компонентные тесты: реальный `DiagnosticView` с `onBeforeRouteLeave`, реальный setup `DiagnosticEvidencePanel`, политику `beforeunload`, смену `requestId` и GET после POST. `npm run build` проверяет vue-tsc и Vite.

### Ручные сценарии навигации
1. Начать запись микрофона → нажать «Назад», ссылку «Профиль» в шапке и кнопку Back браузера: страница и микрофон остаются. Остановить запись → попытаться уйти → подтвердить или отклонить предупреждение; при отказе файл доступен для прослушивания.
2. Прикрепить аудио и ноты, заполнить текст → нажать логотип и «Назад»: отмена диалога оставляет файлы, подтверждение выполняет переход.
3. Затормозить POST → переходы блокируются. Нажать «Отменить загрузку» → убедиться, что файл, ноты, название и `requestId` сохранены; повторить загрузку; не считать клиентскую отмену доказательством отсутствия серверной записи.
4. С несохранённым черновиком выполнить F5 и закрытие вкладки: если браузер поддерживает подтверждение beforeunload, оно появляется. Без черновика переходы/перезагрузка не предупреждают.

## Контракт идемпотентности после исправлений повторного ревью

- **V14** добавляет nullable `diagnostic_evidence.request_fingerprint CHAR(64)` без изменения checksum V13. Для новых загрузок сервер сохраняет SHA-256 от нормализованных названия/автора/комментария и байтов+имен аудио/партитуры. Отпечаток остаётся в БД после TTL очистки файлов.
- Один `requestId` связан строго с **одним** содержимым. Повтор с идентичными данными возвращает прежний результат (HTTP 200), включая повтор после назначения задания. Отличающийся payload возвращает **409 IDEMPOTENCY_PAYLOAD_MISMATCH** без удаления локального черновика и без ложного подтверждения нового файла. Ранее созданные записи без fingerprint безопасно отклоняют неопределённый повтор.
- Клиент сохраняет `requestId` при ошибке/отмене POST, когда содержимое формы неизменно. При изменении файла, нот, названия, автора или комментария немедленно создаёт новый UUID. Изменять форму во время POST нельзя.
- Флаг `uploading` означает только **POST**. Успешный POST сразу освобождает навигацию; следующий GET истории выполняется независимо и не удерживает `AbortController`. Ошибка GET не превращает успешную загрузку в повод отправлять ещё один POST.
- Регрессии PostgreSQL: файл A принят, ответ утрачен, попытка B с прежним UUID → 409 без потери B; новый UUID → B действительно создана; изменённое название или ноты с прежним UUID → 409. Vue component tests: отмена POST сохраняет прежний UUID и аудио до редактирования, редактирование создаёт новый UUID, зависший GET после успешного POST не оставляет состояние uploading=true.

### Дополнительные ручные проверки
1. Загрузить A с тестовыми файлами; при эмуляции обрыва ответа сменить аудио на B: получить **новый** requestId и независимую запись B. Серверное обращение B со старым requestId должно вернуть 409; проверить историю, чтобы A и B не перепутались.
2. Не менять форму после сбоя/Abort → повтор с исходным requestId возвращает одну существующую запись, если первый POST успел завершиться.
3. Смоделировать зависший GET списка сразу после успешного POST: исчезает блокировка навигации и можно перейти к заданиям, без новой отправки аудио.
