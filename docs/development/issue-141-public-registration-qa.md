# #141 — Публичная регистрация: план независимого тестирования и пользовательской приёмки

**Решение 24.10.2026:** регистрация свободная; код приглашения в форме отсутствует. Первая Google-регистрация тоже свободная. Предыдущие приёмочные шаги с приглашением отменены.

## Предусловия

- Проверить SHA ветки `feature/141-auth-email-password` и успешный Java/Vue/Audio CI именно для него.
- Применить **только** новую Flyway V22 к существующим V20/V21; не редактировать применённые миграции. Перед изменениями на реальной БД проверить читаемость резервной копии.
- Остановить старый backend; запустить один backend из ветки. Не использовать внешнее развертывание в обход #39/#40.
- Для регистрации нужен серверный SMTP или изолированный SMTP capture. Письма с кодами не публиковать в чате, CI и скриншотах. Без настроенного SMTP регистрация должна завершиться отказом, а не активировать аккаунт.
- Если тестирование выполняется по HTTP, это допускается только в существующем **loopback-only** QA-режиме, не для публичной сети. Проверить secure-cookie/CSRF настройки для выбранного origin.
- Тестовые адреса и логины уникальны, пароли — только тестовые. В основной базе тестовые пользователи остаются как отдельные Account/Learner; не использовать реальные персональные данные.

## Автоматические проверки

- Java компиляция, PostgreSQL/Flyway V22 upgrade, локальная регистрация без invitation в HTTP DTO, CSRF на POST.
- Pending аккаунт не входит; email proof создаёт одного LEARNER; replay verification не активирует повторно.
- Дубликаты pending/active email и username; generic 202 для повторной регистрации без раскрытия существования учётной записи.
- Login email/username, неверный пароль, DISABLED, session/access_version, reset/change и их токены.
- Google с verified email создаёт отдельного LEARNER при первом входе; Google identity не объединяется автоматически с локальным Account при совпадении email.
- Регрессия метода link в профиль и старых Google/OWNER учётных записей; V18–V21 untouched.
- Frontend build и тесты, отсутствие code invitation на странице регистрации.

## Stop / Go

Не принимать и не объединять PR при красном Java CI, нарушении авторизации или ownership, раскрытии кодов, активации без verification, невозможности пройти регистрацию через SMTP capture, либо неисправленном блокирующем дефекте. Реальные Google OAuth, доставка и браузерные испытания требуют пользовательского окружения. Итог приёмки утверждает владелец.
