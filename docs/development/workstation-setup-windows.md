# Guitar Mentor AI — настройка рабочего места разработчика (Windows 10)

> **Назначение:** единая инструкция для нового участника проекта и для восстановления рабочего окружения после смены компьютера.
>
> **Проверено:** 18.10.2026. Описаны шаги, выполненные при первоначальной настройке проекта на Windows 10, и команды текущего этапа DEV-01. При дальнейшем развитии проекта обновляйте этот документ вместе с конфигурацией зависимостей.

## 0. Что именно мы устанавливаем

Проект: **Guitar Mentor AI** — Python-приложение, которое постепенно превратится в Telegram-бота с ИИ-наставником по игре на гитаре.

- **GitHub-репозиторий:** https://github.com/roafo1989/guitar-mentor-ai (приватный; необходим выданный владельцем доступ).
- **ОС для данной инструкции:** Windows 10 x64.
- **Проверенная локальная папка:** `D:\Development\guitar-mentor-ai`. На другом ПК можно выбрать любой удобный путь.
- **Рабочая версия Python при первой настройке:** 3.13.16. В `pyproject.toml` заявлен минимум Python 3.11, но для максимально близкого воспроизведения используйте Python **3.13.x**.
- **Текущий статус на 18.10.2026:** в `main` есть базовый README; рабочий Python-каркас DEV-01 находится в ветке `feature/dev-01-python-bootstrap`, см. [PR #5](https://github.com/roafo1989/guitar-mentor-ai/pull/5). После слияния PR работайте с `main`.

На этом этапе **не нужны** Docker, Node.js, Java/JDK, отдельный сервер, WSL, PowerShell 7 или ключи Telegram/OpenAI. Они не входят в необходимый набор DEV-01. GitHub Copilot — необязательное дополнение к VS Code, а не требование для запуска.

## 1. Установка программ (чистая Windows 10)

Установите три программы в указанном порядке. Ссылки ведут на официальные сайты.

| Программа | Откуда скачать | Что выбрать при установке |
|---|---|---|
| **Visual Studio Code** | https://code.visualstudio.com/download | **Windows User Installer x64** (`VSCodeUserSetup-x64`), если используется обычный ПК x64 |
| **Git for Windows** | https://git-scm.com/install/windows | **Git for Windows/x64 Setup**. Разрешить Git из командной строки и сторонних программ; **Git Credential Manager** оставить помощником для входа |
| **Python 3.13.16** | https://www.python.org/downloads/release/python-31316/ | **Windows installer (64-bit)**, обычный установщик (не Python Install Manager). Отметить **Add python.exe to PATH**; оставить установку **Python Launcher** |

После установки закройте и вновь откройте PowerShell и VS Code, чтобы они увидели обновлённый PATH.

### 1.1. Расширения VS Code

Откройте VS Code → **Extensions** (`Ctrl+Shift+X`) и установите:

1. **Python** от Microsoft — `ms-python.python`;
2. **Pylance** от Microsoft — `ms-python.vscode-pylance`.

**Git** уже поставляется отдельно и интегрируется с VS Code. Для базовой работы **не нужно** отдельно устанавливать GitHub Desktop или расширение Copilot.

### 1.2. Проверка установленных программ

Откройте **PowerShell** (подходит встроенный в Windows 10 **Windows PowerShell 5.1**):

```powershell
git --version
py -3.13 --version
python --version
```

Первые две команды должны вывести версии Git и Python 3.13.x. Если `python --version` показывает другую версию, для создания окружения ниже всё равно используйте `py -3.13`.

Опционально: `code --version` проверяет доступность команды VS Code из терминала. Если `code` не найден, можно открывать проект через **File → Open Folder** — запуск приложения от этого не зависит.

## 2. Первоначальная настройка Git и GitHub

### 2.1. Укажите автора будущих коммитов

В PowerShell **подставьте своё имя и почту GitHub**, а не копируйте примеры дословно:

```powershell
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

git config --global --get user.name
git config --global --get user.email
```

У каждого участника — собственные имя и email, а не учётные данные владельца репозитория.

### 2.2. Авторизация в приватном репозитории

При первом `git clone` / `git pull` / `git push` через HTTPS **Git Credential Manager** может открыть окно авторизации. В ходе первоначальной настройки мы выбрали **Sign in with your browser**, вошли в свою учётную запись GitHub и одобрили запрошенный доступ. Пароль GitHub или Personal Access Token **не требуется вручную вставлять в команду**.

Если GitHub возвращает **Repository not found** или 403, сначала проверьте, что ваша учётная запись действительно имеет доступ к приватному репозиторию. Публичная ссылка сама по себе не даёт права на клонирование.

Для диагностики помощника авторизации:

```powershell
git config --show-origin --get credential.helper
```

При стандартной установке Git for Windows используется Git Credential Manager. Не переключайте помощник на хранение секретов в открытом виде.

## 3. Скачивание проекта на новый компьютер

Откройте PowerShell. **Если есть диск D:**, используйте первоначальный путь:

```powershell
New-Item -ItemType Directory -Force -Path D:\Development | Out-Null
Set-Location D:\Development
git clone https://github.com/roafo1989/guitar-mentor-ai.git
Set-Location .\guitar-mentor-ai
```

Если **диска D: нет**, замените первые две команды на:

```powershell
New-Item -ItemType Directory -Force -Path "$HOME\Development" | Out-Null
Set-Location "$HOME\Development"
```

Затем выполните те же `git clone` и `Set-Location .\guitar-mentor-ai`.

### 3.1. Выберите ветку с исходным кодом

**Пока PR #5 не слит:**

```powershell
git switch feature/dev-01-python-bootstrap
git branch --show-current
```

Ожидаемое имя ветки — `feature/dev-01-python-bootstrap`. В ней находятся `pyproject.toml`, каталог `src`, тесты и конфигурация CI.

**После слияния PR #5** вместо переключения на feature-ветку используйте:

```powershell
git switch main
git pull --ff-only
```

Если вы только что клонировали проект уже после слияния PR, вы обычно сразу будете на актуальной `main`, и отдельное переключение не нужно.

> **Важно:** все дальнейшие команды выполняются **из корня репозитория**, где лежит `pyproject.toml`.

## 4. Создание изолированного Python-окружения

`.venv` — локальное окружение Python. Оно создаётся **на каждом компьютере заново**, не переносится между ПК и не добавляется в Git.

```powershell
py -3.13 -m venv .venv

.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Последняя команда устанавливает сам пакет в режиме редактирования и dev-инструменты из **`pyproject.toml`** (на DEV-01 — `pytest` и `ruff`). Отдельный `requirements.txt` сейчас не нужен.

Здесь намеренно используется полный путь к `.\.venv\Scripts\python.exe`: **активация окружения через `Activate.ps1` не обязательна**. Поэтому не требуется менять политику выполнения PowerShell, если система запрещает запуск скриптов.

## 5. Открытие проекта в VS Code

1. В VS Code выберите **File → Open Folder** и откройте `D:\Development\guitar-mentor-ai` (или выбранную вами папку).
2. Если VS Code спрашивает **Do you trust the authors of the files in this folder?**, доверяйте папке **только если** вы уверены в происхождении клонированного репозитория.
3. Нажмите `Ctrl+Shift+P` → **Python: Select Interpreter** → выберите **`.\.venv\Scripts\python.exe`**. Если автоматически не обнаружен, укажите этот путь вручную.
4. Откройте **Terminal → New Terminal**. Можно использовать встроенный PowerShell.

Точка проверки: VS Code использует интерпретатор из `.venv`, а не глобальный Python; подсказки и анализ кода обеспечивают Python + Pylance. При выполнении команд из следующего раздела выбор интерпретатора VS Code не критичен, потому что путь к Python указан явно.

## 6. Проверка, что всё работает

В **корне проекта**:

```powershell
.\.venv\Scripts\python.exe -m guitar_mentor --check
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
git status
```

Для текущего DEV-01 проверка приложения должна вывести:

```text
OK: Guitar Mentor AI bootstrap is ready.
```

При первой локальной настройке (17–18.10.2026) тесты успешно проходили (было **4 passed**), а `ruff check .` завершался без ошибок. Число тестов может вырасти с развитием проекта; требование — отсутствие ошибок тестирования и линтера.

**Это пока проверка каркаса, а не запуск Telegram-бота.** Реальные команды бота и обработка сообщений появятся на следующем этапе разработки.

## 7. Переменные окружения и секреты

В репозитории есть `.env.example` со списком будущих параметров:

| Имя | Для чего |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `OPENAI_API_KEY` | Ключ доступа к OpenAI API |
| `GUITAR_MENTOR_DATA_DIR` | Локальная папка данных (по умолчанию `./data`) |

**Для DEV-01 токены не нужны.** В текущем каркасе `src/guitar_mentor/config.py` читает переменные **из окружения процесса ОС**, но **автоматическое чтение файла `.env` пока не реализовано**. Поэтому простое копирование `.env.example` в `.env` само по себе пока ничего не настроит.

При появлении интеграций секреты задавайте в безопасном локальном окружении или секрет-хранилище согласно будущей инструкции запуска. Не записывайте реальные токены в исходный код, README, скриншоты, историю команд терминала и репозиторий.

**Нельзя коммитить:** `.env`, `.venv`, ключи/токены, `data/`, локальные БД SQLite (`*.db`, `*.sqlite*`), аудио/видео и загруженные файлы учеников. Основные исключения уже включены в `.gitignore`.

## 8. Повседневная работа и переезд на другой ПК

### Уже установленный проект — забрать изменения

```powershell
# Откройте каталог клонированного репозитория
git status
git branch --show-current
git pull --ff-only

# После изменений зависимостей при необходимости повторите:
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Перед переключением ветки и загрузкой изменений сохраните или закоммитьте собственные локальные правки; `git pull --ff-only` не должен перезаписывать незакоммиченную работу.

### Полностью новый компьютер — короткий чек-лист

1. Установить VS Code, Git for Windows (с Git Credential Manager) и Python 3.13.x.
2. Установить расширения Python и Pylance в VS Code.
3. Настроить имя и email Git; иметь доступ к приватному GitHub-репозиторию.
4. Клонировать проект и выбрать нужную ветку (см. раздел 3.1).
5. Создать `.venv`, установить `-e ".[dev]"`.
6. Выбрать Python-интерпретатор `.venv` в VS Code.
7. Запустить проверку `--check`, `pytest`, `ruff`.
8. Когда будут добавлены интеграции — отдельно восстановить **секреты и локальные данные**, которые намеренно **не хранятся в GitHub**.

**Важно:** GitHub содержит код и историю коммитов, но **не является резервной копией** локальной базы, токенов и пользовательских медиа. Для восстановления данных нужна отдельная, безопасная стратегия хранения и резервного копирования, если эти данные требуется сохранять.

## 9. Частые проблемы

| Симптом | Что проверить |
|---|---|
| `git` не распознаётся | Переоткрыть PowerShell/VS Code после установки Git; убедиться, что Git добавлен в PATH |
| `py -3.13` не найден | Проверить наличие Python 3.13 и Python Launcher; при необходимости повторить установку Python |
| `python` запускает Microsoft Store или другую версию | Для проекта пользоваться `py -3.13` и затем `.\.venv\Scripts\python.exe` |
| Ошибка 403 / Repository not found при `git clone` | Проверить доступ к **приватному** репозиторию и правильность GitHub-учётной записи в браузере/Git Credential Manager |
| `pyproject.toml` не найден при `pip install -e` | Проверить текущий каталог и ветку: каркас находится в feature-ветке до слияния PR #5 |
| VS Code подсвечивает импорты как несуществующие | Выбрать через **Python: Select Interpreter** Python из `.venv` |
| PowerShell блокирует `Activate.ps1` | Не менять политику ради проекта; вызывать `.\.venv\Scripts\python.exe` напрямую |
| После перехода на другой ПК пакет не запускается | Не копировать старую `.venv`, а создать новую и повторить установку зависимостей |
| `.env` заполнен, но приложение не видит значения | На DEV-01 автоматической загрузки `.env` **нет**; сейчас поддерживаются переменные окружения процесса |

## 10. Дополнительные ориентиры

Для разработчика с опытом Java:

- `pytest` — тестовый фреймворк (по назначению похож на JUnit).
