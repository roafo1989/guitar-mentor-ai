# #21 — локальная политика хранения аудиозаписей

Профиль: один backend JVM, одна локальная папка. Не запускать две JVM с общей папкой.
По умолчанию 48 часов после завершения всей цепочки TECHNICAL_ONLY_V1 и 48 часов для незавершённой записи. История попыток и компактные результаты в PostgreSQL остаются. Учебные примеры MP3/PDF не входят в storage path и не удаляются.

Настройки (PostgreSQL):
```sql
BEGIN;
UPDATE system_settings SET setting_value='48',updated_at=now()
 WHERE setting_key='media.retention_after_processing_hours';
UPDATE system_settings SET setting_value='48',updated_at=now()
 WHERE setting_key='media.max_unprocessed_age_hours';
UPDATE system_settings SET setting_value='60',updated_at=now()
 WHERE setting_key='media.cleanup_interval_minutes';
COMMIT;
```
Значения — положительные целые. Удаление при невалидной политике не производится. Применение без перезапуска на следующем служебном тике (~60 секунд). Удаление может задержаться, если занят worker/upload или возникла ошибка ОС; фактическое удаление отделено от окончания обработки.

## Проверка локально
1. Выполнить миграции Flyway V10 на копии тестовой БД, проверить старые ID и requestId.
2. Проверить валидное и невалидное значение policy; при невалидном не должны исчезать файлы.
3. Сохранить тестовый WAV, дождаться PROCESSED, искусственно сдвинуть processing_finalized_at назад SQL на 49 часов, не меняя реальные пользовательские файлы.
4. На следующем цикле проверить DELETE_PENDING → DELETED, media_deleted_at, сохранение status, comment, checksum и старого requestId.
5. Прервать JVM после DELETE_PENDING либо после удаления файла; после restart должно подтвердиться DELETED через ALREADY_ABSENT.
6. Повторить при отключённых uploads, а также с занятым worker.
7. Создать отдельный тестовый orphan старше 48 часов с валидным UUID-ключом, проверить отсутствие ссылки в БД и очистку; symlink и случайное имя не удалять.
8. Проверить русский и английский UI; старый requestId возвращает старую попытку без восстановления файла.

Настоящие аудиозаписи и производные материалы сторонних сервисов (Telegram, ИИ) этой политикой не охватываются. Не направлять media_key, файловые пути или аудиоданные в логи. Операция физического удаления необратима; SQL rollback её не восстанавливает.

## Ограничения проверки
Изменения в ветке до независимого тестирования; результаты PostgreSQL/HTTP/CI и конкурентных тестов должны быть подтверждены на PR. До этих проверок не включать очистку на папке с ценными записями.
