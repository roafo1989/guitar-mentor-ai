# Локальный адрес https://guitar-mentor на Windows 10 (Caddy)

**Задача:** открывать Guitar Mentor AI в браузере по адресу **`https://guitar-mentor`** — без `.localhost`, `:5173` и платы за DNS/VPS.

> Эта настройка **только для одного компьютера**. Это не реальный публичный домен. Она не добавляет авторизацию: использовать только локально с тестовыми данными, не открывать порты в роутере или firewall. Конфигурация Caddy привязана к `127.0.0.1`; Vite и Spring Boot тоже должны оставаться на loopback. HTTPS нужен для защищённого контекста браузера и будущего доступа к микрофону.

## Как устроено

```text
https://guitar-mentor   [браузер Windows]
          |
hosts: guitar-mentor -> 127.0.0.1
          |
Caddy 127.0.0.1:443 (HTTPS, локальный сертификат)
          |
Vite 127.0.0.1:5173 (HTTP, веб-интерфейс)
          |
Vite /api -> Spring Boot 127.0.0.1:8080 (HTTP)
          |
PostgreSQL localhost:5432
```

**Почему здесь три разных порта:** порт `443` браузер использует автоматически для HTTPS, Caddy перенаправляет запросы на `5173`, а Vite уже проксирует `/api` к backend. В браузерной строке будет только `https://guitar-mentor`. Caddy также передаёт WebSocket для горячей перезагрузки Vue.

## 0. Получить конфигурацию из репозитория

В PowerShell (обычном, без администратора):

```powershell
cd D:\Development\guitar-mentor-ai
git status
git switch main
git pull --ff-only
```

Если `git status` показывает локальные изменения, **не переключать ветки насильно**: сохранить изменения коммитом или `git stash` только после проверки содержимого.

Понадобятся файлы `infra/local/Caddyfile` и обновлённый `frontend/vite.config.ts`.

## 1. Установить Caddy (бесплатно)

1. Скачать **официальную сборку Windows amd64** с https://caddyserver.com/download или со страницы https://github.com/caddyserver/caddy/releases (проверить, что источник — caddyserver).
2. Скачать исполняемый файл и поместить его в `C:\Tools\Caddy\`. У файла может быть имя **`caddy_windows_amd64.exe`** (именно так оказалось при практической установке); переименовать его в **`caddy.exe`**. Если Windows скрывает расширения, в проводнике достаточно переименовать `caddy_windows_amd64` в `caddy`. Если файл внутри ZIP — предварительно распаковать.
3. Проверить в PowerShell:

```powershell
& 'C:\Tools\Caddy\caddy.exe' version
```

Можно добавить папку в PATH, но **не обязательно**: следующие команды используют полный путь. Не скачивать исполняемый файл из неизвестных источников. Если PowerShell пишет «термин `C:\Tools\Caddy\caddy.exe` не распознаётся», сначала выполнить `Test-Path 'C:\Tools\Caddy\caddy.exe'` и проверить **имя файла**, не переустанавливая другие компоненты.

**Проверенная версия 18.10.2026:** `v2.11.7` (другие поддерживаемые версии 2.x также возможны).

## 2. Прописать имя в hosts

1. Открыть **Блокнот от имени администратора** (Пуск → Блокнот → «Запуск от имени администратора»).
2. **Файл → Открыть**: `C:\Windows\System32\drivers\etc\hosts`. В диалоге переключить тип файлов с «Текстовые документы» на **«Все файлы»**.
3. Добавить ровно одну строку (если ещё нет такой):

```text
127.0.0.1 guitar-mentor
```

4. Сохранить. Никаких записей для внешних IP и IPv6 добавлять не требуется. Проверка в PowerShell:

```powershell
ping -4 guitar-mentor
```

Ожидаемый адрес — **127.0.0.1**. Команда `nslookup` может не показывать содержимое `hosts` (она обращается к DNS), поэтому для этого теста лучше `ping`. Если имя не разрешается — проверить права сохранения, убрать опечатки и выполнить `ipconfig /flushdns`.

## 3. Запустить backend, frontend и Caddy

Нужны **три терминала** VS Code или PowerShell, PostgreSQL уже должен работать.

**Терминал 1 — Spring Boot:**

```powershell
cd D:\Development\guitar-mentor-ai\backend
$password = Read-Host "Пароль guitar_mentor_app" -AsSecureString
$env:SPRING_DATASOURCE_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
# Только для локальной разработки с синтетическими данными.
# Защищённый режим по умолчанию требует настроенного OIDC.
$env:GUITAR_MENTOR_SECURITY_ENABLED = 'false'
.\mvnw.cmd spring-boot:run
```

Эти команды работают и в Windows PowerShell 5.1, и в PowerShell 7. Они считывают пароль без отображения и передают его приложению через переменную окружения текущего процесса. Не выводите её содержимое в терминал и не записывайте пароль в Git. Если база уже настроена — используйте свой текущий способ запуска.

**Терминал 2 — Vue:**

```powershell
cd D:\Development\guitar-mentor-ai\frontend
npm ci
npm run dev
```

`npm ci` нужен только при первой установке/изменении зависимостей. Vite продолжает слушать `127.0.0.1:5173`.

**Терминал 3 — Caddy** (из корня репозитория):

```powershell
cd D:\Development\guitar-mentor-ai
& 'C:\Tools\Caddy\caddy.exe' validate --config .\infra\local\Caddyfile --adapter caddyfile
& 'C:\Tools\Caddy\caddy.exe' run --config .\infra\local\Caddyfile --adapter caddyfile
```

Не закрывать этот терминал во время работы. Caddy должен прослушивать `127.0.0.1:443`, а не `0.0.0.0:443`. Глобальная опция `auto_https disable_redirects` выключает создание ненужного HTTP-redirect listener на 80/tcp, **но не** выпуск локального HTTPS-сертификата.

## 4. Один раз доверить локальный сертификат

Caddy использует `tls internal`: это **не сертификат из интернета** и не платный сертификат, а локальный CA. Браузер должен доверять его корневому сертификату.

При первом запуске Caddy может попытаться сам установить корневой сертификат, но без администраторских прав это часто не удаётся. **Когда Caddy уже запущен (терминал 3):**

1. Открыть **другое** окно PowerShell **от имени администратора**.
2. Выполнить:

```powershell
& 'C:\Tools\Caddy\caddy.exe' trust
```

3. Согласиться на импорт **только если это локальный корневой сертификат Caddy, установленного из официального источника**, затем перезапустить браузер.

Команда `caddy trust` получает сертификат у запущенного Caddy через локальный admin API. Она не предназначена для получения публичного сертификата. **Никому не передавать** файл приватного ключа и не коммитить файлы `Caddy`/сертификаты в репозиторий. Если используется Firefox со своим хранилищем доверенных сертификатов, может потребоваться разрешить системные корневые сертификаты или импортировать именно корневой сертификат Caddy вручную.

Удалить доверие после отказа от локального сервера можно командой `caddy untrust` в администраторском PowerShell; перед выполнением сверить справку своей версии Caddy.

## 5. Открыть приложение

**`https://guitar-mentor`** — адрес без порта и без `.localhost`.

Проверить:
1. Браузер показывает HTTPS без предупреждения о сертификате, в адресе нет `:5173`.
2. Страница профиля `https://guitar-mentor/profile` открывается, затем `/onboarding` и сохранение анкеты работает.
3. В DevTools → Network вызовы `/api` идут через **тот же origin** `https://guitar-mentor`; в браузере нет прямого вызова backend `8080`.
4. Перезапускать Caddy, Vite или Spring Boot можно по отдельности. После остановки Caddy адрес перестанет открываться, хотя dev-server продолжит работать на `127.0.0.1:5173`.
5. Для будущего микрофона HTTPS даёт безопасный контекст (`window.isSecureContext`), однако разрешение микрофона пользователь выдаёт дополнительно в браузере.

**ВАЖНО о ранее созданном ученике:** `localStorage` привязан к *origin* (схема + hostname + порт). Данные `http://127.0.0.1:5173` автоматически не переносятся на `https://guitar-mentor`. Существующий профиль остаётся в PostgreSQL, но веб-анкета не будет помнить его UUID. **Не нажимать «Создать профиль» до восстановления старой привязки** — иначе можно создать дубликат.

### 5.1. Перенос уже существующего тестового профиля на новый адрес

Способ ниже **проверен на Windows 10 с Chrome 18.10.2026**. Меняем только локальный указатель на существующего ученика; **не переносим строки БД и не создаём нового ученика**.

1. При запущенных PostgreSQL, backend и Vite открыть старый URL **`http://127.0.0.1:5173/profile`**. Убедиться, что там отображаются ожидаемые имя, инструмент и музыкальные предпочтения. При необходимости увидеть плашку «Профиль загружен из PostgreSQL».
2. На **старой** странице открыть Chrome DevTools клавишей **F12** → вкладка **Application** → **Storage → Local storage** → **`http://127.0.0.1:5173`**.
3. Скопировать **только Value** записи с точным Key **`guitar-mentor.learnerId`**. Это идентификатор (UUID). Не публиковать его в issue, README или снимках экрана общедоступного репозитория: API пока без аутентификации.
4. Открыть **`https://guitar-mentor/profile`** в другой вкладке. DevTools → Application → Local storage → **`https://guitar-mentor`**; создать строку с Key **`guitar-mentor.learnerId`** и **тем же Value**, либо исправить существующее значение. Убедиться, что в обеих вкладках одинаковое значение, без кавычек и лишних пробелов.
5. Обновить **новую** вкладку клавишей **F5**. Приложение выполнит `GET /api/v1/learners/{id}` и должно показать исходные имя, инструмент, предпочтения и уведомление о загрузке из PostgreSQL.
6. Перейти на **`https://guitar-mentor/onboarding`** и проверить, что в форме отображаются ранее сохранённые уровень игры, стаж, навыки и произведения. Перейти на шаг 2 и проверить цели/режим занятий; при необходимости обновить F5. **Сначала проверять чтение**, не нажимать «Сохранить» до уверенности в правильности профиля.

Приложение использует ключ `guitar-mentor.learnerId` из `frontend/src/stores/learner.store.ts`. При `HTTP_404` магазин может удалить неактуальную ссылку на ученика из `localStorage`; это **не удаляет** запись в PostgreSQL. Если ID не найден, проверить правильный backend/БД и использовать сохранённый исходный ID, а не создавать профиль автоматически.

## 6. Диагностика

| Симптом | Проверка и решение |
| --- | --- |
| `guitar-mentor` не разрешается | Проверить `hosts` и `ping -4 guitar-mentor`. `nslookup` не подходит для проверки hosts. |
| Не открывается HTTPS / `connection refused` | Caddy запущен? Прослушивается ли 443: `Get-NetTCPConnection -LocalPort 443 -State Listen`? Нет ли другой службы на порту? |
| Браузер предупреждает о сертификате | Выполнить `caddy trust` с повышенными правами; перезапустить браузер. Не обходить предупреждение кнопкой «всё равно перейти». |
| `502 Bad Gateway` | Caddy запущен, но Vite не слушает `127.0.0.1:5173`. |
| Ошибка загрузки данных `/api` | Проверить терминал Spring Boot, PostgreSQL и конфигурацию Vite proxy. |
| Vite пишет `Blocked request. This host is not allowed` | Выполнить `git pull --ff-only`, проверить `server.allowedHosts: ['guitar-mentor']`, перезапустить Vite. Не устанавливать `allowedHosts: true`. |
| Vue не обновляется автоматически | Проверить Caddy, WebSocket/HMR в DevTools; proxy должен поддерживать WebSocket. |
| `443` занят | Проверить, какой процесс владеет портом (`Get-NetTCPConnection` и `Get-Process`); **не останавливать чужие системные службы наугад**. Для короткого URL без порта нужен свободный 443. |
| Страница открылась, но «ученик пропал» | Origin поменялся. Данные в PostgreSQL не удалены; нужен перенос тестового UUID, а не импорт из старого localStorage автоматически. |

## 7. Границы и дальнейшее развитие

- `infra/local/Caddyfile` — **только dev**. Для настоящего публичного домена, Linux/VPS, доступа по приглашениям и OIDC нужно отдельное развертывание, см. [DEPLOY-00 #37](https://github.com/roafo1989/guitar-mentor-ai/issues/37) и [PR #41](https://github.com/roafo1989/guitar-mentor-ai/pull/41).
- **Нельзя** менять `bind 127.0.0.1` на `0.0.0.0`, открывать порты 443/5173/8080/5432 на роутере или отключать защиту `allowedHosts` до реализации серверной аутентификации.
- `https://guitar-mentor` можно добавить в закладки: при вводе только слова `guitar-mentor` некоторые браузеры запускают поиск, а не переход на локальный ресурс.
- Windows 10 достигла окончания обычной поддержки, поэтому подключение этого компьютера к интернету требует внимания к своевременным обновлениям ОС; это не причина открывать приложение в публичную сеть.
