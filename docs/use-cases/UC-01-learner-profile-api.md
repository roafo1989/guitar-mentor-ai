# UC-01 — Профиль ученика и музыкальные предпочтения (первый вертикальный срез)

## Зачем
До диагностики и планирования уроков приложение должно знать, на чём и как ученик собирается играть и какие музыкальные стили ему интересны или противопоказаны с точки зрения мотивации.

## Схема
- Learner: отдельная сущность ученика.
- InstrumentProfile: инструмент, техника, набор музыкальных предпочтений. Один ученик может иметь несколько InstrumentProfile, но в этом инкременте создаётся только один.
- MusicPreference: styleCode + rating (LIKE / NEUTRAL / EXCLUDE). Отношение к стилю не эквивалентно уровню навыка.

## Временный REST API
- POST `/api/v1/learners` — создать профиль (201 Created)
- GET `/api/v1/learners/{uuid}` — получить профиль (200 либо 404)
- PUT `/api/v1/learners/{uuid}/preferences` — заменить стили для инструмента (200 либо 404)

Пример POST:

```json
{
  "displayName": "Student",
  "instrumentCode": "ACOUSTIC_GUITAR",
  "techniqueCode": "FINGERSTYLE",
  "preferences": [
    {"styleCode": "BLUES", "rating": "LIKE"},
    {"styleCode": "BLUES_ROCK", "rating": "LIKE"},
    {"styleCode": "FUNK", "rating": "EXCLUDE"}
  ]
}
```

На этом этапе коды инструментов, техник и жанров — символьные значения. Каталоги и локализованные подписи будущего интерфейса (в стиле JHipster) спроектируем отдельно.

## Бизнес-правила
- При формировании следующего учебного задания нельзя навязывать стили с EXCLUDE без изменения предпочтения учеником.
- Списки предпочтений можно корректировать, не удаляя профиль ученика.
- Нельзя дублировать styleCode внутри одного InstrumentProfile.
- Приоритеты музыкальных стилей и техника игры не являются оценкой навыков; диагностика — отдельный UC.

## Ограничение безопасности первой итерации
**На этих REST-эндпоинтах пока нет аутентификации и авторизации.** Это только локальный прототип для одного разработчика. Запускать сервер публично, пробрасывать порт и развёртывать для других пользователей нельзя. В приложении выставляем loopback-bind `127.0.0.1` по умолчанию. Прежде чем подключать Vue/Telegram с реальными пользователями, добавим идентификацию/изоляцию профилей.
