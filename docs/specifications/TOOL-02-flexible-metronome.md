## Сценарий и интерфейс

Основной экран прежнего окна: крупный BPM **с длительностью ноты**, ±1 и Tap, размер N/D, кнопки Start/Stop, сетка счётных позиций и общая громкость. Сильная/средняя/слабая/тихая позиция различима формой/подписью и звуком; активная позиция выделяется отдельно от типа акцента. Цвет — дополнительный признак.

Нажатие на позицию циклически меняет **сильная → средняя → слабая → без звука**. У всех позиций, включая первую, одинаковые права редактирования. В раскрываемом блоке «Ритм и звук»: группы, единица BPM, подразделения, три уровня акцентов, громкость выбранной позиции и подразделений, сохранение/выбор пресета, сброс. Детали не закрывают Start/Stop и принятую кнопку «Свернуть и продолжить»; при асинхронном starting кнопка остаётся в фокусе, повторы не создают второй запуск. Не требовать long press, hover, точного drag или только жеста: элементы доступны кликом и клавиатурой.

Окно не теряет форму ученика, выбранный файл или материал. Сетка до 16 позиций переносится строками; на ширине 360 CSS px нет горизонтальной прокрутки страницы. Нажимаемая область основных кнопок/позиций не менее 44×44 CSS px — проектный UX-критерий, не характеристика конкурентов. В диалоге удерживается Tab/Shift+Tab; новые select/range тоже входят в фокус. Escape/явное закрытие останавливает звук и возвращает фокус инициатору; minimize возвращает фокус и доступ к странице, сохраняя звук. Случайный клик на backdrop ничего не делает. Подсвеченная иконка в header позволяет снова открыть управление. RU/EN для всех подписей, ошибок и имён заводских пресетов. Пользовательские имена не переводятся и не интерпретируются как HTML. Screen reader сообщает статус и изменение настройки, не озвучивает поток быстрых тиков.

## Размер, пульс и музыкальная семантика

**Счётная позиция** — одна единица знаменателя D; их N в такте. Для 6/8 это шесть восьмых, сгруппированных 3+3, а не шесть четвертей. Группа — способ акцентирования, она не прибавляет ударов и не меняет длину такта.

| Настройка | Допустимые значения / исходное состояние |
| --- | --- |
| Размер | N целое 1…16; D одно из 2,4,8,16; default 4/4 |
| Быстрые размеры | 2/4,3/4,4/4,5/4,6/8,7/8,9/8,12/8; «Свой» открывает N/D |
| Группы | Массив положительных целых, сумма=N. 6/8→3+3; 9/8→3+3+3; 12/8→3+3+3+3; 5/4→3+2; 7/8→2+2+3. Остальные default одна группа N. Разрешено изменить порядок/состав, например 7/8→3+2+2 |
| BPM | Целое 20…240, исходно 80; это частота **показанной единицы темпа**, не всегда четверти |
| Единица темпа | QUARTER (четверть), EIGHTH (восьмая), DOTTED_QUARTER (четверть с точкой); рядом с BPM всегда и значок, и доступное текстовое имя |
| Подразделение позиции | 1 (нет дополнительных тиков), 2,3,4 равных частей единицы 1/D; без swing. Подпись объясняет основу деления, а не всегда называет её «восьмыми» |

Выбор быстрого размера задаёт его группы и исходные акценты; 6/8,9/8,12/8 предлагают DOTTED_QUARTER, остальные QUARTER. Нажатие быстрого размера — явная замена рисунка с возможностью отмены до применения; изменение размера не сохраняет несовместимый старый массив. BPM-число остаётся прежним, но смена его единицы видна **до** применения. Пользователь вправе выбрать другую единицу. При отдельной смене единицы число не пересчитывается молча. В «Свой» недостающие группы/позиции формируются как единая новая конфигурация, не частично во время звука.

Начальный акцент: позиция 1 STRONG; начала остальных групп MEDIUM; остальные WEAK. Это только шаблон, не обязательная музыкальная интерпретация: можно сделать слабую первую, сильные 2/4, несколько сильных либо все тихие. Изменение групп автоматически предлагает шаблон в draft; пользовательские изменения не перезаписываются без явного применения/сброса.

Формулы для реализации и тестов: P — длительность единицы BPM в четвертях (QUARTER=1, EIGHTH=0.5, DOTTED_QUARTER=1.5); интервал позиции `60/BPM × (4/D)/P`; длина такта `N × интервал позиции`; интервал sub-tick — интервал позиции / subdivision. Первый sub-tick совпадает с основной позицией и не создаёт второго click.

Примеры: 4/4, четверть=60 → 4 с/такт; 3/4 →3 с; 6/8, четверть с точкой=60 →2 с, позиции каждые 1/3 с, группы начинаются на 0 и 1 с. 6/8, восьмая=60 →6 с; 7/8, восьмая=140 →3 с при любом порядке групп. Это ожидаемая музыкальная семантика, не результат измерения тайминга браузера.

## Акценты и громкость

У позиции `accent=STRONG|MEDIUM|WEAK|MUTE` и независимый `volumePercent=0…100` (default100). Глобальный `masterVolumePercent` default50; уровни типов акцента default STRONG100/MEDIUM65/WEAK35; их можно менять отдельно 0…100. MUTE всегда0. Диапазоны/default — наше предложение; это линейные доли внутреннего gain, не дБ и не обещание воспринимаемой громкости/звукового давления.

Громкость основной позиции пропорциональна `master × accentLevel × positionVolume`, все множители нормализованы 0…1. У подразделений свой общий уровень default25%; их gain=`master × subdivisionLevel × positionVolume`. MUTE/volume0 позиции заглушает **всю** её ячейку с подразделениями, сохраняя время и визуальный счёт. Слабая доля с volume100 не обязана звучать громче сильной с volume20: UI показывает оба параметра, пользователь управляет ими намеренно.

Типы акцента различаются также высотой/тембром встроенного короткого щелчка. Сохраняется единственный audio graph с ограниченной амплитудой; максимальные значения не дают clipping/суммирования одинаковых тиков. Огибающая короче минимального sub-интервала (либо эквивалентное ограничение суммарного выхода), без «хвостов» предыдущей конфигурации. Конкретные тембры/огибающие выбираются разработчиком с проверкой слышимости. Системную громкость ОС приложение не меняет. Все доли выключены — допустим визуальный метроном с явной подписью «Без звука», не сообщение о поломке.

## Единое состояние и изменение на ходу

Разделить `draftConfig`, последнюю полностью валидную `requestedConfig`, `activeConfig` и runtime. Звук планируется Web Audio clock, UI отражает уже прозвучавшую позицию/sub-tick. Массивы возвращаются независимыми snapshots. Не использовать DOM-таймер как источник звукового ритма. Сохраняются singleton, поколения отмены, очистка audio nodes и отсутствие автоматического resume из #86.

Остановлен: валидная настройка применяется сразу, без звука; составные правки подтверждаются «Применить», отмена возвращает последнюю принятую конфигурацию. В running **отдельное изменение BPM** через ручной ввод/±1/Tap применяется немедленно с отменой старой очереди и началом счёта с1, как в принятой #87; не подменять этот контракт ожиданием конца такта. Размер/единица темпа/группы/акценты/уровни позиций и акцентов/подразделения и загрузка полного пресета применяются атомарно **с начала следующего такта**. Пресет со своим BPM — одна составная конфигурация и тоже ждёт границы. Интерфейс различает active и pending; последний валидный составной запрос заменяет предыдущий. Если при существующем pending отдельно изменён BPM, новое значение применяется и к active, и к pending: устаревший темп не возвращается при следующем такте. В starting последний валидный запрос применяется к первой позиции после resume, не создавая дополнительный context/start. Невалидный draft не меняет playing/pending и не может запуститься. Старый планировщик не должен заранее проиграть click старого рисунка за границей переключения.

Общая громкость, общее заглушение (master=0) и Stop действуют сразу, включая уже запланированные события; master меняется плавно, без click от скачка gain. Stop отменяет очередь звука/визуализации; валидный pending становится настройкой следующего **ручного** Start, но не запускается сам. Ошибка resume, явное закрытие/Stop, document.hidden/pagehide, route change, реальная смена/удаление выбранного материала либо запуск тюнера отменяют running/starting и pendingStart. На возврате после этих событий тихо. **Minimize и начало/конец записи не останавливают метроном.** Повторное открытие окна не является сменой материала; unmount самого диалога при minimize не должен dispose/stop общего engine, стирать pending, сбрасывать beat или менять громкость/рисунок. Нет фонового воспроизведения при сворачивании — сохраняем политику #86/#87, даже если мобильные конкуренты умеют иное.

Из карточки упражнения: при running/starting только показать тот же диалог — **не вызывать stop/setBpm/applyConfig и не заменять active/pending**. Сохраняются ритм, фаза, единица темпа, BPM, акценты и громкость. Только при stopped/ready/unavailable допустимо подставить рекомендованный bpm как QUARTER, пока каталог не предоставляет иной явной единицы (схема каталога здесь не меняется); при невалидном bpm предыдущая валидная конфигурация остаётся. Размер без доступных в каталоге данных остаётся пользовательским, с подписью «Пользовательский размер — проверьте по нотам». Карточка не перезаписывает каталог или именованный пресет. Header только открывает управление; оба входа используют один engine.

**Запись под метроном:** поддерживаются оба порядка: Start → minimize → начать запись и запись → открыть метроном → Start → minimize. Начало/завершение записи не вызывает stopMetronomeForAudioCapture; этот метод остаётся для тюнера как эксклюзивного инструмента. MediaRecorder получает только MediaStream микрофона: click не подмешивается программно. Щелчки колонок могут акустически попасть в запись, поэтому сохраняется подсказка про наушники; обещания автоматического удаления щелчков нет.

Диаграммы: [компоненты](../diagrams/tool02-metronome-components.mmd), [смена конфигурации](../diagrams/tool02-metronome-sequence.mmd). Это проект, новые имена/методы уточняются при системном анализе итогового #87; существующего REST нет и новый не нужен.

## Tap Tempo и локальная память

Tap измеряет **выбранную единицу BPM**. По минимум четырём нажатиям используется медиана последних не более восьми межтаповых интервалов, округление до целого BPM. Интервалы меряются monotonic clock; после паузы более4 с серия начинается заново. Полученный результат за пределами20…240 не применяется и не clamp-ится молча. Tap не запускает звук; во время работы применяет отдельный валидный BPM немедленно по сохранённой политике #87. Первые1–3 нажатия показывают сбор темпа.

Предлагаемый ключ `guitar-mentor.metronome.v1` в localStorage текущего origin; JSON schemaVersion=1, currentConfig, presets. Не хранить running, AudioContext, таймеры, sourceExercise или ссылки на DOM. Чтение/запись/JSON/access to storage обёрнуты в обработку ошибок. Повреждённые/неподдерживаемые данные дают безопасный default4/4/80/STOPPED; исходное значение не удаляется/перезаписывается автоматически при ошибке чтения. Превышение квоты не выключает метроном: работа в памяти, сообщение «Настройки не удалось сохранить».

| Сущность/поле | Тип и проверка |
| --- | --- |
| Config | bpm, numerator, denominator, tempoUnit, groups, subdivision, masterVolumePercent, accentVolumes{strong,medium,weak}, subdivisionVolumePercent, positions[{accent,volumePercent}]; все обязательны, finite integer/range/enum по разделам выше; positions.length=N |
| preset | id локальный UUID; name строка trim1…60; config валиден; не более20 пользовательских пресетов; имена могут совпадать, идентичность по id |
| storage | schemaVersion=1; currentConfig валиден; presets массив0…20; максимальный размер64 KiB (UTF-8); до JSON.parse проверяется размер входа, oversized значение не разбирается; невалидные/oversized данные не удаляются, запись сверх лимита отклоняется без удаления прежней |

Пресеты: сохранить под именем, загрузить, переименовать, заменить после явного выбора, удалить с подтверждением. Заводские шаблоны размеров не удаляются. Редактирование загруженного пресета не меняет сохранённый вариант без «Сохранить». Локальная память привязана к браузеру/origin; не обещать облачную синхронизацию/перенос между устройствами. Запрет/отказ storage не блокирует остальные функции. При восстановлении после F5 всегда STOPPED, в том числе если сохранение произошло во время running.

## НФТ, безопасность, проверка и откат

Применимы NFR-001 (минимальная инфраструктура — новых сервисов нет), NFR-002 в локальной части (повторные Start/Stop и смена конфигурации не создают дубли), NFR-004 (понятные состояния/UX), NFR-007 (безопасные ошибки), NFR-008 (версии/трассировка), SEC-001/005/008 по применимости. NFR-003/005 не получают нового объёма: история обучения, TTL и схема PostgreSQL не меняются. RU/EN и отсутствие ложного анализа наследуются из существующего объёма #87 и границ этой спецификации, им не назначаются чужие ID НФТ. Новых персональных данных, credentials, сетевых прав или аудиофайлов нет. Имена пресетов/JSON — недоверенный ввод: allow-list, bounded parse, текстовый вывод. Никаких eval/HTML или произвольного звука по URL. Ошибка аудио доступна как локализованный код, без device ID/стека/содержимого storage в логах. Запись совместима с метрономом по принятому правилу #87; взаимоисключение сохраняется только для тюнера. Пользовательская настройка не отменяет остановку по document.hidden/route/явному закрытию.

Проверочный протокол зафиксирован для реализации. В fake AudioContext проверить минимум100 тактов для4/4,3/4,6/8,7/8 и граничного16/16 с subdivision4; времена планирования соответствуют формуле с абсолютной вычислительной погрешностью≤1e-6 с, без двойного события на общей границе, catch-up burst и накопленной арифметической ошибки. Этот допуск относится только к расчёту в тесте, не к слышимому jitter/latency браузера. В foreground выполнить реальные прогоны по5 минут4/4 и6/8, включая запись, minimize/reopen, изменение BPM и размера: зафиксировать браузер/ОС/устройство/AudioContext sampleRate, слышимые пропуски/дубли и события остановки; результат сравнить с неизменной принятой #87 на той же среде. Порог микросекундной точности слухом не заявлять. Матрица: Windows10 Chrome и Edge, Android Chrome, iPhone Safari; реальные версии/устройства записать в QA. При отсутствии платформы/микрофона кейс BLOCKED и передаётся на доступную ручную проверку; это не скрытый блокер написания кода. До приёмки #104 нужны unit-проверки расчёта периодов/групп/gain и fake AudioContext планирования, mounted UI включая ручной input/новые select/range, storage failures, lifecycle/races и ручное прослушивание составных размеров. Старые тесты #86/#87/recorder/tuner сохранить.

Установка: frontend после принятия #87, npm ci/build и прежние CI плюс новые проверки этой задачи; backend/Flyway/env/секреты не меняются. Настройки доступны ученику без рестарта, изменяются через UI; default задаётся frontend. Отдельный feature flag не требуется для локального выпуска.

Smoke: без сохранённых настроек открыть header→4/4/80, Start/Stop; 6/8/четверть с точкой60→шесть позиций/два групповых акцента; 7/8→2+2+3→3+2+2; заглушить позицию, изменить master/volume; сохранить пресет, F5→тихо и настройки сохранены; открыть из stopped упражнения→рекомендованный quarter-BPM; running90→minimize→открыть через упражнение84→осталось90 и та же фаза; backdrop→ничего; minimize→запись→звук продолжается; конец записи→продолжается; тюнер/×/Escape/реальный уход со страницы→остановка.

Откат при двойном звуке, ошибочном пульсе, потере управления или нарушении остановки: владелец установки останавливает воспроизведение и возвращает прежний frontend после #87, перезагружает страницу и проверяет4/4/Start/Stop, minimize/reopen и одновременную запись под метроном. Новый ключ не читается старым frontend; удалять его или другие ключи не требуется. Backend/данные обучения не откатываются. Пресеты новой версии не обещаются доступными в старом UI; восстановления удалённого пресета без сохранённой копии нет.

## Критерии приёмки — ожидаемые результаты, не PASS

- **AC-MET-01 / FT-003-05:** Дано: остановленный метроном. Когда: выбран3/4 либо допустимый свой16/16. Тогда: число позиций равно N, цикл возвращается к1 после N; нулевой N, D=3, дробные/NaN/бесконечные значения отклонены без порчи последней валидной настройки.
- **AC-MET-02:** Дано:6/8 и четверть с точкой60. Когда: выполняется цикл. Тогда: шаг1/3 с, такт2 с, начала групп1/4 через1 с; для восьмой60 такт6 с. Единица BPM видна в UI и доступном имени.
- **AC-MET-03:** Дано:7/8, восьмая140. Когда: выбраны2+2+3 затем3+2+2. Тогда: шаблон вторичных акцентов меняется, такт остаётся3 с; сумма групп≠7 не применяется; пользовательские акценты меняются только явным действием.
- **AC-MET-04:** Дано:4/4. Когда: позиция1 сделана слабой,2 сильной,3 MUTE,4 средней. Тогда: слышен именно этот рисунок, позиция3 занимает своё время и отображается, первая не получает скрытого принудительного акцента. Все MUTE дают визуальный счёт с подписью «Без звука».
- **AC-MET-05:** Дано: разные уровни акцентов и volume отдельной позиции. Когда: изменены master/positionVolume/акцент. Тогда: применена указанная формула,0 даёт тишину,100 не усиливает выше ограниченного выхода; настройка одной позиции не меняет соседние/системную громкость.
- **AC-MET-06:** Дано: subdivision1/2/3/4. Когда: включено деление. Тогда: верное число равных sub-интервалов, нет двойного click в начале позиции; MUTE заглушает и её подразделения, такт не ускорен, максимум нагрузки не даёт clipping/очереди старых щелчков.
- **AC-MET-07:** Дано: выбранная единица BPM и не менее4 taps с интервалом0.5 с. Тогда: предлагается120 этой единицы, звук сам не начинается; новая серия после>4 с не наследует старые интервалы; недопустимый результат показан без молчаливой обрезки.
- **AC-MET-08:** Дано: настройки и именованный пресет. Когда: сохранение/F5/загрузка/переименование/замена/удаление. Тогда: восстановлены значения, но STOPPED; несохранённое редактирование не портит пресет. Повреждённый JSON, неизвестная schema, quota/access exception не ломают приложение и не удаляют чужие ключи.
- **AC-MET-09:** Дано: running/starting. Когда: меняется отдельно BPM либо составной config. Тогда: отдельный BPM немедленно принят с reset на1; составной config/пресет применён на границе такта без старых/двойных тиков. Изменение BPM обновляет и pending, исключая возврат старого темпа. В starting применяется последняя валидная конфигурация к первой позиции, второй context не создаётся. Stop/общее заглушение (master=0)/master действуют сразу; поздний resume не возобновляет остановленное.
- **AC-MET-10:** Дано: входы header/карточка. Когда: running90 либо starting и кнопка материала84. Тогда: только открыто управление, stop/setBpm/applyConfig не вызваны,90/единица/рисунок/фаза/pending сохранены. Только stopped получает рекомендованный quarter-BPM; каталог/пресет не изменены, неизвестный размер явно пользовательский.

Тогда: звук и очередь остановлены, поздний resume/возврат не запускает их. Начало/конец записи и minimize исключены из stop-событий; открытие окна из карточки не считается сменой материала.
- **AC-MET-12:** Дано: RU/EN, ширина360, touch/клавиатура/screen reader. Тогда: все настройки достижимы без hover/long press, focus trap включает select/range, подписи различают accent/mute/current beat, форма страницы сохраняется, нет быстрой очереди aria-объявлений.

- **AC-MET-14:** Дано: включённый метроном и доступный микрофон. Когда: Start→minimize→record либо record→Start→minimize, затем конец записи.
