## Паспорт и ценность

Issue [#19](https://github.com/roafo1989/guitar-mentor-ai/issues/19), US-003/#57, EPIC-001/#53; FT-003-02, BT-005/006/007/008/012 БТ 0.4, ТЗ 0.9; NFR-002/003/004, SEC-001/005/008. Основной backend-контракт — [MVP-R4-01 v1.0](MVP-R4-01-learning-state-and-decisions.md); его имена endpoint — проект для реализации, не текущий API. Данные/последовательность наследуются из схем #18, отдельная архитектура сервиса не вводится.

Как ученик, я хочу видеть, что получилось, что ещё требует работы и какой следующий шаг я выбираю. Решение продолжить не должно скрывать замечания и выдавать навык за подтверждённый.

## Экран и источники данных

На текущем экране задания: его идентификатор/версия и материалы → запись/отправка → история попыток → выбранный результат → решение. PDF свёрнут по умолчанию, детали истории по запросу. Данные запроса всегда соответствуют текущим learner/session/task/attempt; смена контекста отменяет/игнорирует устаревший ответ. После F5 восстанавливаются существующие выбранные learner/session/task и серверное состояние; наличие локальной медиа-черновой записи не обещает восстановление её Blob после перезапуска браузера.

| Состояние | Представление и доступные действия |
| --- | --- |
| Загрузка | Понятный progress; команды недоступны до чтения server version |
| Нет попыток | Существующий recorder/upload и инструкция; нет выдуманного результата, COMPLETE без попытки не предлагать |
| UPLOADED/PROCESSING | Техническое состояние конкретной попытки; не «ИИ проверил» |
| FAILED | Локализованная техническая причина, повтор загрузки по существующему механизму; не отрицательная музыкальная оценка |
| PROCESSED, NO_ASSESSMENT | «Файл технически проверен. Музыкальная оценка пока недоступна»; можно продолжить практику или самостоятельно завершить работу |
| ASSESSED | Критерии MEETS/NEEDS_WORK, основание и method/source; рекомендация отдельно от решения ученика |
| UNCERTAIN/NOT_ASSESSED | Причина/ограничение, не нулевой балл; нет зелёного «всё освоено» |
| COMPLETED_PASSED | Серверный факт завершения с принятыми критериями, доступна история |
| COMPLETED_BY_LEARNER | «Завершено по вашему решению», старые замечания и неоценённые критерии остаются |
| LEARNING_DISABLED/временно недоступен API | Старые материалы/попытки доступны; новые действия отключены с понятной причиной, не ложный результат |

Не смешивать processingFinishedAt с моментом музыкальной оценки. `assessmentAvailable` — признак доступности, а не PASS. При удалённом исходнике показывать статус удаления; текстовые результаты/решения остаются, кнопка прослушивания недоступна. Source/версия нужны в деталях результата; технические пути/stacktrace пользователю не показывать.

## Действия, API и устойчивость

Чтение `T/learning`, `T/attempts/{attemptId}/assessments`, `T/decisions` через отдельный `*.service.ts` и типизированные модели; T определён в #18. Все тексты RU/EN, включая reasonCode и fallback неизвестного кода. Недоверенный текст оценки/причины выводить обычной интерполяцией, без v-html/исполнения команд.

- «Продолжить отрабатывать» → action CONTINUE_PRACTICING; существующая запись создаёт новую попытку только по отдельной отправке ученика.
- Завершение при серверном PASS → action COMPLETE; клиент не устанавливает итоговый статус самостоятельно.
- Завершение вопреки REVISE/без оценки → та же COMPLETE с ясным пояснением сохранения замечаний; можно добавить необязательный комментарий причины. Не заставлять бесконечно пересдавать.
- До подтверждения учеником ни переход между страницами, ни просмотр PDF/оценки не отправляют decision. На время POST блокировать повторное нажатие; requestId сохраняется для retry неизменённого тела после сетевого сбоя. При изменении выбора/причины — новая команда/requestId, старый неопределённый результат сначала уточнить чтением серверного состояния.
- POST передаёт выбранную attemptId, expectedVersion и baseAssessmentId/null. При 409 VERSION_CONFLICT/ASSESSMENT_CHANGED перечитать результат и показать, что данные обновились; не повторять завершение автоматически на новом основании.
- При смене ученика, маршрута, выбора попытки или unmount игнорировать запоздалый ответ. Ответ на команду старого задания не закрывает новый экран/другого ученика.
- Ошибка POST сохраняет причину и выбранную попытку; успешный commit отражается после перечитывания. История результатов не подменяется только локальным optimistic state.
- Защиту несохранённой попытки распространить на действия нового учебного сценария: не потерять черновик при переключении экрана/завершении, во время записи/отправки управляемо остановить действие. Не копировать второй рекордер и не обходить существующий аудиолизинг #98/#87.

История листается cursor-пагинацией #18; новая revision не удаляет просмотренную старую. Решение содержит ссылку на ту оценку, которую видел ученик. Навыки показывают самооценку, результат отдельного критерия и подтверждённый уровень раздельно; null/UNKNOWN не превращается в «0 из 10» или «не умеет».

## Следующее занятие и граница полной приёмки

Сохранение COMPLETE и подтверждение завершения задания — #18/#19. Реальный персональный план/выдача следующего занятия — #24; музыкальная оценка — #22/#23 после исследовательских gates. В текущем backend `DiagnosticSession.start()` возвращает активную сессию с единственным assigned task: **нельзя изображать следующее занятие повторным POST start, который вернёт то же задание**. Пока nextStepAvailability=NOT_IMPLEMENTED, показывать сохранённый итог и честное пояснение о недоступности следующего плана, без неработающей кнопки.

Для разработки UI допустимы маркированные test fixtures. Они не заменяют реальную оценку, сквозной выпуск или приёмку всей #19/US-003. Исходное требование полноценного следующего шага сохраняется: его E2E-критерий зависит от #24. Это явный интеграционный остаток, а не молчаливое исключение из объёма.

## Сценарные AC

- **AC19-01:** Дано: существующая сессия/назначение. Когда: F5. Тогда: прежние материалы/попытки и текущее taskState восстановлены без нового назначения.
- **AC19-02:** Дано: нет оценки или PROCESSED. Тогда: показана техническая готовность и NO_ASSESSMENT, не музыкальный PASS.
- **AC19-03:** Дано: ASSESSED/UNCERTAIN/NOT_ASSESSED. Тогда: критерии, причины и источник различимы, неопределённость не заменена нулём.
- **AC19-04:** Дано: REVISE. Когда: ученик подтверждает COMPLETE. Тогда: серверное COMPLETED_BY_LEARNER отображено отдельно, замечания и прежняя оценка остаются.
- **AC19-05:** Дано: CONTINUE_PRACTICING. Тогда: можно сделать новую попытку, предыдущая история не скрыта/не перезаписана.
- **AC19-06:** Дано: timeout POST или двойное нажатие. Тогда: retry неизменённой команды не создаёт дубль, ложного «завершено» до ответа нет.
- **AC19-07:** Дано: новая assessment/version между чтением и POST. Тогда: 409 объяснён, результат перечитан, команда не отправлена повторно автоматически.
- **AC19-08:** Дано: несохранённый черновик/активная запись или запоздалый ответ старого ученика. Тогда: ввод не теряется без согласия, старый ответ не меняет новый контекст.
- **AC19-09:** Дано: DELETED media или LEARNING_DISABLED/сеть недоступна. Тогда: понятный fallback, сохранившиеся результаты доступны по возможностям API, остальные разделы работают.
- **AC19-10:** Дано: RU/EN, клавиатура и узкий экран. Тогда: действия/ошибки доступны, смена языка не сбрасывает форму и не отправляет decision.
- **AC19-11:** Дано: реальные поставщики #22/#23 и план #24 готовы. Когда: пройден полный сценарий «попытка → оценка → решение → следующее занятие». Тогда: весь исходный E2E выполнен на реальной интеграции. До этого AC BLOCKED, не PASS от mocks.
