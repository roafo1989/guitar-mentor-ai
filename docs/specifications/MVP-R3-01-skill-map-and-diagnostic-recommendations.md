## 2. User Story и границы

Как ученик с разным начальным опытом, я хочу получать понятное по цели, стилю и сложности диагностическое упражнение, чтобы начать с подходящего материала и знать, какие навыки он помогает проверить.

**Входит #16:** расширение уже существующего справочника навыков (описание, порядок, граф зависимостей, 4 состояния педагогической шкалы); метаданные целей/критериев версионированного Exercise; детерминированное объяснимое предложение доступного упражнения; адаптер к текущим профилю/анкете/предпочтениям; фиксация истории **заявленных** сигналов отдельно от будущих подтверждённых; точечная интеграция рекомендаций в существующий диагностический экран; миграция, автоматические проверки, документация.

**Не входит:** создание и музыкальное ревью пяти этюдов, PDF/MP3/метроном (#17); полноценная диагностика и загрузка собственных записей (#29/#68); полная история Assessment/StudentDecision/SkillEvidence и проверка исполнения (#18/#22/#23); следующая программа после урока и история рекомендаций по урокам (#24); новая генерация музыки, вызовы LLM, самостоятельное изменение результата диагностики; интернет-авторизация (#38/#42).

**Польза без фиктивных метрик:** проверить на тестовых профилях предсказуемость выдачи, соблюдение EXCLUDE, пригодность новичку, причины выбора и отсутствие ложных подтверждений. Уровень из анкеты — только заявленный контекст, не факт исполнения.

## 4. Карта навыков и смысл уровней

Переиспользовать коды V5 без переименования:

| SkillCode | Наблюдаемый смысл | Необходимые предшествующие навыки |
| --- | --- | --- |
| PULSE | устойчивость долей | — |
| SUBDIVISION | восьмые, паузы, дробление | PULSE |
| RH_HAND | извлечение звука пальцами правой руки | — |
| BASS_PULSE | стабильный бас большим пальцем | PULSE, RH_HAND |
| MELODY | разборчивая верхняя мелодия | RH_HAND |
| VOICE_INDEPENDENCE | самостоятельность баса и мелодии | BASS_PULSE, MELODY, SUBDIVISION |
| LEFT_HAND | чистота прижатия и переходов | — |
| DYNAMICS | акценты, баланс голосов, фразировка | MELODY |
| TAB_READING | понимание табулатуры/длительностей | — |

Шкала: **UNKNOWN (0)** — данных недостаточно, **INTRODUCED (1)** — знаком с принципом, **DEVELOPING (2)** — работает в простом контексте с нестабильностью, **CONSISTENT (3)** — устойчивое выполнение в проверенных контекстах. Шкала не является расчётом вероятности. **UNKNOWN не равно FAIL и не равно уровню новичка.** Статусы источника отдельно: `SELF_REPORTED` (только слова ученика), `OBSERVED` (ручная проверка при наличии протокола), `MEASURED` (только валидированный метод), `NOT_ASSESSED`. Пустая анкета не создаёт отрицательных оценок.

Предпосылки — направленный ациклический граф. Запрещены циклы, ссылки на отсутствующий код и зависимость самого от себя. Они формируют объяснение и планируемую сложность, **не становятся автоматическим отказом** по неизвестному навыку; при заведомо несовместимой сложности материал исключается по отдельному правилу пригодности.

## 5. Предлагаемая схема данных (следующая свободная Flyway-миграция)

1. **`skill_codes`** — оставить PK `code`, добавить `description TEXT NOT NULL`, `display_order INT NOT NULL`, `category VARCHAR(30) NOT NULL`, `active BOOLEAN NOT NULL DEFAULT TRUE`. Backfill по девяти кодам. Не менять их идентичность.
2. **`skill_prerequisites`** — `skill_code VARCHAR(50) FK skill_codes`, `prerequisite_code VARCHAR(50) FK skill_codes`, PK обе колонки, CHECK не равны. Seed строго по таблице выше. Проверка отсутствия циклов в доменном тесте/при старте; если предусмотрен импорт через SQL, защитить и его валидатором или администрировать только миграциями.
3. **`exercise_skills`** — сохранить PK (`exercise_id`, `skill_code`) и существующие связи. Добавить `target_level SMALLINT NULL CHECK 1..3`, `target_role VARCHAR(10) NOT NULL DEFAULT 'SUPPORT'` с CHECK `PRIMARY/SUPPORT`. Для GM-EB01 `PULSE, BASS_PULSE, MELODY` → PRIMARY; остальные → SUPPORT. `target_level` остаётся NULL, пока педагогический уровень не задан; NULL не конвертировать в CONSISTENT.
4. **`exercise_criteria`** — PK (`exercise_id`, `criterion_code`), `skill_code FK skill_codes`, `label`, `observable_result`, `assessment_policy` (`MANUAL_OR_NOT_ASSESSED` по умолчанию), `display_order`. FK `exercise_id` на версионированную запись `exercises.id`, не на изменяемый код. Критерии для текущего GM-EB01: `PULSE_STEADY`, `BASS_STEADY`, `MELODY_CLEAR`; каждый привязан к своему skillCode; ни один не получает автоматическую оценку. Текстовые пороги ритмической точности не сочинять до PoC.
5. **`exercises`** — добавить `recommended_practice_minutes INT` (10..120), для существующего GM-EB01 предложение 30 минут в рамках диапазона R3-брифа 20–40 (педагогическая оценка, не измеренный факт). Для новых текущих упражнений #17 заполняет обязательное значение до публикации. При вводе требуется явное значение, не делить 12 тактов на BPM как «длительность занятия».
6. **`learner_skill_signal_history`** — append-only: `id UUID PK`, `instrument_profile_id UUID FK`, `skill_code FK`, `source_type` (`SELF_REPORTED/OBSERVED/MEASURED`), `level SMALLINT NULL CHECK 1..3`, `source_reference VARCHAR(160) NOT NULL`, `recorded_at TIMESTAMPTZ`, `confidence NUMERIC(4,3) NULL CHECK 0..1`, `note_code VARCHAR(60) NULL`. Индекс (`instrument_profile_id, skill_code, recorded_at DESC`). Для `SELF_REPORTED` подтверждённый уровень не создаётся; `level=NULL` означает только заявление о знакомстве. Запись OBSERVED/MEASURED через публичный endpoint **не предоставлять**. Их будущая запись — интеграция с #18/#22 по подтверждённому evidence, без дублирования общей Assessment. Текущие `background_skills` остаются источником онбординга; новые события `SELF_REPORTED` отражают **только однозначно обозначенные утверждения** (напр. FINGERSTYLE_MELODY → MELODY/NULL, как знакомство), но не выводят уровень из стажа, CHORDS или STRUMMING. При каждом изменении таких утверждений писать новое событие с происхождением, а не заменять старое. Обозначить `BACKFILL_FROM_BACKGROUND` при единоразовом переносе: дата переноса не равна дате фактического освоения.
7. **Агрегация:** view/application read model `SkillSnapshot`: `selfReported` (наличие отдельного claim), `assessedLevel` (UNKNOWN либо последнее *валидное* наблюдение), `evidenceStatus`, `unresolvedGaps` (при отсутствии проверок пустой список, не «нет пробелов»). Правила выбора источника и фиксирования конфликта включить в unit-тесты. Не переносить VERIFIED в `learning_backgrounds`.

**Миграционный принцип:** не редактировать V1–V9; номер выбрать после учёта миграций других PR, особенно #21. Migration/backfill транзакционны на PostgreSQL. Flyway `validate` на уже заполненной БД, существующие задания и версии `GM-EB01` остаются доступны; исторические `diagnostic_tasks.exercise_id` не перенаправлять на новую версию.

## 6. Алгоритм v1: фильтрация и объяснимое ранжирование

**Серверный источник данных:** из владения `learnerId → InstrumentProfile → DiagnosticSession`, предпочтения `MusicPreference`, `LearningBackground`, текущие/допущенные упражнения, `SkillSnapshot`. Query не принимает произвольный `learnerId` другого пользователя как полномочие. Внешний LLM не используется.

**Жёсткий фильтр (в таком порядке):**
1. `is_current=true`; совпадают instrument/technique; материал разрешён для локального прототипа своим реальным `review_status`, правами, версией и наличием учебного ресурса. Принято для прототипа ≠ разрешено к внешней публикации.
2. Style `EXCLUDE` — **никогда не рекомендовать автоматически**. Отсутствующее предпочтение трактуется как NEUTRAL, но это не LIKE.
3. Требуемое время занятий `recommended_practice_minutes <= practice_minutes`; если отсутствует анкета — безопасный диагностический beginner-fallback без приписывания стажа/целей. Если нет достоверного времени занятия у упражнения — не назначать автоматически.
4. Если `experience_level=NONE/BEGINNER` или анкета отсутствует, из автоматического списка исключать `INTERMEDIATE/ADVANCED`; неизвестные навыки сами по себе не приравнивать к ошибкам. Для иных уровней сложности ранжировать разумно, а не выдавать автоподтверждение.
5. Данные о незакрытых пробелах из подтверждённой модели #18 в будущем влияют на приоритет, но отсутствие таких данных в #16 — нормальная ветвь `NOT_ASSESSED`.

**После фильтра:** отсортировать *детерминированно* по (а) совпадению с сохранёнными целями, (б) первичным навыкам, требующим диагностики и ещё не подтверждённым, (в) LIKE выше NEUTRAL, (г) меньшему времени выполнения в лимите ученика, (д) `code` лексикографически и `version` стабильно. Для целей использовать явную таблицу соответствия, а не LLM: `RHYTHM→PULSE/SUBDIVISION`, `INDEPENDENT_BASS→BASS_PULSE/VOICE_INDEPENDENCE`, `FINGERSTYLE→RH_HAND/MELODY`, `COMPOSITIONS→MELODY/DYNAMICS`, `THEORY→TAB_READING`. `DIFFERENT_STYLES` не отменяет EXCLUDE. У всех с равным score порядок одинаков между запросами; изменение версии правил фиксируется `algorithmVersion`. В ответе отдавать коды причин (`GOAL_MATCH`, `UNKNOWN_SKILL_DIAGNOSTIC`, `PREFERRED_STYLE`, `TIME_FIT`, `PREREQUISITE_TO_PRACTICE`) и конкретные `skillCodes`, не выдумывать персональные диагнозы.

**Нет кандидата:** HTTP 200 `NO_MATCH` с `reasonCode` типа `NO_COMPATIBLE_EXERCISE`, `NO_BEGINNER_EXERCISE`, `ALL_STYLES_EXCLUDED`, `NO_TIME_FIT`. Не смягчать EXCLUDE/уровень/лицензию. Пользователь может изменить предпочтения/время или дождаться наполнения каталога в #17. Ошибка базы или нарушенные данные — не NO_MATCH, а техническая ошибка с диагностическим кодом.

**Ручной выбор:** текущий POST назначения по exerciseCode сохраняется для совместимости. GET рекомендаций **ничего не назначает**. Ученик может сознательно выбрать иной материал из каталога, включая исключённый стиль, только своим явным действием; это не автоматический выбор. Запрещено менять назначение после TASK_ASSIGNED в обход существующей проверки.

## 7. REST и UI (проектируемый контракт)

### GET `/api/v1/learners/{learnerId}/diagnostic-sessions/{sessionId}/exercise-recommendations`

- Только авторизованный в контексте локального стенда InstrumentProfile, которому принадлежит Session. Путь: два обязательных UUID; параметр `limit` целое 1–3, default 3; без body. Сервер не получает пользовательский `skillLevel` и `isVerified`.
- Предусловие: `READY_FOR_TASK`. Для `COLLECTING_EVIDENCE` и `TASK_ASSIGNED`: HTTP 409 с `code=DIAGNOSTIC_NOT_READY` / `TASK_ALREADY_ASSIGNED`; отсутствующая/чужая сессия 404 (без раскрытия существования).
- **200 пример** (UUID условные, `skillCodes` относятся к текущей версии задания):

```json
{
  "sessionId": "11111111-1111-4111-8111-111111111111",
  "algorithmVersion": "initial-diagnostic-v1",
  "status": "RECOMMENDED",
  "reasonCode": null,
  "items": [
    {
      "exerciseCode": "GM-EB01",
      "exerciseVersion": "0.8B",
      "recommendedPracticeMinutes": 30,
      "skillCodes": ["PULSE", "BASS_PULSE", "MELODY"],
      "reasonCodes": ["GOAL_MATCH", "UNKNOWN_SKILL_DIAGNOSTIC", "TIME_FIT"],
      "reasonText": "Подходит для проверки пульса, баса и мелодии в вашем режиме занятий."
    }
  ]
}
```

Пример `GM-EB01` допустим **только если** профиль пользователя и допуск каталога удовлетворяют фильтрам. Для новичка с текущим единственным INTERMEDIATE материалом ответом будет `{"status":"NO_MATCH","reasonCode":"NO_BEGINNER_EXERCISE","items":[]}` вместе с `sessionId` и `algorithmVersion`.

- GET без записи, без изменения Session/DiagnosticTask, воспроизводим при одинаковых исходных данных; при конкурентном POST возвращает корректный снимок либо 409, не создаёт дубль. Сервис читает консистентный набор в одной read-only транзакции.
- 400 `INVALID_LIMIT`/некорректный UUID, 404 `SESSION_NOT_FOUND`, 409 по состоянию, 500 `RECOMMENDATION_INTERNAL_ERROR` без внутренних деталей и stacktrace в ответе. Использовать имеющийся обработчик ошибок или добавить совместимый; не возвращать SQL/файловые пути.
- Контракт существующего POST `…/tasks` не ломать: DTO `AssignRequest(exerciseCode)` и коды возврата сохраняются. Рекомендуемый вариант по-прежнему **выбирает** ученик; автоматическое назначение без действия ученика — отдельное решение, не скрытый эффект GET.

### Vue

В уже существующем `DiagnosticView` после `READY_FOR_TASK` показать до 3 рекомендаций с названием, временем, основными навыками и объяснением, кнопку выбора существующим POST; ниже сохранить явный каталог для самостоятельного выбора. `EXCLUDE` не отображается как рекомендация. При NO_MATCH — понятная причина и действия «Изменить предпочтения» / «Изменить доступное время» / «Посмотреть каталог вручную» без фиктивной автовыдачи. Состояния загрузки, нет данных, серверная ошибка, переход в TASK_ASSIGNED, двойной клик/F5; повтор назначения не дублирует DiagnosticTask. Тексты вынести в i18n ru/en, клавиатурная навигация и доступные подписи. Полноценный интерфейс истории освоения и экраны следующего урока остаются #19/#24.

## 8. Поведение при отказах, безопасность, наблюдаемость

- Код подбора без внешних запросов, локален и детерминирован. Отсутствие анкеты/подтверждённых evidence — штатный неполный контекст, а не ошибка оценки; отсутствие подходящего каталога — штатный NO_MATCH. Повреждённые ссылки skill/exercise или цикл графа — ошибка данных; детальный сигнал для разработчика, безопасный отказ пользователю.
- Владение learner/session/profile проверяется на сервере как в `DiagnosticTaskService`. Локальный тестовый UUID — **не аутентификация**; интернет-публикация до #38/#42 запрещена. Сервисы не доверяют полям `verified`, `assessmentMode` или `score` из браузера.
- В логах по диагностике: `sessionId`, алгоритм, `status`, число кандидатов после фильтров и `reasonCode` без имени/нот/медиа/секретов; не логировать аудиоключи и содержимое анкет. Без создания новых исходных медиа и без изменения TTL.
- Чтение рекомендаций не влияет на worker аудио/очистку #21; повторно использовать существующую транзакционную модель и Flyway. Нет новых env/secret-переменных или фоновых задач; правила v1 — версионированные значения кода/справочника, а не динамический SQL пользователя.
