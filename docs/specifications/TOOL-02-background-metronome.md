## Объём, среда и ограничения

Обязательная целевая проверка: пользовательский Chrome/Windows10, локальный HTTPS/Caddy, другое обычное окно/вкладка, работающая ОС и разрешённый AudioContext. Звуковой фон должен продолжаться без ожидания UI-таймеров. Android/iOS/Safari/Firefox — отдельные результаты совместимости; сон устройства, закрытая/выгруженная вкладка и принудительная приостановка ОС не обещают звучание. Ограничения фиксировать, а не изображать «Играет».

Нет нового микрофона, разрешений, сервисов, wake lock, сетевых запросов, скрытого бесшумного аудио для обхода ограничений, фонового Service Worker или постоянного кэширования. Запись упражнения под метроном сохраняется. Общая модель скинов #113 независима от этой задачи: наружный интерфейс singleton движка сохраняется, интеграция проверяется после merge обоих PR.

## Почему не достаточно убрать stop

Сейчас begin проверяет hidden после await resume; onVisibilityChange вызывает stop. JS setInterval25ms планирует только100ms вперёд, визуальные setTimeout также выполняются в main thread. Удаление двух остановок не даёт гарантии при throttling. Сохранить обработку pagehide и уход со страницы.

Проверены первичные источники22.10: [Chrome timers](https://developer.chrome.com/blog/timer-throttling-in-chrome-88/), [AudioWorklet](https://developer.chrome.com/blog/audio-worklet), [W3C Web Audio](https://www.w3.org/TR/webaudio-1.0/). Вывод для проекта: рендерить клики по аудиочасам в AudioWorklet, отделив DOM. Состояние suspended прекращает обработку и там; требуется честный отказ. Это архитектурный выбор анализа, ещё не результат работающего прототипа.

## Ответственность и контракт

[Компоненты/последовательность](../diagrams/issue109-background-audio.mmd).

- Singleton MetronomeEngine сохраняет start/stop/getState/getConfig/getPendingConfig/setBpm/applyConfig/setMasterVolume/subscribe. Публичные config/storage схемы #104 не меняются.
- Встроенный processor поставляется с frontend как статический модуль того же origin. В Vite использовать поддерживаемый build URL; проверить dev и production через Caddy. Никаких произвольных URL/плагинов.
- Processor сам рендерит синусоидальные клики с текущей огибающей/частотами/громкостями #104. Шаг — позиция по positionSeconds/config/subdivision. Sample cursor и границы тактов принадлежат rendering thread. В hot path нет fetch, таймеров, DOM и выделения объектов на каждый sample.
- Главный поток отправляет команды; сообщения для UI не запускают звук. У UI может временно отставать индикатор, но после возврата он показывает актуальную позицию, без проигрывания старых визуальных тиков.

### Предлагаемый внутренний protocol v1

Каждая команда: v=1, sessionId (целое безопасное, новая сессия при Start), seq (монотонное внутри сессии), type и payload. Unknown/invalid payload → контролируемый отказ; processor повторно проверяет config, конечность чисел и диапазоны. seq не заменяет sessionId. Старые ACK/команды прежней сессии игнорируются.

| Команда | Эффект и подтверждение |
| --- | --- |
| INIT(config) | Создать остановленный processor с валидной config, ACK READY. Не запускать звук самим module load. |
| START | После явного жеста и running context — начать с первой доли, ACK STARTED с текущими audioFrame/activeRevision. |
| BPM(value) | Сохранить контракт #87/#104: валидный новый BPM действует сразу с первой доли. Старый pending сохраняется с обновлённым BPM; не применить его случайно на этой reset-доле. |
| MASTER(percent) | Немедленно изменить master с прежним сглаживанием, не умножать громкость повторно. |
| CONFIG(config,revision) | Последний валидный запрос побеждает; применить атомарно на следующей ещё не прозвучавшей границе такта. ACK QUEUED не означает APPLIED. |
| SNAPSHOT | Актуальный status/beat/active/pending/revisions/frame; запрос после visible, без нового START. |
| STOP | Закончить генерацию/хвост, очистить pending в соответствии с нынешним stop; ACK STOPPED. Host дополнительно разрывает node и закрывает context, не ждёт ACK для прекращения звука. |

Ответы содержат sessionId/seq, activeRevision, audioFrame и тип READY/STARTED/QUEUED/APPLIED/SNAPSHOT/STOPPED/ERROR. Порядок по MessagePort сохраняется, ревизии нужны для отсеивания опоздавшего UI и сопоставления запроса. Несколько CONFIG до границы заменяют pending, а не накапливаются в очередь тактов. CONFIG + BPM + MASTER покрыть отдельными тестами. Объём сообщений ограничен валидной config; один ожидающий composite запрос. BEAT/summary не чаще одного на позицию, скрытый UI отбрасывает устаревшее; никаких накопленных списков тиков.

При ручном Stop во время addModule/resume использовать generation/session guard, немедленное отключение host graph и close context. Позднее завершение не стартует звук и не возвращает running. Новый Start ждёт завершения прежнего close; максимум один context/processor. processorerror, невозможность module load/resume, suspended/interrupted/closed вне явного Stop → unavailable с RU/EN сообщением и явным повторным Start. Автоматический retry/resume при visible запрещён. Для скрытия во время разрешённого пользовательского Start не вызывать stop, если running context действительно получен.

При отсутствии AudioWorklet/secure context — понятное unavailable; не выдавать старый таймерный движок за успешно поддержанный фон. Модуль загрузки/ACK: технический предохранитель5s, затем очистка/ошибка (проектный предел ожидания, не SLA доставки). Реальный старт Web Audio должен инициироваться в пользовательском обработчике, а не только после асинхронного module load; тест autoplay обязателен.

## Состояния и lifecycle

| Событие | Целевое поведение |
| --- | --- |
| hidden / visible | Продолжать running; не вызывать stop/start, не сбрасывать фазу; visible запрашивает актуальный snapshot |
| minimize/reopen | Звук и pending сохранены; новый UI не создаёт engine/context |
| Start записи | Запись не прерывается; метроном может продолжать играть |
| Открытие тюнера | Остановить метроном по принятому приоритету #98 до анализа микрофона |
| Stop, ×, Escape без открытой внутренней панели | Остановить, освободить audio graph/context |
| Закрытие внутренней панели Escape | Только панель, по #111; не уничтожать метроном |
| route/pagehide/F5/закрытие вкладки | Остановить, нет восстановления playing из localStorage |
| suspended/interrupted/processorerror | Остановить/очистить, unavailable; после возврата нужен Start |

Новых пользовательских настроек/ключей БД или localStorage нет. Включение нового engine — часть frontend-поставки. Реализовать тот же meter/config math один раз в совместимом модуле, с тестом parity в main и worklet; не копировать расходящиеся формулы. Ошибки логировать reasonCode/stage и session revision, без аудио, device id, личных путей. Не считать отсутствие heartbeat из скрытого main thread доказательством остановки звука.

| AC-BG-10 | Дано production build под HTTPS/Caddy. Когда прогнан smoke и реальные переключения. Тогда модуль грузится с того же origin; зафиксированы версия браузера/ОС, длительность, аудиодоказательство и ограничения, отдельно от mock/render tests. |

Кейсы: unit render/command state machine44.1/48kHz; ошибки/гонки host; mounted existing UI/regression; production module URL. В синтетическом render harness сравнивать frame positions с расчётом с точностью до1 sample — алгоритмический критерий, не обещание акустической задержки. Реальная запись loopback либо разрешённый внешний захват: интервалы/число кликов и слуховая проверка; приватную запись не публиковать. Браузерная анимация и mockтаймеры не доказывают реальное звучание в фоне. Задача не готова к приёмке без обязательной Chrome/Windows проверки; недоступное устройство — BLOCKED, не PASS.

## Установка, smoke и откат

Frontend build/test + тот же Caddy; миграций/секретов нет. Разработчик указывает точную ветку/commit, команды из актуального package.json и production asset. Smoke: Start84→другая вкладка→возврат→7/8 pending→Stop→новый Start→тюнер останавливает→F5 не звучит. Trigger отката: пропуски/залипший звук, нарушение pending или lifecycle. Владелец локальной установки возвращает предыдущий принятый frontend и проверяет Start/Stop/запись. Старое hidden→stop вернётся как известное ограничение; данные и физические записи не восстанавливаются/не удаляются откатом.
