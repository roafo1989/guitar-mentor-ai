## 1. Трассировка и ценность

БТ 0.4: BT-002, BT-003, BT-008, BT-009 → ТЗ 0.7: US-002 / FT-002-04 → Issue #68 (родитель #56, эпик #53). Сценарий UC-02 пп. 2–4, A1–A4, A8; AC-D02/03/04/07/08. Применимые NFR: NFR-001/002/003/005/007; SEC-001/004/005/007/008 в релевантных границах. ADR-0002, #20/#30/#21; не путать собственные записи с попытками заданий (#20) и с доказательствами проверенного навыка (#18/#22).

**Как ученик**, до первого диагностического задания я хочу показать одно или несколько знакомых исполнений и при наличии приложить ноты/табулатуру, чтобы наставник учитывал мой реальный материал, не заставляя новичка загружать записи.

Показатель результата: сессия в `COLLECTING_EVIDENCE` принимает 0…N собственных примеров с устойчивой связью с произведением и опциональной партитурой; по явному переходу существующий `POST /continue` переводит её в `READY_FOR_TASK`. Запись не обязана быть загружена, а загруженная запись сама по себе не подтверждает навыки.

## 2. Существующая основа, границы, зависимости

**Проверено по исходникам:** `DiagnosticSessionService` (COLLECTING_EVIDENCE → READY_FOR_TASK → TASK_ASSIGNED; повторный continue идемпотентен), `DiagnosticSessionController`, `DiagnosticView.vue`; `SubmissionAttempt` требует `diagnostic_task_id`, поэтому для pre-task материалов непригодна. #20 реализовала микрофон/preview/upload, MP3/WAV/OGG/WebM ≤20 MiB/≤120 с; #30 — `AttemptMediaStore`, `LocalAttemptMediaStore` (ключи, сигнатуры, безопасное удаление) и компенсацию rollback. Реальный код Vue, Java и БД остаётся источником истины при старте #68.

**Входит:** добавление примера аудио, название произведения, необязательные композитор/комментарий/один лист нот (PDF/JPG/PNG), список примеров и добавление следующего, работа без записей, защита переходов, восстановление после F5, жизненный цикл и удаление пользовательских файлов по общей политике.

**Не входит:** новая система попыток заданий, музыкальная оценка, подтверждение навыка, транскрипция, OCR/разбор партитур, создание GTP, видео, сторонние URL, публичная раздача материалов, безлимитная библиотека своих произведений, постоянное хранение пользовательских нот, интернет-пилот/авторизация (#38), интерфейс создания этюдов (#17), персональный план (#24), изменение логики подбора (#16).

**Последовательность зависимостей:** #30 принята и в main; #21 определяет 48h после окончания **всех** проверок и безопасную очистку, но исходная спецификация #21 ориентирована на попытки назначенных заданий. До интеграции #68 разработчик обязан сверить реализацию #21 и расширить единую политику на intake аудио **и** партитуры. Два несвязанных cleanup-сервиса создавать нельзя. Не применять TTL к учебным MP3/PDF каталога. Не использовать `SubmissionAttempt` с фиктивным `taskId`. База миграции выбирается по актуальному main/открытым PR, без заранее занятого номера.

## 3. Сценарии и состояния

1. Старт или восстановление сессии. Только `COLLECTING_EVIDENCE` разрешает создавать пользовательские примеры.
2. UI показывает необязательный блок «Мои исполнения», кнопки «Добавить запись» и «Перейти к заданиям». Отсутствие примеров — нормальное пустое состояние.
3. Ученик вводит название, выбирает файл либо записывает микрофоном; по желанию указывает автора, комментарий и один файл нот. Прослушивание черновика и явная отправка обязательны. Файл не попадает в сервер до отправки.
4. Сервер проверяет владение сессией и её состояние, лимиты, состав пакета и безопасно сохраняет аудио + опциональные ноты. При ошибке пакет не создаёт частично готового видимого примера. Ученик видит элемент списка со статусом технической проверки; «Загружено» ≠ «Навык подтверждён».
5. По F5/возврату сервер отдает список и метаданные; локальный выбор незагруженного файла не сохраняется.
6. «Добавить ещё» открывает пустую форму и новый requestId, не перезаписывает предыдущее. «Перейти к заданиям» вызывает **существующий** POST `/continue` даже при 0 примеров.
7. После успешного `continue` новые POST intake запрещены (конкурирующие upload и continue сериализуются блокировкой сессии); список уже принятых примеров доступен на чтение, пока хранится история.

**Предложенные ограничения MVP для подтверждения владельцем:** не более **10 примеров** на сессию; одно аудио обязательно для каждого примера; не более **одного** PDF/JPG/PNG с нотами на пример; название 1–200 видимых символов, автор 0–200, комментарий 0–2000. Аудио — наследовать ≤20 MiB и технические ≤120 с; партитура 1 байт – **10 MiB**. Это рабочий контракт, а не ранее утверждённые бизнес-лимиты. PDF/JPG/PNG — только перенос/хранение, не распознавание нот; GTP/GPX/MusicXML/видео — не принимать в MVP.

**Сложные ветви:** нет микрофона → file picker; score отсутствует → аудио допускается; нет аудио → пример не отправляется, но continue возможен; ошибка ноты/аудио → весь пример отклонён и форма остаётся для исправления; технический FAILED после приёма → запись остаётся с ошибкой, переход не блокируется; два параллельных POST с одним requestId → один пример; POST одновременно с continue → последовательный результат: либо целиком принят до READY, либо 409 без новой записи/сиротских файлов.

## 4. REST v1 (проект новых методов)

Базовый префикс:
`/api/v1/learners/{learnerId}/diagnostic-sessions/{sessionId}/evidence`.

**Общее:** оба ID — обязательные UUID path; принадлежность сессии конкретному learner/instrument проверяется **на сервере** по образцу `DiagnosticSessionService`. UUID не является авторизацией: до #38 только локальный тестовый режим и запрет публичного deployment; после #38 требуется principal+ownership. Клиенту не передаются `media_key`, физические пути, хеши и байты.

| Метод | Путь (от базы) | Назначение / успех |
| --- | --- | --- |
| GET | `/capabilities` | 200: enabled; audioFormats, maxAudioBytes, maxAudioSeconds, scoreFormats, maxScoreBytes, maxItems |
| GET | `/` | 200: массив EvidenceView по createdAt/ID; чтение возможно во всех существующих статусах сессии |
| POST | `/` | multipart/form-data; 201 + EvidenceView (либо 200 для прежнего requestId), Location указывает на созданный ресурс |

**POST form parts** (все как `@RequestParam`, кроме файлов):
- `requestId`: UUID, обязателен; уникален в рамках sessionId. Повтор после commit возвращает прежнюю запись без повторного создания файлов. При неожиданном конфликте целостности 409/CONFLICT.
- `title`: string, обязателен 1–200 после trim, не blank; никаких HTML-инъекций в UI.
- `composer`: string? ≤200, nullable.
- `comment`: string? ≤2000, nullable.
- `audio`: multipart file, обязателен; наследует поддерживаемые форматы и проверки #20.
- `score`: multipart file?, необязателен; PDF/JPG/PNG, лимит и сигнатура проверяются отдельно. Content-Type и расширение сами по себе недостаточны.

Пример **GET /capabilities**:
```json
{"enabled":true,"audioFormats":["mp3","wav","ogg","webm"],"maxAudioBytes":20971520,"maxAudioSeconds":120,"scoreFormats":["pdf","jpg","jpeg","png"],"maxScoreBytes":10485760,"maxItems":10}
```
Пример **201 / EvidenceView** (структурно тот же DTO у GET):
```json
{"id":"a7dd4ddb-bfde-4a79-a89f-67449884931b","title":"Yesterday","composer":"Lennon–McCartney","comment":null,"submittedAt":"2026-10-19T18:00:00Z","audio":{"format":"mp3","bytes":1340000,"status":"UPLOADED","durationSeconds":null,"errorCode":null,"mediaState":"AVAILABLE"},"score":{"format":"pdf","bytes":98000,"mediaState":"AVAILABLE"},"source":"STUDENT_UPLOADED","skillEvidence":"NOT_ASSESSED"}
```
DTO не означает публичного `GET /{id}/file`: прямые скачивания исходников пока недоступны; UI использует локальное preview до POST и показывает метаданные после POST. Будущая оценка #18/#22 должна читать файлы внутренним сервисом по ссылке на Evidence, с проверкой наличия после TTL; отсутствие файла после TTL не уничтожает метаданные.

**Ошибки:** 400 `INVALID_TITLE`, `MISSING_AUDIO`, `INVALID_AUDIO_SIZE`, `UNSUPPORTED_AUDIO_FORMAT`, `INVALID_AUDIO_CONTENT`, `INVALID_SCORE_SIZE`, `UNSUPPORTED_SCORE_FORMAT`, `INVALID_SCORE_CONTENT`, `INVALID_REQUEST_ID`; 403 `UPLOAD_DISABLED`; 404 `SESSION_NOT_FOUND` (в том числе чужой learner, без утечки существования); 409 `INVALID_SESSION_STATE`, `MAX_ITEMS_REACHED`, `CONFLICT`; 413 `PAYLOAD_TOO_LARGE`; 500/503 `STORAGE_UNAVAILABLE` с безопасным кодом. Не допускать в ответ stack trace/path/original filename. Ограничение полного multipart с учётом audio+score: не менее суммы лимитов + служебных границ (настроить Spring multipart отдельно; существующий лимит 21 MB недостаточен).

**Совместимость:** существующие `POST /continue` и `/tasks/{taskId}/attempts` не менять. Возможное изменение `SessionView.availableActions` — аддитивно: для COLLECTING_EVIDENCE добавляется `UPLOAD_EVIDENCE` при enabled, `CONTINUE_WITHOUT_RECORDING` остаётся; UI не полагается на наличие неизменяемой длины массива действий. Запрет POST после continue — атомарен.

## 5. Данные и владение

Новые таблицы (точные имена предложены; оформляются аддитивной Flyway-миграцией):
- `diagnostic_evidence`: id UUID PK; `diagnostic_session_id` UUID FK NOT NULL; `request_id` UUID NOT NULL; `title` VARCHAR(200) NOT NULL; `composer` VARCHAR(200) NULL; `student_comment` VARCHAR(2000) NULL; `source`='STUDENT_UPLOADED'; `submitted_at` timestamptz NOT NULL; constraint unique(session_id,request_id); index(session_id,submitted_at,id). Никакого `diagnostic_task_id`: пример существует **до** назначения.
- `diagnostic_evidence_media`: id UUID PK; `evidence_id` UUID FK NOT NULL; kind AUDIO | SCORE; `storage_key` internal (unique); `format`, `size_bytes`, technical status/error/duration nullable, `media_state` и `finalized_at`, `deleted_at`/diagnostics совместно с правилами #21; unique(evidence_id,kind). `kind=AUDIO` обязателен для опубликованного примера, `SCORE` опционален. Не путать статус технического аудио worker и факт удаления.
- `diagnostic_sessions` менять только при доказанной необходимости; существующая version/row lock для синхронизации POST и continue. `submission_attempts` и каталог не модифицировать ради новой предметной связи.

**Граница транзакции:** проверить ownership и статус + захватить lock сессии → найти существующий requestId → ограничить maxItems → сохранить файлы во внутреннее storage → зарегистрировать компенсацию обоих ключей при подтверждённом rollback → сохранить evidence и media rows и flush → commit. Для STATUS_UNKNOWN не удалять потенциально committed файлы автоматически; reconciliation по общей политике #21. Обязательна проверка отсутствия частичного пакета при ошибке второго файла, не только при DB rollback. Повтор submit с тем же ключом не переотправляет байты; новый пример получает новый requestId. Race с continue сериализуется по **одному** lock.

**Разделение обязанностей:** `LocalAttemptMediaStore` сегодня принимает только аудио и root `.../attempts`. Нужен общий безопасный низкоуровневый filesystem primitive (key validation, NOFOLLOW_LINKS, delete, rollback, orphan policy), поверх него media adapters с отдельными allowlists аудио и документов. Это **не** вторая самодельная подсистема хранения: повторно использовать или безопасно обобщить сервис #30 и контракт #21. Совместимые ключи/пути старых попыток должны остаться рабочими. Не хранить бинарные файлы в PostgreSQL или Git.

## 6. TTL, приватность и безопасность

- Новые аудио **и ноты** — временные пользовательские медиа: начальное правило 48 ч после финализации всех назначенных стадий обработки, конфигурация из PostgreSQL по #21, безопасная pending/retry/orphan reconciliation и защита занятых файлов. Не стартовать обратный отсчёт от временного `PROCESSED`, если запланирован реальный дальнейший анализ. Если только TECHNICAL_ONLY_V1 и никаких следующих проверок нет, финализация применяется по контракту #21.
- По истечении TTL сохраняются название, источник, связь с сессией, форматы, размеры, история ошибок и результаты будущей оценки; удаляется только бинарный исходник. После F5 UI показывает «Исходный файл удалён по сроку хранения», не ломая список и подбор.
- Score не должен переживать audio по умолчанию как «вечный учебный PDF». Настройки единого cleanup применимы к обоим; файлы преподавательского каталога вне очистки.
- Угрозы: IDOR/перебор UUID, path traversal/symlink, MIME spoofing, PDF/image polyglot, zip bomb (GTP/архивы не принимать), HTML-инъекции в title, flood/multipart, гонки/сироты, доступ к личному файлу по URL, несанкционированный фоновый анализ. Меры: owner-scoped запросы, локальный feature flag, приватная директория вне webroot, не выдавать raw upload-файлы HTTP, basename генерирует сервер, allowlist сигнатур, byte limits, транзакционный compensation и safe delete, экранирование Vue, ограничение количества, безопасные журналируемые коды.
- Логи: event, requestId, entity IDs, result code, count, duration без пути, исходных названий, автора, контента, нот или аудиобайтов. Полная auth/permissions до интернета остаётся #38; #68 не делает публичную эксплуатацию безопасной.

## 7. UX, локализация, наблюдаемость и установка

В `DiagnosticView.vue` разместить intake на экране `COLLECTING_EVIDENCE` **до** кнопки перехода к заданиям; новый `DiagnosticEvidencePanel.vue`/service по реальной Vue-структуре; переиспользовать компоненты микрофона, индикатора уровня и local preview из `entities/attempt`, не перепривязывая новый пример к `taskId`. Показывать способ записи, название произведения, опциональные поля, загрузку файла нот с подписью лимитов, отключённую кнопку при отсутствии аудио, явное подтверждение, список отдельных карточек, empty/loading/error/success, безопасный retry, ru/en, labels и keyboard flow. «Добавить ещё» не требует лишней навигации. Состояние после refresh получать из API, не из localStorage как единственного источника.

Установка: новая Flyway миграция (номер только после сверки main), сервис/контроллер/DTO, общие настройки multipart и feature flag, тестовые fixtures; не ломать V7–V9 и старые attempts. Сохранять `uploads.enabled=false` на незащищённых средах; отдельная возможность intake не должна обходить выключенную загрузку. Настройки лимитов проекта — код/config с фиксированной серверной валидацией, без новой платной инфраструктуры. Версии Java/PostgreSQL/Vue — унаследовать из репозитория.

После установки smoke: начать новую сессию, загрузить один PDF+audio, второй audio-only, F5 → две карточки; продолжить → READY_FOR_TASK → можно назначить упражнение; повтор POST с requestId → без дубля; новичок без файлов → READY_FOR_TASK; существующие попытки задания работают; проверить отсутствие бинарных файлов в публичных URL; TTL из #21 проверять с `Clock`/тестовым расписанием, не дожидаясь двух суток.

Откат: при нарушении целостности отключить новые POST intake (не отключать очистку старых файлов), вернуть Vue/Java к совместимому релизу, оставить аддитивные таблицы и старые метаданные; не обещать down-migration/восстановление уже очищенных файлов. Схема и Java должны оставаться совместимыми для безопасного rollback. Владельцу — локальный smoke и решение о приёмке после CI/код-ревью.
