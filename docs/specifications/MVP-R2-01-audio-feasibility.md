## 4. Состав минимального корпуса и протокол записи

Основа — комментарий #14 от 18.10.2026: 2–3 дубля ровного баса, 2–3 с нарушением темпа/остановками, 2–3 полифонического fingerstyle; контроль смартфон/компьютер по возможности. Минимум для первичной полноты — по два дубля в каждой группе, то есть шесть **реальных** записей, не шесть перекодировок одного файла. Количество — минимальный исследовательский пакет, не статистическое доказательство качества.

| Группа | Что должно быть представлено | Что размечается |
| --- | --- | --- |
| REAL-BASS | Ровный чередующийся бас под известный темп; целевые 60/80 BPM из исходного протокола | Реальный темп, начала атак, сдвиг начала, возможные отклонения |
| REAL-TIMING | Намеренная остановка и ускорение/замедление, точные события уточняются по факту | Интервалы ошибки, паузы сверх нотного эталона, локальное изменение темпа |
| REAL-POLY | Бас вместе с мелодией: условно успешный и намеренно ошибочный вариант | Слышимые атаки, голос, пропуск/замена баса и явно неразличимые участки |
| SYNTHETIC-CONTROL | Из исходных событий: контроль без нарушения, с известным сдвигом/пропуском/остановкой | Точные преобразования/seed/версия генератора; не подменяет REAL |
| QUALITY-CONTROL | Тишина, обрезанный/повреждённый файл, недоступный источник, лишний шум/клиппинг при наличии | Причина технической непригодности или неоднозначности, без оценки навыка |

При невозможности второго устройства отметить NOT_AVAILABLE и ограничение применимости; не делать вывод о переносимости между устройствами. Исполнитель/сеанс/устройство получают псевдонимы. Для записи указываются строй, инструмент, BPM/метр, версия нот, выбранные такты, условия микрофона/расстояния/комнаты, слышимый метроном, намеренная ошибка и фактическое содержание. Не требовать игры, не соответствующей уровню ученика: допускается упрощённый оригинальный басовый фрагмент с собственным эталоном.

Для GM-EB01 допустим фрагмент тактов 1–4 v0.8B; его точный диапазон и hash фиксируются. Значения beat — от нуля внутри такта 4/4, length — длительность в четвертях. Нотное время `((bar-1)*4+beat)*60/BPM` — только идеальная сетка, не действительное время записи. Начальный отсчёт/тишина фиксируются отдельно; полезный участок должен полностью соответствовать выбранным тактам. У каждого исходника отдельная лицензия/разрешение и проверка пригодности исполнения.

WAV предпочтителен как исходник без дополнительного сжатия; допускаются текущие продуктовые MP3/WAV/OGG/WebM в пределах 20 MiB/120 с для сопоставления. Конверсия в PCM является производной: сохранить hash источника, параметры/команду/версию декодера и производного, не менять исходник. Нет требования внедрять новый формат в приложение. Число каналов/частота дискретизации/длительность читаются из файла, а не доверяются расширению. Неизвестный или повреждённый формат отклоняется с технической причиной.

## 5. Контракты данных

Пакет имеет `schemaVersion=1`, `datasetId`, неизменяемую `datasetVersion`, `createdAt` UTC и `sourceCommit`. Манифест и содержимое версионируются совместно. Новое изменение разметки — новая версия, старый отчёт не переписывается.

| Поле | Тип / обязательность | Семантика / проверка |
| --- | --- | --- |
| recordingId | string, required, уникальный внутри версии | Псевдоним, без имени человека/исходного filename |
| kind / group | enum, required | REAL / SYNTHETIC / QUALITY; группа корпуса |
| recordingGroupId / performerId / sessionId / deviceId | string required для REAL | Связанные варианты одного исполнения не разносить по calibration/holdout; только псевдонимы |
| fileRef | string required для доступного материала | Относительно явно выбранного локального root; без absolute, `..`, symlink и выхода из root. Только read-only, произвольные URI не открывать |
| sourceSha256 / bytes / durationMs / sampleRateHz / channels | hash/int, required после регистрации | Проверить actual; durationMs > 0; отрицательные/нефинитные значения недопустимы |
| referenceId / referenceVersion / referenceSha256 / barFrom / barTo | string/string/hash/int/int, required для музыкального примера | Версия эталона и диапазон согласованы; 1 ≤ from ≤ to ≤ число тактов |
| rightsBasis / consentRef / useScope | enum/string/enum, required для REAL | Собственная запись/допустимая лицензия/явное разрешение; локальная проверка не означает согласие на публичный Git или внешний ИИ |
| annotationRef / annotationVersion / annotationSha256 | string/string/hash, required для готового пакета | Техническая ссылка на локальную фактическую разметку |
| split | enum required | CALIBRATION / HOLDOUT / DIAGNOSTIC_ONLY; назначен до эксперимента |
| availability | enum required | AVAILABLE / MISSING / WITHDRAWN; отсутствующий исходник не считается воспроизводимым |
| transform | object required для SYNTHETIC/производной | Исходная ссылка/hash, преобразование, параметры, seed при случайности, версия инструмента |

Контракт эталона: referenceId/version/hash, origin/rights, instrument/tuning, meter, BPM, диапазон тактов и события `eventId/bar/beat/durationBeats/voice/notes`. Исходный score JSON не менять: при необходимости подготовить производное представление с сохранением связи. Одновременное созвучие — одно событие атаки с несколькими нотами; bass/upper не смешивать. Затухание струны не объявлять новой атакой. Для каждого eventId возможны несколько ручных наблюдений либо явное «неразличимо».

Ручная разметка: annotationId/version, recordingId/sourceSha256, annotatorId, reviewedBy (null, если второго проверяющего нет), eventId либо null для лишней атаки, onsetMs и интервал допустимой неопределённости [fromMs,toMs], voice BASS/UPPER/MIXED/UNKNOWN, label MATCH/OMISSION/EXTRA/WRONG_BASS/PAUSE/TEMPO_CHANGE/AMBIGUOUS, фактический интервал события и комментарий. При подтверждённой замене баса actualNotes содержит вручную определённые ноты; при невозможности определить высоту — UNKNOWN, а не выдуманная нота. Время от начала конкретного декодированного файла, не от номера такта. Нельзя автоматически подставить идеальные timestamps как ручные метки.

Правила: from ≤ onset ≤ to и все границы внутри длительности; отрицательные/NaN запрещены; ссылка eventId существует, кроме EXTRA; PAUSE имеет начало/конец и относится к незапланированному перерыву, а не нотной паузе/тихому затуханию. Намеренная ошибка не считается подтверждённой, пока не размечен фактически услышанный результат. Одного автора разметки достаточно для пилотного пакета, но это ограничение явно записывается; неоднозначное не принуждается к «правильно/неправильно».

Отчёт проверки содержит только datasetId/version/hash, код ошибки и recordingId/поле, доступность, покрытие групп и READY_FOR_POC либо INCOMPLETE/INVALID. Он не содержит full path, аудио/секреты/имя исполнителя и не выставляет PASS ученику. Отсутствующий REAL или неподтверждённые права дают INCOMPLETE, а не готовый пакет. Утилита проверяет наличие записи об основании и ручном подтверждении; истинность лицензии/согласия и музыкальных меток проверяет ответственный, не автоматический парсер. Ошибка схемы/hash/ссылок даёт INVALID. Код возврата утилиты: 0 — READY_FOR_POC, 2 — INCOMPLETE/INVALID, 3 — ошибка среды/ввода; отчёт различает эти причины.

## 6. Методика и границы доверия

До #15 задаются единицы и правила подсчёта. Числовая точность и границы пригодности определяются по данным; здесь не назначается выдуманный SLA или порог «навык подтверждён».

| Критерий | Метрика для #15 | Что нельзя скрывать |
| --- | --- | --- |
| Начала атак | Precision/Recall/F1 однозначного one-to-one сопоставления по согласованному окну; ошибки onset в ms: median/P95 | Пропуски/лишние атаки, неоднозначные labels отдельно; одна атака не сопоставляется нескольким |
| Темп | Абсолютная и относительная ошибка BPM, ошибка по локальным участкам | Ошибка в 2 раза/половину темпа отражается отдельно; произвольный global time-warp не исправляет настоящую нестабильность |
| Незапланированные остановки | Precision/Recall и ошибка начала/конца размеченного интервала | Нотная пауза/затухание не считаются ошибкой ученика |
| Бас | Сопоставление размеченных басовых событий: recall/precision и confusion для пропуска/замены/UNKNOWN | При полифонии наличие низкой частоты не доказывает правильную басовую ноту; отделить attack и pitch |
| Воздержание | coverage = оценённые пригодные единицы / все пригодные; доля ошибочных категоричных выводов | Не исключать трудные записи молча, публиковать причины abstain и знаменатели |
| Ресурсы | Длительность записи и обработки, CPU/память по возможности, версии/оборудование, число внешних запросов и стоимость | Измерять, не гарантировать неизвестную latency; внешние обращения по умолчанию отсутствуют |

Если ошибок сопоставления нет и знаменатель равен нулю, выводить NOT_APPLICABLE, не делить на ноль и не выдавать идеальный F1. Сопоставление и окно, допустимый стартовый offset, метрики и подготовка данных фиксируются в версии протокола до проверки holdout. Допустим единый сдвиг записи/отсчёта; деформации времени, которые убирают реальные паузы/ускорения, запрещены для оценки этих же дефектов. Чувствительность к окну показывается отдельно. #14 задаёт форму конфигурации `matchingWindowMs / qualityPolicyVersion / abstainPolicyVersion`; рабочие значения подбирает #15 на CALIBRATION, замораживает и проверяет на HOLDOUT, #31 утверждает область применимости. До этого критерий остаётся UNVALIDATED.

Trainable модель в #14 не обучается. Для предотвращения утечки все перекодировки/нарезки одного исполнения и связанные ручные метки имеют одну recordingGroupId и один split. Разделение шести пилотных записей фиксируется до #15: по одному независимому дублю каждой REAL-группы в CALIBRATION и HOLDOUT. Если это невозможно — NO_INDEPENDENT_HOLDOUT, результат только диагностический, без заявления обобщающей точности.

Abstain причины: INPUT_INVALID, RIGHTS_UNCONFIRMED, REFERENCE_MISSING, ANNOTATION_AMBIGUOUS, QUALITY_UNSUITABLE, OUTSIDE_VALIDATED_DOMAIN, METHOD_UNVALIDATED. Они не означают слабый навык ученика. Алгоритмическая confidence не считается вероятностью правильного ответа без отдельной калибровки. LLM не используется как ground truth.

## 8. Безопасность, настройки и воспроизведение

Утилита запускается локально вручную, не предоставляет сервер и не сканирует product media root. Root входов задаётся явно; все ссылки относительные и проверяются на traversal/symlink, вывод размещается отдельно от входа. Source read-only; hash до/после одинаков. Лимиты входов соответствуют продуктовой базе выше; превышение размера/длительности отклоняется, а не запускает неограниченный decode. Использовать текущий ограниченный ffprobe-подход, не дублировать сетевой ingest. Версию инструмента, ОС/JDK и параметры сохранять в приватном паспорте запуска; команды не должны включать секреты.

Настройки: локальный `--root` (обязателен, существующий каталог), `--manifest` (обязателен, относительный файл внутри root), `--report` (обязателен, отдельный новый отчёт вне входного root), режим `--offline` обязателен/единственный в этой задаче. Некорректные/пустые параметры завершаются кодом 3 до чтения медиа; сеть/автоматическое скачивание не включаются. Существующий отчёт не перезаписывать неявно: новый runId. Числовые лимиты и версия протокола входят в пакет конфигурации, ошибки конфигурации дают явный отказ. Флаги production/config PostgreSQL не добавляются.

Личные записи остаются у владельца: только явно выбранные им локальные оригиналы читаются read-only; долгоживущие копии и бэкапы не создаются. Product upload нельзя незаметно экспортировать в benchmark ради обхода TTL #21. Срок/состав исследовательского использования фиксируется в согласии; отсутствие основания делает материал непригодным. Если исходник удалён/согласие отозвано, пакет маркируется MISSING/WITHDRAWN, hash/обезличенный отчёт не объявляются возможностью воспроизвести звук. Возобновление требует нового допустимого материала, а не восстановления из скрытого архива. Внешние ИИ/хранилища не вызываются без отдельного решения.

В Git: контракты, инструкция, схема, лицензии на собственный безопасный эталон и безопасные синтетические structural fixtures. Медиа и приватный manifest/разметка исключены из staged diff; приватный root — вне checkout (добавочный ignore не заменяет проверку git diff). Не менять gitignore так, чтобы скрыть реальные файлы приложения. Допустимые диагностические коды — без путей, исходных имен и содержимого записей.

Проверка после установки утилиты на JDK 21: сборка/тесты → валидный синтетический fixture (технический успех, но недостаточно REAL) → испорченный hash/путь/ссылка (явный отказ) → локальный полностью размеченный REAL-пакет (READY_FOR_POC) → неизменность hash входов и отсутствие данных в Git/логах. Конкретные команды сборки/запуска разработчик фиксирует в README вместе с версией и условиями ffprobe; документ не выдаёт ещё не написанную команду за исполнимую.

Откат: при изменении исходника, утечке данных или несогласованной интерпретации остановить утилиту, не передавать результаты #15, отклонить версию пакета и вернуться к предыдущей версии контракта/инструмента. Удалить только собственный временный output по согласованному процессу; личные оригиналы не трогать. Проверить hashes, отсутствие фоновых процессов/сетевых обращений и неизменность приложения/БД. Удалённый владельцем исходник не восстанавливается откатом кода. Компенсация storage #30 к этому откату не приравнивается.
