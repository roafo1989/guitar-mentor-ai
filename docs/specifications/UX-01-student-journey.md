## Паспорт и решение

Источник: #51, родитель US-003/#57, эпик #53; БТ0.10 / BT-006/007/012 → ТЗ0.17 / FT-003-04. NFR-002/003/004/007/008, SEC-001/005/008. Исходная база frontend-аудита: main `26bd83c5fec3a439685d481ea0a8e4ba24a78409`. Заключительная сверка: main `b6485e4ba5f98cf55ff03e12d926049d61810da0`, PR122/119 merged23.10; compare показывает только backend/CI/docs, без изменений frontend. Выводы UX-аудита сохраняются; наличие metadata119 больше не внешний gate,120ещё нужен для pinned resources.

**Аналитический пакет подготовлен, прототип предлагается к согласованию.** Команда на анализ не означает утверждение нового дизайна или начало продуктового кода. Исходный AC #51 требует, чтобы владелец прошёл прототип и согласовал предложения до реализации. Поэтому целевое состояние #51 — **Анализ / Ожидание UX-согласования**, Issue OPEN. Реальная запись полей Project оговаривается в Issue отдельно; после тайм-аутов доступ к GitHub восстановлен, а локальный прототип заблокирован URL policy. Не считать подготовку макета приёмкой всей задачи.

Как ученик, я хочу сразу понимать, куда вернуться и что сделать сейчас, чтобы заниматься 30–45 минут, не проходя повторно настройку и не теряя запись. Цель — ясность и сохранение контекста. Числа ниже — статический разбор переходов/контролов, не наблюдение за пользователем, не исследование скорости и не измерение конверсии.

**Главное решение:** контекстная главная с одним основным действием; существующий `/diagnostics` становится понятным пользователю рабочим пространством «Занятие». Пути URL и доменные переходы не меняются. Внутри — «Материалы», «Моя запись», «Результат», затем история по запросу. Отдельная отправка и подтверждение завершения сохраняются. Автоматическое следующее задание не изображается работающим.

## Текущий и целевой путь; правила счёта

Переход — смена route; действие — активация кнопки/ссылки/контрола. Ввод символов, прокрутка, автоматические GET/polling, ожидание сети и действия в системном file picker не считаются. Save, Next, Send и подтверждение считаются отдельно. «До» — путь по основному CTA либо явно названному кратчайшему пути. Это не гарантия, что каждый пользователь проходит именно так.

## Прототип и способ review

[Интерактивный HTML](../ux/UX-01-student-workspace-prototype.html) — автономный файл: скачать и открыть браузером. Внешних ресурсов, fetch, микрофона, upload, localStorage и реальных решений нет. Панель выбора сценария/размера/языка находится **вне интерфейса продукта** и служит review, в реализацию не переносится. Данные GM-EB01 демонстрационные; сценарий «пример реальной оценки» показывает только представление, не выдуманное доказательство исполнения.

Пройти: Главная→Продолжить; Записать→Остановить→Прослушать→Отправить; выбрать «Нет музыкальной оценки»; ContinuePracticing; Complete→Cancel и Complete→Confirm; error upload; mobile360; RU/EN. Через сценарии доступны loading, resume error, empty, intake, каталог, два шага onboarding. Формы профиля/анкеты схематичны: существующая полная валидация/состав полей остаются обязательными, из макета нельзя вывести их удаление.

Контент должен оставаться полным в реализации: поля119/85, доступные PDF/MP3 и их fallback, реальные списки attempt/decision/evidence и пагинация19. Макет не поставляет музыкальные файлы, не реализует аудио и не изображает такой тест пройденным.

## Контракт главной — предложение H1

Фронтенд, Standard, без API/БД изменений. Один компонент/сервис summary читает существующие данные, выдаёт view state. До запросов — loading. Не трактовать отсутствие локального ключа как глобальное отсутствие занятий на сервере: MVP восстанавливает только выбранный этим браузером контекст, серверного поиска всех активных сессий здесь нет.

| Подтверждённые данные | Основной CTA / место | Ошибка/граница |
| --- | --- | --- |
| Нет выбранного learnerId | Создать профиль → `/profile` | Home не делает POST. |
| Learner GET404 | Создать профиль | Существующий learner store очищает свой ID; не чистить всё localStorage. |
| Learner есть, sessionId отсутствует, background GET204 | Продолжить настройку → `/onboarding` | 204 — нормальное отсутствие анкеты, не ошибка. |
| Learner есть, sessionId отсутствует, background GET200 | Открыть диагностику → `/diagnostics` | Не делать start автоматически. |
| Session COLLECTING_EVIDENCE | Продолжить диагностику → `/diagnostics` | Сохранить intake/draft guards при последующем уходе. |
| Session READY_FOR_TASK | Выбрать упражнение → `/diagnostics` | Не загружать/назначать каталог с Home ради клика. |
| Session TASK_ASSIGNED + task + learning ACTIVE | ContinueLesson + title/code/version → `/diagnostics` | Без реконструкции Exercise по current-коду. |
| Learning COMPLETED_PASSED или COMPLETED_BY_LEARNER | Посмотреть результат → `/diagnostics` | Не обещать следующее задание и не создавать новую session. |
| Только GET сохранённой session вернул404 | Очистить только её selection-key, затем ветвь no-session | Ошибка task/media/catalog/learning404 не разрешает очистить sessionId. |
| Network/5xx, task=null при TASK_ASSIGNED, неожиданная схема | Локальный Retry + безопасный текст; последняя подтверждённая карточка не становится новой сессией | Не маскировать под «новый ученик», не терять ключи и не показывать ложную готовность. |

Существующие ключи: `guitar-mentor.learnerId`, `guitar-mentor.diagnostic.{learnerId}.ACOUSTIC_GUITAR`. Новых ключей/токенов/секретов нет. Background запрашивается только при no-session, чтобы не требовать повторную анкету для уже назначенной работы. learnerStore.restore() возвращает void и записывает ошибку в store.error; summary обязан проверить store.error/learner, а не рассчитывать только на catch. Повторная попытка — GET, без скрытых POST/PUT. REST:

- GET `/api/v1/learners/{learnerId}` через learnerStore.restore;
- GET `/api/v1/learners/{learnerId}/instruments/ACOUSTIC_GUITAR/background` (200/204);
- GET `/api/v1/learners/{learnerId}/diagnostic-sessions/{sessionId}`;
- GET тот же prefix + `/tasks`;
- GET тот же prefix + `/tasks/{taskId}/learning`.

Path UUID и ownership/ошибки/API bodies существующие, не меняются. Новых query/header/body нет; GET идемпотентны. Сборка summary: запомнить learnerId/sessionId+generation, поздний ответ другого контекста не отображать; unmount обесценивает callbacks. Ошибки локализованы из существующего error model, исключения/UUID/SQL не печатать в основной текст. `HomeView` только маршрутизирует, запись/изменение домена остаётся на старом экране.

## Представление занятия — предложение H2

Путь остаётся `/diagnostics`; пользовательская подпись «Занятие» (EN Lesson) не меняет диагностическую модель. Внутренние COLLECTING/READY/ASSIGNED остаются; не показывать искусственный stepper, обещающий уже готовую персональную программу.

Порядок: название и одна строка version/BPM/meter; на desktop материалы слева, запись и результат справа; на narrow экран — материалы→запись→результат, без дублированного DOM. Материалы сохраняют goal/instructions/criteria85, PDF collapsed, Audio и fallback. Результат сначала показывает актуальный статус выбранной попытки и доступные действия; method/evidence/старые revisions — раскрываемые details. История попыток/решений/навыков — один подписанный контейнер с существующими вложенными списками и More/retry; перенос не удаляет данные и не лишает доступа к пагинации. Ошибка конкретного списка видима у его блока, раскрытие не отменяет запрос/повтор.

| Состояние | Представление / действие | Что сохраняется |
| --- | --- | --- |
| Нет попыток | Record primary, file secondary, Send недоступен | Capabilities и формат/размеры из20/94. |
| Recording | Ясное «Идёт запись», Stop primary | Захват, индикатор уровня, audio ownership, запрет ухода при busy. |
| Draft ready | Имя/размер, Listen, Replace, comment optional, Send primary | Файл не отправляется до Send; dirty guard. |
| Upload in flight | Отправляем, повтор недоступен | Idempotency requestId, один POST, нельзя закрыть контекст во время busy. |
| Upload failed | Inline error рядом с draft, RetrySend | Тот же файл/comment/requestId; новый ключ только по существующим правилам. |
| UPLOADED/PROCESSING | Техническая обработка; автоматическое обновление | Polling из20, не новый интервальный цикл/дубли запросов. |
| PROCESSED + NO_ASSESSMENT | Обработано; музыкальная оценка недоступна | PROCESSED не равен musical PASS, нет выдуманных баллов. |
| Assessment AVAILABLE | Краткая recommendation, раскрываемые критерии/основания; обе допустимые альтернативы решения | availableActions, expectedVersion/baseAssessmentId, выбранная attempt, draftBusy/freshness из19. |
| Decision409/network/duplicate | Safe error и существующий reload/retry, без молчаливого применения старого решения | История, причины, idempotency и guards19. |
| Terminal | CompletedPassed отдельно от CompletedByLearner; read-only materials/history; next unavailable | Повторная отправка закрыта; навык не повышается из решения ученика. |
| Media404/TTL | Локальный fallback у источника | История попыток/оценок остаётся, никакой current-подмены. |

Первичный визуальный вес меняется по состоянию, а не запрещает альтернативу: до записи Record, draft Send, при неопределённой оценке ContinuePracticing; Complete виден вторичным, если сервер разрешил. Если recommendation PASS, допустимо выделить Complete, оставив ContinuePracticing доступным. Это только оформление уже разрешённых действий. Нельзя добавить client-only разрешение, убрать confirmation или заменить контракт решения.

## Общие правила и ограничения

Существующая спокойная зелёная палитра/логотип. Шаг отступов4/8px, основной текст16px, вторичный14px; контраст текста не ниже4.5:1, focus не только цветом, controls на touch≥44px. Desktop max content1120–1200px, две колонки при достаточном месте; от680px и ниже одна. 360px и200%zoom без перекрытия действий/горизонтальной прокрутки страницы. Это предлагаемые UI-параметры для приёмки, не измеренные характеристики текущего приложения.

Sticky header, имя, logo→home, RU/EN/F5 и status инструментов сохраняются. Брендовые иконки не перерисовывать в рамках51. No backdrop dismiss и reopen/minimize не меняются. При route change остаются существующие close/stop guards; изменение названия пункта nav не создаёт перенос звучания между формами. Не скрывать саму Send/Complete/error в collapsed details. Native details/summary, heading hierarchy, aria-live=status без объявления каждого audio tick; focus возвращается существующим audio dialogs. No v-html для контента/ошибок. Прототип не заменяет реальную проверку доступности.

Новых env/config/миграций/прав/платных сервисов/аналитики нет. Платформенная аутентификация/публикация остаются US-007, ИИ/аудиоанализ — отложеннаяUS-005. Не логировать файлы/comment/session tokens. Security-проверка касается safe text, отсутствия побочных POST и сохранения имеющихся ограничений локального MVP; SEC-002/003/006/007 не реализуются дизайном.
