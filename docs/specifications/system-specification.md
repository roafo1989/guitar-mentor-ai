## 2. Контракты, найденные в коде

Все пути имеют префикс `/api/v1`; ниже он опущен. Наличие метода в исходниках не означает успешной приёмки всего ФТ.

| Метод и путь | Назначение / источник | ФТ |
| --- | --- | --- |
| POST `/learners`; GET `/learners/{learnerId}` | Создать/получить профиль; [UC-01](../use-cases/UC-01-learner-profile-api.md), LearnerController/DTO | FT-001-01 |
| PUT `/learners/{learnerId}/preferences` | Замена предпочтений; валидация и атомарная запись | FT-001-01 |
| GET/PUT `/learners/{learnerId}/instruments/{instrumentCode}/background` | Анкета, 204 при отсутствии; [UC-03](../use-cases/UC-03-onboarding-experience-goals.md) | FT-001-03 |
| POST `/learners/{learnerId}/diagnostic-sessions`; GET `…/{sessionId}`; POST `…/{sessionId}/continue` | Начать/восстановить сессию, перейти к заданию; DiagnosticSessionController | FT-002-01 |
| GET/POST `/learners/{learnerId}/diagnostic-sessions/{sessionId}/tasks` | Прочитать/назначить задание, AssignRequest: exerciseCode | FT-002-01/03 |
| GET `/exercises`; GET `/exercises/{code}` | Каталог и упражнение | FT-002-03 |
| GET `/exercises/{code}/preview/audio`; GET `…/preview/pdf`; GET `…/score`; GET `…/events` | Материалы каталога; отсутствие бинарного fixture требует явной обработки | FT-002-03 |
| GET `/system/ping` | Проверка приложения; не показатель готовности полного сценария | FT-006-02 |

Будущие API приёма файлов, попыток, результатов, решений, плана и приглашений детализируются в рамках FT-003/004/005/007 до разработки. В этой редакции не назначаются выдуманные URL или коды статусов для ещё не согласованных операций. Для выбранной задачи спецификация обязана добавить метод/путь, payload/response, ошибки, валидацию, права, транзакцию, повторы и пример запроса.

## 3. Данные и инварианты

| Сущность | Назначение и инвариант | Наличие |
| --- | --- | --- |
| Learner, InstrumentProfile, MusicPreference | Профиль; уникальный инструмент ученика, уникальный styleCode; предпочтение не оценка | Миграции main |
| LearningBackground | Одна анкета на InstrumentProfile, нулевой опыт допустим | Миграции main |
| DiagnosticSession | Одна активная сессия инструмента; повтор start восстанавливает её | Миграции main |
| Exercise, SkillCode, DiagnosticTask | Версия упражнения, навыки и одна текущая выдача задания на сессию | Миграции main; каталог пока ограничен |
| Attempt | Неизменяемая связь ученика, задания, версии упражнения и отправки; retry не создаёт новую доменную попытку | Целевая модель |
| CriterionAssessment | Критерий, результат/неоценённость, метод/версия, уверенность, причина/замечания | Целевая модель |
| StudentDecision | Решение и причина отдельно от оценки, автор и время; продолжение не подтверждает навык | Целевая модель |
| MediaAsset | Владелец, связь с сессией/попыткой, безопасный ключ, MIME/размер/checksum, lifecycle timestamps, deletedAt | Целевая модель ADR-0002 |
| SystemSetting | Настройки TTL/cleanup читаются из БД без перезапуска | Целевая модель ADR-0002 |
| Account, AccountIdentity, Invitation | Identity по issuer+subject уникальна; activation атомарна; отключение прекращает доступ | Целевая модель US-007 |

Текущие состояния DiagnosticSession в коде: `COLLECTING_EVIDENCE → READY_FOR_TASK → TASK_ASSIGNED`. Полный учебный цикл ещё не следует из этих трёх состояний. Целевые состояния обработки записи, оценки, решения и ошибок надо согласовать отдельно: нельзя складывать оценку агента и жизненный цикл работы ученика в одно поле.

## 4. Транзакции, повторы и отказы

- Сохранение профиля/анкеты атомарно; создание активной сессии защищено ограничением БД и обработкой конкуренции.
- Для будущего upload/submit определить ключ идемпотентности и область его уникальности до реализации; повтор транспортного запроса не равен новой попытке ученика.
- Файл и БД не составляют одну транзакцию: согласовать промежуточный статус, компенсацию неуспешной записи и обнаружение потерянных объектов.
- Обработка получает ограниченную lease; зависшая работа безопасно отменяется до удаления. Ошибка удаления остаётся наблюдаемой и повторяемой.
- Повтор анализа хранит новую версию результата либо отдельный запуск, не перезаписывая исходную оценку; внешний ИИ не закрывает задания.
- После удаления исходника повторный анализ требует новую загрузку; результаты и решения остаются доступны.
- Ошибки внешнего поставщика, таймаут, исчерпание бюджета/диска и неподдерживаемый файл должны давать понятное состояние с действием пользователя.

## 6. Параметры, требующие решения

Срок TTL — Q-001 ТЗ: действующий ADR содержит processed+24h, unprocessed 48h, cleanup 60min; позднее обсуждение 2 дней требует сверки с владельцем/БА, а не молчаливой замены. Форматы, размеры, квоты, CPU/timeouts, измеримые метрики и бюджет ИИ — Q-002. IdP и настройки сессии/размещения — Q-003. До решения соответствующие части спецификации не объявляются готовыми к реализации/публикации.

## 7. Проверяемость и трассировка

Каждое ФТ имеет AC в ТЗ; тест-кейс ссылается на ФТ и применимые NFR/SEC, фиксирует версию требований, предусловия/данные, шаги, ожидаемый и фактический результат. Изменение БТ требует пересмотра связанных тестов. Закрытые старые Issues не служат доказательством текущей полноты US; сквозная приёмка проводится отдельно.

## 8. Главная и навигация — US-009

База: BT-010/011 БТ 0.2, PR #48 (объединён). Корневой маршрут `/` открывает главную; логотип в header ведёт на этот маршрут из разделов. Сохранённые данные профиля восстанавливаются через существующие API; собственный новый API главной не требуется. При отсутствии профиля доступны начальные действия; ошибка загрузки имеет явное состояние и повтор. FT-009-01/02 трассируют уже реализованный объём; новый пользовательский тест не заявляется выполненным. Подробные решения сквозного UX остаются в #51 / FT-003-04 и не дублируют #17–#20.
