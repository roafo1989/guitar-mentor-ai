# Guitar Mentor AI: восстановление после потери ноутбука / SSD

Связано с #40 (OPS-02), #39 (домашний пилот), #26 (локальный запуск).
Дата: 26.10.2026. Среда: Windows, PowerShell 7.4+, PostgreSQL 17, Java 21,
Vue/Vite, Caddy, Tailscale Funnel. Это не инструкция для Angular/порта 4200.
Release tooling находится в актуальном `main` (PR #246 merged); восстановление использует только совместимые с ним скрипты `scripts/pilot/`.

## Что получаем и когда можно считать защиту работающей

Скрипты и эта инструкция хранятся в GitHub. Данные и переносимые секреты —
в зашифрованных версиях restic, которые загружаются непосредственно в облако
через rclone. Диск D: и C: одного SSD не являются независимыми копиями.
Папка Google Drive для синхронизации не используется как доказательство отправки.
Пользователь выбрал облако; новый сервер и платный хостинг не требуются.
Проверьте свободный объём/условия выбранного облака, бесплатность не гарантируется.

Цели: потерять не более суток изменений (RPO ≤24 ч); после установки Windows
и доступа к интернету восстановить рабочее приложение ориентировочно за 1–2 часа.
Это **цели**, не измеренные обещания: скорость зависит от размера копии,
скачивания инструментов и доступности облака. Засеките реальное время репетиции.
Повреждение самого устройства и утрата доступа к облачному аккаунту — разные риски.

Защита подтверждается только после всех четырёх действий:

1. Проверили карту всех папок и секретов на исходном ПК.
2. Выполнили первую облачную копию; сохранили её полный snapshot ID.
3. Скачали эту копию в новый каталог, восстановили отдельную БД, проверили файлы.
4. Проверили приложение из восстановленного комплекта без Funnel и записали время.

Написанный скрипт, успешный `pg_dump` и `restic check` по отдельности этих условий
не заменяют. Владелец пока не запускал новый DR-комплект; реальная копия и репетиция
**NOT_RUN**. Автотесты работают на синтетических данных.

## Состав копии

| Данные | Источник | Восстановление |
| --- | --- | --- |
| Пользователи, уроки, история, настройки, библиотечные метаданные | БД `guitar_mentor_pilot` | Новый PostgreSQL, роль/БД, custom dump |
| DEV-данные | БД `guitar_mentor`, роль `guitar_mentor_app` | Отдельный dump; можно явно выключить `devEnabled` |
| Постоянные оригиналы библиотеки PILOT | `D:\GuitarMentorPilot\data\library` | Восстанавливаются вместе с парным dump |
| Постоянная библиотека DEV | `backend\.local-media\library` | `devLibraryPath` нужно проверить по реальному запуску |
| Текущая и предыдущая сборки | `releases/<id>` + `release-state.json` | Точные JAR/web и их хеши, без пересборки и обновления схемы |
| Запуск/обновление/откат | `tools`, корневые `.ps1/.cmd/.bat/.caddyfile` пилота | Сохраняются установленные и локальные версии; ярлыки создаются заново |
| Настройки пилота | `application-pilot.yml`, `pilot-tools.json` | Секретный payload, не в публичном Git |
| Исходники и неопубликованные коммиты | `sourceRoot`, git bundle `--all`, binary diff | Точный HEAD, локальные изменения/удаления, untracked и `.env` |
| Google/SMTP/БД/HMAC | `%LOCALAPPDATA%\GuitarMentorAI` | Расшифровка DPAPI на старом Windows → AES-GCM → DPAPI на новом |
| Ноты/архив/другие локальные скрипты | Только явно перечисленные `extraFolders` | `extra/<id>`, оригинальные пути сохранены в config |
| Доступ к облаку | Копия `rclone.conf` внутри шифрованного restic | Для первого скачивания — новый вход в тот же аккаунт |

Кэши npm/Maven, target/dist, старые builds/backups/logs не нужны для восстановления
текущего пилота и не копируются. При необходимости конкретный невоспроизводимый
каталог добавьте в `extraFolders`. В Git bundle не входят недостижимые удалённые
коммиты и состояние незавершённого merge/index; итоговые файлы и достижимая история
сохраняются. Репозиторий после восстановления остаётся на точном detached HEAD;
не делайте сразу pull поверх локальных изменений.

**Временные записи/документы диагностики (`attempts`, `scores`) исключены**,
непрерывный архив таких медиа не создаётся. Их DB-метаданные остаются; после аварии
сами временные файлы могут быть недоступны, потребуется повторная загрузка.
Не добавляйте их в extraFolders. Библиотечные оригиналы — постоянные данные,
политика 48 часов на них не распространяется. Retention зашифрованных копий
библиотеки — отдельная политика: удаление в приложении не стирает старые snapshot.

## 1. Настроить на существующем ноутбуке

Рабочий каталог разработки и текущую ветку не переключаем. Получите инструменты
отдельно командой ниже или распакуйте выданный архив в `D:\Tools\GuitarMentorRecovery`:
он уже содержит `scripts` и `docs`. Владелец разрешил публикацию ветки 26.10.2026.
Используйте `main`; не восстанавливайте release tooling из старой ветки PR #219. До приёмки сначала проверьте PR Checks
и оставшиеся пункты Windows/реального облака из QA-отчёта.

```powershell
git clone --branch ops/40-disaster-recovery https://github.com/roafo1989/guitar-mentor-ai.git D:\Development\guitar-mentor-recovery
cd D:\Development\guitar-mentor-recovery
pwsh -NoProfile -File .\scripts\recovery\Install-RecoveryDependencies.ps1
# Только если нужно установить недостающие инструменты:
pwsh -NoProfile -File .\scripts\recovery\Install-RecoveryDependencies.ps1 -Install
```

Для архива вместо `git clone`/`cd` выше выполните `cd D:\Tools\GuitarMentorRecovery`;
остальные команды одинаковы. Архив инструментов **не содержит ваших данных**
и сам по себе не является резервной копией приложения.

PostgreSQL уже установлен: не переустанавливайте его на рабочем ПК. Нужны его
утилиты `pg_dump`, `pg_restore`, `psql`, `createdb` версии 17. После установки
инструментов заново откройте PowerShell, чтобы обновился PATH. Скрипты winget
не меняют настройки PostgreSQL, Google, домена и не публикуют сайт.

Подключите своё облако:

```powershell
rclone config
# n → имя gm-backup → выбрать провайдера (например drive для Google Drive)
# Войти в выбранный аккаунт в браузере. НЕ создавать публичную ссылку.
rclone config file
rclone lsd gm-backup:
```

Названия/номера пунктов выбора провайдера могут меняться: выбирайте по имени.
`gm-backup` должен указывать на реальное облако, не на backend local/alias
этого компьютера. Для Google Drive без ограничения app-folder используйте
доступ, позволяющий новому входу найти ранее созданную папку restic; ограниченный
`drive.file` может затруднить восстановление после смены OAuth-клиента.
Проверьте выбранный аккаунт и возможность повторного входа с другого устройства.
Если `rclone config file` показал другой путь, измените `rcloneConfig` ниже.

Личный config держите вне Git:

```powershell
$cfgDir = Join-Path $env:LOCALAPPDATA 'GuitarMentorRecoveryConfig'
New-Item -ItemType Directory -Force $cfgDir | Out-Null
$cfg = Join-Path $cfgDir 'recovery.local.json'
Copy-Item .\scripts\recovery\recovery.example.json $cfg
notepad $cfg
pwsh -NoProfile -File .\scripts\recovery\Recovery.ps1 -Mode Inventory -ConfigPath $cfg
```

Проверьте `pilotRoot/sourceRoot/devDatabase/devLibraryPath`. База пилота и порты
соответствуют текущему release tooling: `guitar_mentor_pilot`, 5432, 8081/8090.
DEV: 8080/5173. Не подставляйте dev-данные вместо pilot.
Временно хранится полный payload, поэтому нужен свободный объём под обе БД,
постоянные файлы, две сборки и рабочее дерево. Staging имеет закрытый ACL,
но содержит незашифрованные дампы/настройки и удаляется в finally. Нужен
защищённый системный диск; после аварийного завершения удалите оставшийся
`stageRoot/set-*` только убедившись, что операция не выполняется.
Для PostgreSQL создаётся краткоживущий UTF-8 pgpass в закрытом каталоге
`%TEMP%/gm-dr-auth-*`: это сохраняет кириллицу/спецсимволы пароля на Windows
без передачи пароля в командной строке. Файл удаляется после каждой команды;
после аварийного завершения проверьте эти каталоги так же, как staging.
Пароли с переводом строки/NUL отклоняются, поскольку pgpass их не представляет.

Для разбросанных файлов составьте карту; пример элемента `extraFolders`:

```json
{"id":"music-archive","path":"D:\\MusicArchive"}
```

Добавьте все невоспроизводимые папки проекта: архив нот, свои документы,
скрипты вне репозитория, локальные настройки. Каждый указанный путь обязателен:
отсутствующий каталог останавливает копию. Ссылки/junction/reparse points
отклоняются, чтобы не уйти в другой диск или рекурсию. Проверьте Windows
переменные окружения User/Machine, служебные аккаунты и другие DPAPI-хранилища
без вывода секретов в отчёт: автоматический экспорт знает только перечисленные
в таблице форматы. Неизвестные секреты сохраните в менеджер паролей.
Копия программы, установленной вне проекта, обычно заменяется официальной
установкой; невоспроизводимый конфиг — в extraFolders.
После сверки выставьте `inventoryReviewed: true`. Эта отметка означает ваше
подтверждение полноты списка, а не автоматическое обнаружение всех файлов диска.

Создайте отдельный сильный мастер-пароль (не менее 16 символов, лучше случайный
из менеджера паролей) и сохраните **вне ноутбука**. Он нужен и для restic,
и для переносимого контейнера DPAPI-секретов. Не меняйте только пароль restic
через key-add без учёта контейнера старых копий: старый пароль всё ещё нужен
для их `secrets.enc.json`. Пароли не вводятся в аргументы команд/историю.

```powershell
pwsh -NoProfile -File .\scripts\recovery\Recovery.ps1 -Mode Init -ConfigPath $cfg
# Остановить PILOT Ctrl+C, DEV backend/Vite, Funnel; закрыть SQL-клиенты.
pwsh -NoProfile -File .\scripts\recovery\Recovery.ps1 -Mode Backup -ConfigPath $cfg
pwsh -NoProfile -File .\scripts\recovery\Recovery.ps1 -Mode Status -ConfigPath $cfg
pwsh -NoProfile -File .\scripts\recovery\Install-RecoveryShortcut.ps1 -ConfigPath $cfg
```

Backup использует общую блокировку pilot tooling, проверяет остановку приложений
и отсутствие других подключений к каждой БД. Сам процессы не останавливает.
Используйте тот же Windows-аккаунт, который создавал DPAPI-пароли.
Сохраните открытые файлы и не редактируйте рабочее дерево во время копирования.
`Init` нужен **только один раз**, никогда не нужен для восстановления существующих
копий. Ошибка сети, заполненное облако, неверный пароль, отсутствующий файл,
занятый порт или незавершённый update не дают успешного результата/новой квитанции.

## 2. Обычная работа

Раз в день после остановки приложений используйте новый ярлык
**«Сохранить и запустить Guitar Mentor»**. Он делает копию, проверяет структуру
облачного repository, фиксирует snapshot ID и только затем запускает пилот.
При ошибке окно остаётся открытым; запуск через этот ярлык не происходит.
Стандартный ярлык пилота остаётся доступным для диагностики.
Скрипт не является фоновым сервисом и не планирует сам ежедневные копии.
Если приложение работает непрерывно, выделите ежедневную паузу: пока её нет,
RPO ≤24 ч не обеспечивается. Пропущенный запуск ноутбука/задачи не становится
успешной копией автоматически. После важных изменений и перед релизом — ещё одна копия.

```powershell
# Просрочка более 26 часов даёт ненулевой код, как и отсутствие квитанции.
pwsh -NoProfile -File .\scripts\recovery\Recovery.ps1 -Mode Status -ConfigPath $cfg
# Раз в неделю: чтение всех сохранённых блоков из облака.
pwsh -NoProfile -File .\scripts\recovery\Recovery.ps1 -Mode Check -ConfigPath $cfg
# Раз в месяц и после изменения схемы хранения: повторить репетицию ниже.
```

Начальная политика: 14 ежедневных, 8 еженедельных, 3 ежемесячных состояния;
пока восстановление не проверено — ничего не удалять. Автоматического `forget`
или `prune` скрипты намеренно не делают. После успешной репетиции применяйте
retention отдельно через restic, сначала с `--dry-run`, с `--group-by tags`
и `--tag gm-dr-v1` (staging-path меняется между копиями), затем проверьте список.
Это удаляет исторические данные: отдельное осознанное действие владельца.
Рост repository контролируйте по квоте облака. Храните независимую отключаемую
копию repository на USB, если позже появится диск; облачный аккаунт с правом
удаления не является защитой от всех последствий компрометации ноутбука.

## 3. Репетиция без изменения PILOT

```powershell
pwsh -NoProfile -File .\scripts\recovery\Recovery.ps1 -Mode Snapshots -ConfigPath $cfg
pwsh -NoProfile -File .\scripts\recovery\Recovery.ps1 -Mode Restore -ConfigPath $cfg -Snapshot <ПОЛНЫЙ_ID> -Destination D:\RecoveryDrill\gm-01
pwsh -NoProfile -File .\scripts\recovery\Restore-Database.ps1 -RecoveryRoot D:\RecoveryDrill\gm-01 -Kind Pilot
pwsh -NoProfile -File .\scripts\recovery\Restore-Database.ps1 -RecoveryRoot D:\RecoveryDrill\gm-01 -Kind Dev
```

Потребуются мастер-пароль и пароль локального PostgreSQL-администратора.
По умолчанию `Purpose=Drill`: случайная новая БД и отдельная непривилегированная
роль `gm_dr_*`, никакого DROP, --clean, repair и подключения к PILOT на запись.
Скрипт проверяет все хеши, реально выполняет pg_restore, сверяет количество
строк каждой public-таблицы и историю Flyway; отчёт создаёт **рядом** с комплектом.
Изменять сам комплект нельзя: его файлы привязаны к хешам. Восстановление SQL
из дампа выполняйте только для своего доверенного repository.

Для полного приёмочного прогона используйте новую Windows VM/другой ПК с копией
инструментов и выполните следующий раздел, **не включайте Funnel**. На существующем
ноутбуке `Install-RecoveredHost` использовать нельзя: он откажется перезаписать
каталоги; для прогона приложения предпочтительна отдельная VM.
Доступ наружу/SMTP/внешние обработчики в VM заблокируйте до старта, чтобы копия
не отправляла старые задания/письма. Истёкшие диагностические файлы не восстанавливаются.

Запишите в отчёт: snapshot ID, время, версии инструментов, успешность restore,
вход/F5/историю/библиотеку, время до рабочего UI и все NOT_RUN. Удаляйте после
проверки **только созданную drill-БД/роль** и каталоги, указанные в отчёте;
автоматического удаления БД нет. Полные отчёты/дампы/секреты в публичную Issue не загружать.

## 4. Если SSD уже умер

Начальные условия: новый Windows с интернетом, доступ к GitHub и тому же облаку,
мастер-пароль, возможность войти в аккаунты и получить MFA. Секретов старой Windows
для расшифровки копии не требуется. Не делайте `Init` существующего repository.

1. Установите Git, PowerShell 7.4+, получите recovery-ветку/принятый main как в §1.
   Выполните `Install-RecoveryDependencies.ps1 -Install`; отдельно установите
   PostgreSQL 17 с новым админ-паролем (не надо угадывать старый postgres password).
2. Через `rclone config` снова подключите **тот же аккаунт и путь** облака.
   Создайте личный config из example. Для Restore старые пути pilot/dev не нужны,
   но `rcloneConfig` должен указывать на новый действующий файл. Возьмите точный ID
   через `Snapshots`, затем `Restore` в новый каталог, например `D:\Recovered\gm`.
3. Восстановите БД и рабочие файлы следующими командами. На новой машине целевые
   роли/БД/каталоги должны отсутствовать. При совпадении существующих имён скрипт
   остановится; не удаляйте их наугад.

```powershell
pwsh -NoProfile -File .\scripts\recovery\Restore-Database.ps1 -RecoveryRoot D:\Recovered\gm -Kind Pilot -Purpose Recover
pwsh -NoProfile -File .\scripts\recovery\Restore-Database.ps1 -RecoveryRoot D:\Recovered\gm -Kind Dev -Purpose Recover
pwsh -NoProfile -File .\scripts\recovery\Install-RecoveredHost.ps1 -RecoveryRoot D:\Recovered\gm
pwsh -NoProfile -File .\scripts\recovery\Restore-ExtraFolders.ps1 -RecoveryRoot D:\Recovered\gm
```

`Install-RecoveredHost` проверяет восстановленную pilot-БД до установки файлов,
восстанавливает git bundle/локальные файлы, повторно шифрует секреты через DPAPI
для **нового** пользователя Windows, ставит ярлыки. При установке Caddy/Tailscale
через winget пути могут отличаться: передайте `-CaddyPath (Get-Command caddy.exe).Source`
и `-TailscalePath (Get-Command tailscale.exe).Source`. Если filesEnabled=true,
нужен ffprobe в новом PATH. Другие диски допустимы через `-PilotRoot/-SourceRoot`,
но пользовательские абсолютные пути в `.env`/YAML/extraFolders проверьте вручную.
DEV-библиотека по умолчанию возвращается в `backend/.local-media/library`;
если ваш DEV использовал другой путь, верните её туда и настройте env.
Каталог секретов пилота фиксирован `%LOCALAPPDATA%\GuitarMentorAI`.

`Restore-ExtraFolders` возвращает дополнительные папки по путям из config;
существующие каталоги не перезаписывает. При другой структуре дисков передайте
`-DestinationRoot D:\RestoredExtras`: данные появятся в `<DestinationRoot>/<id>`.
Настройте путь к rclone и личный recovery config на новом хосте; заново создайте
ярлык резервирования из принятой проверенной копии recovery tooling. Доступы,
не поддерживаемые автоматическим экспортом, возьмите из менеджера паролей.

Сначала локальный smoke **без публикации** (в PowerShell 7):

```powershell
cd D:\Development\guitar-mentor-recovery
. .\scripts\pilot\Pilot.Common.ps1
$root = 'D:\GuitarMentorPilot'
$config = Read-PilotJson (Join-Path $root 'pilot-tools.json')
$state = Read-PilotJson (Join-Path $root 'release-state.json')
# Проверяет HTML/JS/API и останавливает процессы после smoke. Funnel не включает.
Invoke-PilotRuntime $root $state.current $config
```

После снятия блокировки внешних отправок в VM/на новом хосте отдельно проверьте
вход, свою историю и скачивание PDF. Для DEV: `npm ci` в frontend, новый локальный
hosts `127.0.0.1 guitar-mentor-dev`, Caddy config из `infra/local/Caddyfile`,
`caddy trust`, запуск `scripts/local-auth-unified.ps1`. На новой машине корневой
сертификат Caddy создаётся и доверяется заново; старый приватный CA не переносим.
Не запускайте старый dev launcher с неизвестным Caddy-путём: он ожидает
`C:\Tools\Caddy\caddy.exe`, либо запустите Caddy отдельно по инструкции.

Tailscale: войдите в свой tailnet, проверьте имя **нового** узла и настройки
Serve/Funnel. Старые ключи узла не копируются. Прежний `guitar-mentor.tail3b8201.ts.net`
может потребовать освобождения/возврата имени в консоли tailnet. Если hostname
изменился, обновите `origin` и точный redirect URI в Google Cloud; не отключайте
проверку URI. `guitar-mentor.ru` этим восстановлением не перенастраивается.
Публичный запуск выполняйте обычным ярлыком только после локальной проверки.
Проверьте с мобильной сети вход/F5/PDF/тюнер/метроном и сохранность двух аккаунтов.
Сделайте новую внешнюю копию. Обновлять приложение до latest main для
восстановления не требуется: сначала запускается сохранённая текущая версия.

При несовместимой схеме старый JAR на новую БД не запускайте. JAR, dump и library
берутся из **одного** snapshot. `pending-update.json` блокирует создание обычной
копии: сначала разбор незавершённого релиза по инструкции пилота. Восстановление
на существующем хосте с откатом новых пользовательских данных в этот сценарий
не входит; это отдельное решение с сохранением текущих данных.

## Экстренная памятка вне ноутбука

В менеджере паролей, доступном с телефона/нового ПК, храните запись «Guitar Mentor — восстановление»:

- URL репозитория и этой инструкции, принятую ветку/commit recovery tooling;
- аккаунт и путь облака (`rclone:gm-backup:guitar-mentor-ai/restic`), мастер-пароль;
- последний проверенный snapshot ID и дату полной репетиции;
- доступ к почте/облаку/GitHub/Tailscale/Google Cloud/SMTP/регистратору и MFA recovery;
- карту дополнительных каталогов и секреты вне поддерживаемых DPAPI-файлов.

Эта запись не должна зависеть от браузерного профиля единственного ноутбука.
Копия в облаке вместе с недоступным MFA/забытым паролем не поможет восстановиться.
Сам мастер-пароль и recovery-коды не помещайте в GitHub или эту документацию.
