### Смысл и результат

Прямое требование владельца: удобный пользовательский сценарий, минимум лишних переходов и действий, спокойный и привлекательный интерфейс, группировка связанных возможностей и ориентир на признанные подходы крупных компаний.

В ответ была предложена проработка пути «открытие приложения → занятие → запись → проверка → результат → следующее действие», одного рабочего пространства и постепенного раскрытия подробностей. Apple HIG, Material Design и Fluent конкретизируют ориентиры в предложении ассистента; пользователь не задавал эти три системы поимённо.

Создана [Issue #51 — UX-01](https://github.com/roafo1989/guitar-mentor-ai/issues/51). На момент чтения Issue открыта, комментариев нет. В теле указаны «Анализ / В очереди», тип «Фронтенд», отсутствие оценки и приоритета. Это сведения тела Issue; фактическое состояние полей Project не подтверждено.

Результат UX-01 — аудит, текущий и целевой пути, прототипы, правила UI и перечень изменений. Реализация и согласование прототипа не считаются выполненными из-за создания задачи. Подробные предложения не заменяют приёмку владельцем.

### Снимок описания Issue #51 на момент переноса

## Цель

Сделать Guitar Mentor AI удобным для регулярных коротких занятий: понятный следующий шаг, минимум лишних переходов и действий, лаконичный и привлекательный интерфейс без визуального шума («ёлочной гирлянды»).

**Запрос владельца от 18.10.2026:** продумать пользовательский сценарий, обеспечить инкапсулированность связанных возможностей и ориентироваться на признанные дизайн-системы крупных компаний.

**Бэклог:** Анализ / В очереди. **Тип:** Фронтенд. Трудоёмкость и приоритет пока не определены; оценка — по отдельной команде «оцени задачи», начало разработки — после совместного выбора.

## Объём задачи

1. Провести UX-аудит текущего приложения: главная, профиль/onboarding, диагностика, каталог/назначение, занятие, запись, результат и продолжение обучения. Отделить уже работающие функции от проектируемых.
2. Описать текущий и целевой путь нового и возвращающегося ученика. Для частых сценариев посчитать переходы между экранами и обязательные действия, выявить повторный ввод, дублирование и потерю контекста.
3. Подготовить прототип главной и единого рабочего пространства занятия с ключевыми состояниями, включая мобильный экран.
4. Зафиксировать небольшой набор общих UI/UX-правил: навигация, иерархия действий, группировка, раскрытие деталей, цвета, типографика, отступы, компоненты и тексты.
5. Подготовить приоритизированный перечень изменений с границами существующих и новых задач. Согласовать прототип с владельцем перед реализацией.

## Целевой сценарий для проработки

- **Главная → продолжить занятие.** Возвращающийся ученик видит текущее задание и понятное главное действие; для нового ученика предусмотрен понятный старт.
- **Занятие в одном рабочем пространстве.** Цель, инструкция, материалы, плеер/метроном, запись и результат доступны в контексте задания. Не требуется искать продолжение одной операции в разных разделах.
- **Записать или выбрать файл → прослушать/при необходимости заменить → отправить на проверку.** Отправка остаётся отдельным осознанным действием.
- **Обработка → обратная связь в контексте той же попытки.** Состояния обновляются автоматически без ручного обновления страницы; сначала краткий вывод и следующие действия, затем подробности по запросу.
- **Доработать и пересдать либо завершить по решению ученика и продолжить.** Рекомендация агента и решение ученика различаются; замечания, история проверок и причины сохраняются. Самостоятельное завершение не подтверждает навык автоматически.

Это целевой UX: задача не утверждает, что перечисленные возможности уже реализованы.

## Правила интерфейса

- Одно визуально главное действие в текущем контексте; второстепенные действия имеют меньший вес.
- Инкапсулированность: информация, состояние, ошибки и действия одного объекта собраны рядом, имеют понятные границы и не требуют переходов для завершения простой операции.
- Основное видно сразу; расширенные настройки, подробные критерии и история раскрываются по запросу. Частые действия остаются обнаружимыми.
- PDF с нотами/TAB по умолчанию свёрнут и раскрывается по запросу — сохранить ранее согласованное правило.
- Спокойная палитра с основным акцентом; цвет статуса сопровождается понятным текстом. Без конкурирующих баннеров, декоративных бейджей, лишних рамок и повторяющихся панелей.
- Единые компоненты, названия действий, типографика и отступы; аккуратный адаптивный интерфейс.
- Сохранить закреплённый header, возврат на главную по логотипу и отображение имени ученика.
- Предусмотреть пустое состояние, загрузку, обработку, успех, ошибку и повтор; сохранять введённые данные и контекст при восстановимых ошибках.
- Учитывать клавиатурную навигацию, видимый фокус, читаемость и понятные подписи.
- Не сокращать число кликов ценой скрытия важных действий или потери понятности.

## Критерии приёмки

- [ ] Описаны текущий и целевой сценарии первого входа/настройки, возобновления занятия, выбора задания, отправки попытки, просмотра результата, пересдачи и самостоятельного завершения.
- [ ] Для каждого частого сценария есть сравнение количества переходов и обязательных действий до/после; сохранённые дополнительные шаги обоснованы.
- [ ] Прототип показывает главную, рабочее пространство занятия и основные состояния, включая ошибку/повтор, на компьютере и телефоне.
- [ ] На каждом состоянии ясно, где находится ученик, что происходит и какое действие доступно дальше.
- [ ] Правила лаконичного оформления и раскрытия деталей зафиксированы; сохранены PDF по запросу и право ученика продолжить с замечаниями.
- [ ] Владелец прошёл целевой сценарий по прототипу; замечания и результат согласования сохранены.
- [ ] Подготовлен список изменений с приоритетами и привязкой к существующим задачам; повторная оценка уже учтённой работы исключена.

### Смысл и результат

Два прямых требования: базовая домашняя страница и возврат на неё по логотипу.

По найденному ответу ассистента и [PR #48](https://github.com/roafo1989/guitar-mentor-ai/pull/48) результат включает:
- самостоятельную главную на корневом адресе вместо перенаправления в профиль;
- краткое приветствие, главное действие и три карточки: «Профиль», «Опыт и цели», «Диагностика»;
- приветствие по имени сохранённого ученика;
- переход по логотипу на главную и к началу страницы;
- сохранение цветов проекта, закреплённого header и имени ученика;
- RU/EN, адаптивную вёрстку, обработку ошибки восстановления профиля с повтором запроса и сброс локального выбора при удалённом профиле.

Эти детали описывают выбранную реализацию. Не все они были отдельными исходными требованиями пользователя.

### Снимок описания PR #48 на момент переноса

Корневой адрес `/` теперь открывает самостоятельную домашнюю страницу вместо перенаправления в профиль. На ней — короткое приветствие, основная кнопка и карточки профиля, опыта и целей, диагностики. Сохранённый ученик видит приветствие по имени; логотип в хедере возвращает на главную и к началу страницы.

Добавлены тексты RU/EN, адаптивная вёрстка и обработка ошибки восстановления профиля с повтором запроса. Удалённый профиль сбрасывает локальный выбор. Существующий sticky header и имя ученика сохранены. Поведение описано в frontend/README.md.

Проверка:
- `npm ci`, `npm run build` (Vue/TypeScript + Vite), `git diff --check` — успешно.
- Chromium/Playwright: все три раздела и возврат по логотипу, RU/EN, отсутствие горизонтального переполнения на ширинах 320/390/768/1024/1440 px, восстановление ученика, ошибка сети и повтор, 404 и неизвестный адрес. Ошибок JavaScript нет.
- Для браузерных сценариев ответы API подменялись; backend не изменён.
