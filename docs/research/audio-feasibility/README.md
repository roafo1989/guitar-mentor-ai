## Privacy and scope
This directory contains **public documentation and synthetic structural examples only**. Never commit real recordings, performer identifiers, original filenames, consent documents, annotated real takes, absolute paths, or product-storage exports. Private corpus root must be **outside the Git checkout**. This experiment does not access the running application, PostgreSQL, the upload worker, or any S3 service. The product TTL remains unchanged.

No recordings have yet been verified or manually annotated. Accordingly the present package is **INCOMPLETE**, not READY_FOR_POC. No accuracy figures or valid musical-analysis model are claimed. Source rights and actual audible labels require human verification; a schema validator cannot certify these.

## Readiness
At least **two distinct real takes** are required for each REAL-BASS, REAL-TIMING and REAL-POLY (minimum six total), each with manually reviewed observations and permission for the intended scope. Preserve original hashes; split derivatives together. Assign independent CALIBRATION and HOLDOUT recording groups before algorithm fitting, ideally one of each REAL group in each partition. Without independent holdout, report NO_INDEPENDENT_HOLDOUT; never claim out-of-sample precision.

Private source deletion or consent withdrawal invalidates the affected dataset version. No recovery from expired product media is allowed.

## Rollback
Stop the offline experiment, reject the dataset version, remove only output generated by the experiment with owner's approval, and return to an earlier approved contract revision. Never overwrite source takes or regenerate withdrawn media.

## Running the validator (Java 21)
From the repository root, run `mvn -f backend/pom.xml -Dtest=AudioCorpusValidatorTest test` to run isolated validator tests. This invocation requires Maven, a working dependency cache/repository, and JDK 21.

Build the test-independent classes with `mvn -f backend/pom.xml -DskipTests package`. The validator is a plain Java main class (`ai.guitarmentor.research.AudioCorpusValidator`), not a REST endpoint or Spring worker. Use an IDE run configuration with the backend's Maven classpath and the following arguments:

```text
--root /private/offline/corpus --manifest manifest.json --report /private/offline/results/run-001.json --offline
```

The root, report directory and example absolute paths above are **illustrations**, not actual existing directories or user media. The output path must be outside the corpus root and must not already exist. Exit status 0 means READY_FOR_POC, 2 means INVALID/INCOMPLETE, 3 means environmental or command-line failure. The console prints only status or a generic error code. The report contains status, abstract issue codes and pseudonymous IDs; protect it as a local research artifact.

Current implementation performs a structural and SHA-256 check, not an ffprobe media-header inspection or authoritative verification of licenses, note-event correspondence, or audible content. Do not interpret READY_FOR_POC as musical validity until those controls have been independently performed and documented. Runtime build and automated tests have **not** been executed in this environment.
