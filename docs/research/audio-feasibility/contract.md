# Benchmark contract v1

All JSON is UTF-8; unknown or invalid enum values are rejected. Identifiers are opaque, non-identifying ASCII tokens; no actual names or original filenames. UTC timestamps are ISO-8601. SHA-256 hashes are lowercase 64-digit hex. The authoritative specification is [#14 original analysis v1.0](https://github.com/roafo1989/guitar-mentor-ai/blob/analysis/system-analysis-standard/docs/specifications/MVP-R2-01-audio-feasibility.md); the owner-approved [technical/REAL split](scope-decision-2026-10-20.md) governs acceptance of this PR.

## Dataset manifest
`schemaVersion: 1`, `datasetId`, immutable `datasetVersion`, `createdAt`, `sourceCommit`, `recordings[]`. Each recording:
- `recordingId` unique; `kind`: REAL | SYNTHETIC | QUALITY; `group`: REAL-BASS | REAL-TIMING | REAL-POLY | SYNTHETIC-CONTROL | QUALITY-CONTROL.
- `recordingGroupId`, `performerId`, `sessionId`, `deviceId`: pseudonyms for REAL. Derivative files and edits share `recordingGroupId`.
- `fileRef` relative to explicit offline root; `sourceSha256`, `bytes`, `durationMs`, `sampleRateHz`, `channels` describe actual bytes, not declared file extensions.
- `referenceId`, `referenceVersion`, `referenceSha256`, `barFrom`, `barTo` identify an immutable score/reference; `annotationRef`, `annotationVersion`, `annotationSha256` identify manual observation for ready records.
- `rightsBasis`: OWNED | LICENSED | EXPLICIT_PERMISSION; `consentRef` is an opaque local consent record ID (not a URL); `useScope`: LOCAL_RESEARCH | EXTERNAL_APPROVED; no inference of publication permission.
- `split`: CALIBRATION | HOLDOUT | DIAGNOSTIC_ONLY; `availability`: AVAILABLE | MISSING | WITHDRAWN; `transform` required for SYNTHETIC and converted derivatives (source reference/hash, operation, parameters, seed where relevant, tool version).

## Reference
`referenceId`, `referenceVersion`, `origin`, `rights`, `instrument`, `tuning`, `meterNumerator`, `meterDenominator`, `bpm`, `barCount`, `events[]`. Event: `eventId` unique, `bar` 1-based, `beat` 0-based, `durationBeats` > 0, `voice` BASS | UPPER | MIXED and `notes[]`. A simultaneous chord is **one attack** with multiple notes; no artificial retrigger from string decay. Every event requires a `voice` enum, `bar` inside the reference, `0 <= beat < meterNumerator`, finite positive duration and a nonempty array of spelled pitch strings (`A-G`, optional `#`/`b`, octave `-1` through `8`, e.g. `G2`, `F#3`). Tuning is likewise a nonempty pitch array; `origin`, `rights`, `instrument`, `meterNumerator` and a power-of-two `meterDenominator` are mandatory.

A notated event at bar b and beat q has ideal time `((b-1)*meterNumerator + q)*60000/bpm` ms for a quarter-note beat in 4/4. This is **not** a manually observed recording timestamp. Explicit pickup, count-in, rests, and initial silence are described separately.

## Annotation
`annotationId`, `annotationVersion`, `recordingId`, `sourceSha256`, `annotatorId`, nullable `reviewedBy`, `observations[]`. Observation: `eventId` (nullable only for EXTRA), `onsetMs`, `fromMs`, `toMs`, `voice` BASS | UPPER | MIXED | UNKNOWN, `label` MATCH | OMISSION | EXTRA | WRONG_BASS | PAUSE | TEMPO_CHANGE | AMBIGUOUS, `actualNotes` (or UNKNOWN where pitch cannot be established), optional interval `endMs` for pause/tempo change. `0 <= fromMs <= onsetMs <= toMs <= durationMs`; all timestamps are integer milliseconds. Every observation requires a `voice` enum and `actualNotes`, either an array of valid pitch strings or the literal `UNKNOWN`. `MATCH`, `WRONG_BASS` and `EXTRA` require known pitch-array evidence. `PAUSE`/`TEMPO_CHANGE` additionally require integer `endMs` with `fromMs < endMs <= durationMs` and `endMs >= toMs`; other labels may omit `endMs`, but if present it must be bounded and not precede `toMs`. `AMBIGUOUS` with `actualNotes=UNKNOWN` is legitimate and must not be counted as a confirmed pitch.

A notated rest is not a PAUSE. An intended mistake is not a measured mistake until listening confirms it. UNKNOWN and AMBIGUOUS remain explicit instead of inventing a pitch.

## Security rules
Reject URI/scheme strings, absolute paths (POSIX, Windows, UNC), any `..` segment, symbolic links (including parent components), paths outside the root, hash mismatch, duplicate IDs, dangling event references and annotation timestamps outside duration. Check source bytes before and after processing. Do not follow arbitrary remote content. Limit media to 20 MiB and 120 seconds; ffprobe metadata alone does not prove a note is correct. Accepted benchmark inputs use the **existing product allow-list**: WAV (PCM), MP3 (MP3), OGG (Opus/Vorbis), WebM (Opus/Vorbis); both filename extension and ffprobe-detected container/codec must agree. Owner-supplied **original M4A/AAC files are retained only as private provenance**; convert to an approved WAV derivative, preserve the original checksum and transform record, and feed only the derivative to the validator. Do not silently expand product format support. Paths must have no symlink ancestors of the root or symlink components below it; audio hashes are checked again after ffprobe and JSON file hashes after read. Owner must prevent concurrent writes: simple path checks/re-hashing reduce but **cannot eliminate** hostile filesystem TOCTOU races.

## Readiness status
`INVALID`: unsafe reference, malformed schema, damaged/hash-mismatched source, inconsistent event/time fields. `INCOMPLETE`: missing/withdrawn source, absent/unconfirmed rights or annotations, insufficient independent REAL coverage. `READY_FOR_POC`: all structural checks and manual attestation flags exist, six+ independent REAL takes are present, and independent CALIBRATION/HOLDOUT coverage holds. This means **ready to measure**, not “accurate”.

## Explicit manual attestation (validator contract)
A real annotation JSON must set `manualConfirmed: true` only after a human has actually listened to the take and reviewed the observations. This is a **declaration**, not evidence that automated tools can authenticate. Test fixtures may set the flag solely to exercise code paths and must never be relabeled as genuine REAL recordings. Only CALIBRATION or HOLDOUT recordings count toward independent coverage; DIAGNOSTIC_ONLY remains excluded.

## Independent holdout declaration
For a REAL entry assigned to HOLDOUT, `holdoutIndependentConfirmed: true` is a required human assertion that the performance is a distinct take, not a conversion or excerpt from CALIBRATION. The validator checks file hashes and group IDs, but cannot prove that two different audio files are from different physical performances. Missing attestation produces INCOMPLETE; an assertion alone never proves independence. The generated integration harness uses a test-only declaration and must not be treated as human evidence.
