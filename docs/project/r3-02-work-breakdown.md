- Исходный остаток **60 ч (48–80 ч)**, оценённый 19.10.2026; после декомпозиции **бюджет перенесён** в 14 новых задач, не прибавлен к ним. #17 не является ещё одной активной задачей и для агрегирования новых работ имеет **0 ч**. Исторические 24 ч/60 ч внутри #17 остаются доказательством предыдущих оценок и не суммируются с текущими.
- В Project новые Issues нужно привязать к стори #56 и установить `Уровень = Задача`, `Этап = Бэклог`, `Status = В очереди`, `Оценка, ч` из таблицы, специализацию и профиль; **сам GitHub-коннектор не умеет записать Project v2 или native sub-issues**. Текстовые ссылки/метки в Issues уже существуют, но это не доказательство Project-связей.
- Целевой размер каждого независимого задания **3–6 ч**. Новый code/permalink не подменяет уже назначенный GM-EB01; PDF/MP3 по-прежнему отдельные учебные ресурсы, не хранение пользовательских попыток.
- Новые задачи находятся в бэклоге до прямого выбора владельцем; текущие активные #14/#21 не переводятся и не меняются. Состояние `Оценка / Выполнено` было достигнуто при расчёте общего остатка и сохраняется как **результат оценки**, а не как текущая колонка неактивного бэклога.

1. Независимые работы: #76 (аудит GM-EB01), #77–#80 (четыре композиции), #86 (метроном engine). Музыкальное одобрение не заменять зелёным CI.

5. Каждый дочерний Issue живёт по общему процессу: разработка → код-ревью → тестирование → приёмка; никакой автоматической «выполнено» на основании зависимости/PR без решения владельца.

## Границы и ограничения

Уже реализовано и не считается заново: GM-EB01 как первоначальный **не финально верифицированный** прототип, V5/V6, Java REST каталога и назначения, текущий PDF/MP3 preview в Vue (#36/#49). Вне FT-002-03 остаются #16 (правила подбора), #68 (собственные примеры и ноты), #18/#19 (оценка/продвижение), #20/#30/#21 (user media storage/TTL) и аудио-PoC #14/#15.

**Риск версий:** `diagnostic_tasks.exercise_id` хранит конкретную версию, а `/exercises/{code}/...` выбирает текущую — выпуск GM-EB02–05 с новыми кодами безопаснее обновления GM-EB01. Отдельное переиздание требует отдельного решения про version-aware контракты.

**Статус:** план/оценка зафиксированы; ни одна новая задача ещё не реализована и не протестирована. Спецификация и этот реестр в открытом PR #74, не в main до merge. Изменения исходных FT ссылок внутри PR #64 должны быть синхронизированы с новыми Issues перед окончательным merge ТЗ.
