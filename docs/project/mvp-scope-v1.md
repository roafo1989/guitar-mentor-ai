## 1. Цель, аудитория и форма выпуска

Проверить на **личном локальном стенде**, что Guitar Mentor AI помогает ученику акустической гитары организовать занятия мелодическим fingerstyle: подобрать упражнение из каталога, исполнить, получить честную оценку по доступным критериям, понять замечания, сохранить историю и получить следующую рекомендацию.

- Интерфейс M1: **адаптивное веб-приложение Vue** + **единый Spring Boot backend** + PostgreSQL.
- Первоначальный пользователь: **один локальный ученик** (в пилоте — владелец проекта). Модель может различать несколько Learner и InstrumentProfile, но это **не равно готовой авторизации**.
- Основной сценарий: мелодический fingerstyle на акустической гитаре, без обязательной перкуссии, медиатора, когтя / thumbpick.
- Telegram / Telegram Mini App — отдельный M2 **после** web MVP, оценка +5–8 рабочих дней, не включать в M1.
- Сеть: до реализации аутентификации, авторизации и проверки изоляции пользователей — **только loopback / 127.0.0.1**, без публичного развёртывания, туннелей и доступа других учеников по UUID.

## 2. Входит / не входит в M1

| Входит (обязательно) | Не входит |
| --- | --- |
| Профиль, техника, музыкальные стили LIKE/NEUTRAL/EXCLUDE | Массовая регистрация, teacher/admin кабинет, платные занятия |
| Onboarding: самооценка, техника, репертуар, цели, регулярность | Считать самооценку подтверждённым уровнем |
| Явная карта навыков, цели и условия перехода | Неограниченная генерация собственных невалидированных упражнений |
| ≥5 коротких авторских/разрешённых упражнений; табулатуры или подготовленное представление | Нелицензированное копирование песен и коммерческих партитур |
| Программа из реальных упражнений, страница задания, темп/метр | Универсальная транскрипция полифонии, уверенная проверка всех нот |
| Повторные попытки, аудиозапись или загрузка, статусы обработки | Видеоанализ кистей, положения пальцев и посадки |
| Проверка по **подтверждённым PoC** параметрам + осторожная LLM-обратная связь | Неверифицированные категоричные суждения об услышанной игре |
| Явное решение ученика, отдельные факты о результатах навыка | Вето ИИ на самостоятельный переход ученика |
| История оценок, незакрытые пробелы, следующий рекомендованный урок | Telegram в рамках M1 |
| TTL очистки исходных файлов, тесты, локальный запуск | Публичное многоарендное развертывание, облачная инфраструктура |

## 3. Участники, полномочия и данные

| Участник | Что делает | Граница ответственности |
| --- | --- | --- |
| Ученик | Выбирает цели и упражнения, записывает попытки, решает повторить/завершить | Может завершить по собственному решению, но **не выдаёт себе подтверждённый навык** |
| Детерминированная Java-доменная логика | Сохраняет сущности, правила переходов, результаты, проверяет связи | Единственный источник фактического состояния и бизнес-правил |
| Аудио-анализатор | Возвращает измерения и оценку их достоверности | Не заявляет проверки критериев, проваливших PoC |
| ИИ-наставник / LLM | Даёт объяснение, советы, рекомендует следующее упражнение | Не подменяет измерения, не создаёт сам право на переход/«сдал» |

**Концептуальная карта данных** (имена и связи уточнятся в R3/R4; не требование создать все таблицы прямо сейчас):

`Learner` → `InstrumentProfile` → `MusicPreference` + `LearnerBackground` → `LearningGoal` → `Skill` → `Exercise` (+ Skills/Criterion/Reference) → `LessonAssignment` → `Attempt` → `MediaAsset` (временный) → `Assessment` + `CriterionFinding` → `LearnerDecision` → `SkillEvidence` → `NextExerciseRecommendation`.

Обязательное разграничение:

- `selfReportedExperience` / `selfReportedSkills` — анкета ученика, **не** подтверждение освоения.
- `assessmentStatus` или `agentVerdict`: например `PASS`, `REVISE`, `UNCERTAIN` — заключение системы, не решение ученика.
- `learnerDecision`: например `RETRY`, `COMPLETE`, `MOVE_ON`, c причиной/временем (точный API-контракт утвердить в R4).
- `verifiedSkillEvidence`: основания для объективного подтверждения навыка; **не** создаётся автоматически при `MOVE_ON`.
- Исторические Attempt/Assessment/Decision не перезаписываются новым результатом; отдельные будущие миграции Flyway.

## 4. Два входных пути

### Путь N — новичок
1. Создаёт профиль и выбирает fingerstyle.
2. В UC-03 указывает `NONE`, 0 лет, пустые освоенные техники и репертуар, цели и доступное время.
3. Система не записывает `NONE` как отрицательную объективную диагностику; выдаёт простое базовое упражнение.
4. Выполняет его, может записать попытку и увидеть, что именно удалось/не удалось оценить.

### Путь E — ученик с опытом
1. Выбирает техники, жанры (включая `EXCLUDE`), ранее сыгранные композиции и цели.
2. Анкета может подсказать стартовый уровень упражнений, но **не аттестует** способность играть конкретный приём.
3. Выбирает задание с независимостью баса, темпом и мелодией.
4. История текущих попыток и диагностических результатов постепенно становится основным сигналом персонализации.

## 5. Сквозной демонстрационный сценарий (E2E-MVP-01)

**Демонстрационный материал:** короткий **авторский** этюд fingerstyle (предварительный дизайн: 8 тактов, 4/4, чередующийся бас + короткая мелодия, ориентир 60–80 BPM). **Точный темп, табулатура и исполнимость — результат R3; реалистичность метрик — результат R2**, эти параметры пока не гарантированы.

1. Ученик сохраняет профиль и onboarding и видит предложенный этюд.
2. Открывает этюд; видит его ноты/табулатуру, цель, опорный темп, условия попытки.
3. Нажимает «Записать» или загружает заранее записанный файл; получает номер попытки и статус.
4. Анализ обрабатывает запись; **метрики выводятся лишь для прошедших R2 проверок**. Если бас или ноты достоверно не определяются, UI это прямо показывает. LLM не вправе «услышать» не измеренное.
5. На первой записи обнаруживается воспроизводимая проблема, которую испытательный эталон способен показать; выдаются 1–3 конкретных совета, статусы критериев и рекомендация повторить.
6. Ученик выбирает «Завершить и продолжить» несмотря на `REVISE`, при необходимости записывает причину («результат меня устраивает»).
7. В истории остаются замечания и вердикт ИИ, а также решение ученика. Навык, связанный с **несданным критерием**, не отмечается подтверждённым.
8. Следующее упражнение учитывает цели и этот незакрытый пробел; после истечения TTL бинарная запись удаляется, но оценки и история сохраняются.
9. Проверяется другая попытка с `PASS` или `UNCERTAIN`; интерфейс и история различают все случаи.

### Базовые категории доказательств

- Система может уверенно утверждать только то, что подтвердили PoC и тестовый набор R2 (#14, #15).
- Каждый аудио-критерий получает решение `GO` / `LIMITED` / `NO-GO`. При `LIMITED` фиксируются условия применимости; `NO-GO` **отключает** автоматический вывод.
- Точность измерения проверяется относительно помеченных человеком эталонов, с учётом ошибок и ложных уверенных решений. Пороговые значения не выдумываем заранее: фиксируем их в результатах PoC до включения критерия.

## 6. Границы двух контрольных точек

### M0 — рабочий учебный прототип, 18–25 рабочих дней (ориентир)

- [ ] Профиль / onboarding создаётся и восстанавливается.
- [ ] ≥2–3 этюда доступны в интерфейсе; показаны цель и критерии.
- [ ] Уроки, попытки, ручные/демонстрационные оценки и история сохраняются.
- [ ] Состояния «повторить» и «завершить несмотря на замечания» работают; навык не подтверждается из-за простого перехода.
- [ ] UI честно сообщает, когда автоматический аудиоанализ ещё не реализован.
- [ ] Пройден локальный короткий сценарий без публичного доступа.

### M1 — функциональный web MVP, 42–69 рабочих дней (предварительно)

- [ ] Всё M0.
- [ ] Загрузка/запись аудио, очередь/статус обработки и безопасный фолбэк.
- [ ] Автоматические измерения только в подтверждённых условиях; понятная, проверяемая LLM-обратная связь.
- [ ] Новая рекомендация учитывает историю, предпочтения, цели и незакрытые ошибки.
- [ ] Медиа из отдельного временного хранилища удаляется по политике: обработанные — **через 24 ч после завершения всех проверок**; необработанные — **максимум через 48 ч после загрузки**. Параметры в PostgreSQL, изменяются SQL без перезапуска.
- [ ] Все Attempt/Assessment/Decision и метаданные остаются после очистки.
- [ ] CI и интеграционные тесты зелёные; пилот с фактической игрой на гитаре пройден; все критические ошибки закрыты; локальный запуск/восстановление документирован.
- [ ] Ограничения и неточные критерии перечислены; нет утверждений о невозможной точности полифонического распознавания.

**Выполненный M0 — не доказательство выполненного M1**, как и зелёный CI не заменяет пользовательскую проверку.

## 7. Риски / условия пересмотра

1. **Достоверность аудио (критический путь):** R2 стартует рано. Неуспех PoC означает ограничение автоматической оценки, новую оценку R6 и явную фиксацию изменившегося объёма M1.
2. **Лицензии на музыкальный материал:** в первую версию помещаем собственные короткие этюды или контент с подходящей лицензией.
3. **Приватность:** аудио в отдельном временном хранилище; не логировать медиа/секреты. Отправку исходного аудио третьему лицу согласовываем отдельно; в LLM по умолчанию передаём только разрешённые метаданные и подтверждённые измерения.
4. **Браузеры:** проверять `MediaRecorder` / микрофон; иметь резервную загрузку файла.
5. **Безопасность:** без настоящей авторизации ни один Learner UUID не даёт права публичного доступа. Продакшен и многопользовательский режим — отдельные работы.
6. **Стоимость:** минимум инфраструктуры, лимиты AI API, чистка файлов, прозрачный учёт затрат.
