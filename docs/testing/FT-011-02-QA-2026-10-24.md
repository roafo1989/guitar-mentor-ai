## Assumptions, limitations and operator safety

- All content tests use synthetic PDF/GP bytes. Accepting GP is **opaque storage**, not a claim that a GP editor can open every file.
- CI's OIDC principal is synthetic; external Google/SMTP, user browsers and remote live deployment were not exercised.
- The feature is disabled by default; enabling requires an adequately protected local filesystem root, stable random cursor HMAC secret of at least 32 bytes, suitable disk backup strategy and active authentication. Never point the root inside attempt/score cleanup roots or a web-served directory.
- The upload path does not implement user deletion; that is #162. Vue upload/list/download UI is #163 and integrated acceptance #164.
- File storage and PostgreSQL are distinct persistence domains; durable manifests and stale-operation reconciliation mitigate interrupted requests. They are **not** a substitute for an actual backup/recovery drill against power loss or filesystem corruption.
- Code review in this iteration is the author's structured review, not independent human sign-off. The owner must not interpret green CI as human security certification.

## Owner acceptance script (backend contribution)

1. On an isolated test environment with library enabled and current authentication, upload one own synthetic PDF and one Guitar Pro original, retaining the local originals.
2. Verify the new private card has two files; download both and compare SHA-256 / byte sizes with the originals.
3. Retry the **same request and Idempotency-Key**; expect the existing material (HTTP 200), not a new card or quota charge. A different payload with that key must be rejected.
4. Check HEAD: no body, correct length, attachment/no-store/nosniff. Check anonymous and second-account requests: deny access, foreign resource 404.
5. Confirm POST without a CSRF token fails, with the token succeeds; rejected extensions/invalid PDF/oversize do not create READY materials.
6. Verify a restart leaves the committed private originals intact. Full browser library UX should be accepted once #163/#164 are complete.
