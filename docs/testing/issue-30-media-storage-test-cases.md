## 3. Среда, данные и запуск

**Ручная проверка:** Windows 10, Chrome, PostgreSQL 17, Java 21, Node.js 22+, Vue/Vite, Caddy с доверенным HTTPS, ffprobe по [DEV-07](https://github.com/roafo1989/guitar-mentor-ai/blob/07cc33b99e9cc6fdbf0c9cc7dae28c1a1fab87ac/docs/development/dev-07-local-audio-submission.md). Адрес: `https://guitar-mentor/diagnostics`.

Перед обновлением зафиксировать старые ID/номера/комментарии/статусы, версию и используемые настройки БД/storage. Не считать обязательным наличие именно попыток №1–5: сравнивать со своим снимком данных.

Остановить backend. В корне локального репозитория:

```powershell
git status
git fetch origin
git switch feature/issue-30-safe-media-store
git pull --ff-only
git rev-parse HEAD
```

Ожидаемый SHA приведён выше. Если ветка ушла вперёд, зафиксировать новый SHA и повторно сверить diff перед исполнением. При локальных изменениях сохранить их отдельно; принудительное удаление изменений не требуется.

В каталоге backend, с обычными ранее настроенными параметрами подключения:

```powershell
$env:GUITAR_MENTOR_ENABLE_UPLOADS = "true"
.\mvnw.cmd spring-boot:run
```

Frontend и Caddy запущены по прежней инструкции. Подготовить синтетические аудио без личных данных: короткие валидные WAV/MP3/OGG/WebM; WAV 120 и 125 с; пустой файл; текст под .mp3; неподдержанный .txt; граничные размеры для технического блока.

**BASE** ниже = `https://guitar-mentor/api/v1/learners/{learnerId}/diagnostic-sessions/{sessionId}/tasks/{taskId}/attempts`. Подставляются реальные ID одного тестового ученика и назначенного ему задания; не копировать чужие ID из истории переписки. POST = multipart `file`, UUID `requestId`, optional `comment`.

**Технические проверки:** только отдельная тестовая БД и temp-root. PostgreSQL integration создаёт фикстуры и временный SQL CHECK; не запускать его на БД владельца с рабочей историей. Настроить `SPRING_DATASOURCE_URL/USERNAME/PASSWORD` для выделенной тестовой БД, включить `GUITAR_MENTOR_TEST_POSTGRES=true` и выполнить `.\mvnw.cmd --batch-mode verify` в backend. Без этого флага integration будет пропущен и результат не покрывает 14–16. Java CI уже содержит изолированную PostgreSQL 17 и HTTP smoke; новый прогон выполняется отдельно по команде на тестирование.

Нет публичного delete endpoint: 10–19 выполняются на уровне unit/integration/изолированного тестового стенда, не через придуманный REST API. Для каждого примера в матрицах фиксировать отдельный фактический результат; общий PASS допустим только после всех примеров.
