# #229 — профиль, анкета и настройки аккаунта

Дата: 26.10.2026. База: `main e302f0dd15211f71f97baf91ada5fdadcb598083`.
Ветка: `feature/229-profile-onboarding-ux`. Связанная задача: [#229](https://github.com/roafo1989/guitar-mentor-ai/issues/229).

## Реализованное поведение

- `/profile`: единая карточка предпочтений, опыта, ритма занятий, целей и навыков; явное редактирование каждой части, три варианта отношения к каждому стилю, заметное подтверждение. Имя берётся из общего learner store; существующий API изменения имени не поддерживает, поле остаётся только для чтения у сохранённого ученика.
- `/settings/account`: существующая смена пароля и подключение способов входа вынесены из профиля. Способы входа показываются только после успешного валидного ответа API. Подключение Google раскрывается только по кнопке, поясняет подтверждение текущего аккаунта Guitar Mentor AI и последующий переход к Google; пароль подтверждения изолирован от формы смены пароля. Ошибка чтения предлагает retry и не открывает формы на основании предположений.
- `/onboarding`: опыт → цели и интересы → ритм занятий. Произведения вводятся отдельными полями, до 10, без парсинга `|`; название обязательно, исполнитель необязателен. Лимиты сохранены из `OnboardingDtos`.
- Черновик анкеты хранится в памяти, сохраняется при переходах назад. При выходе предлагается остаться или отказаться; refresh/tab close использует native beforeunload. Ошибки GET не открывают запись; read/draft conflict требует явной загрузки серверной версии. Ошибка PUT сохраняет ввод, двойное сохранение блокируется.
- На шагах 1 и 2 есть отдельная кнопка «Сохранить изменения»: сохраняет всю текущую анкету без перехода и показывает подтверждение рядом с действием. «Продолжить» только переключает шаг. После финального сохранения на шаге 3 показывается завершение с одной основной CTA, рассчитанной существующим `resolveHomeSummary`. Retry следующего шага не повторяет PUT. Редактирование анкеты не создаёт новую диагностическую сессию и не меняет историю попыток.
- «Навыки»: самооценка анкеты отдельно; реальные `OBSERVED`/`MEASURED` из существующего skillMap API выводятся с источником. Самооценка не означает подтверждения, проценты и новые уровни не генерируются. Ошибка получения наблюдений отличается от пустого результата.
- Смена ученика/аккаунта инвалидирует поздние ответы и очищает черновик. Старые `/profile#authAction=link` письма совместимы: маршрут перенаправляется, секрет удаляется из URL до запуска роутера, не попадает в поле или storage.
- Новые строки RU/EN; внутренние DEV/MVP/PostgreSQL подписи убраны из затронутых экранов и footer. Breakpoint шапки скорректирован: навигация больше не перекрывается инструментами на 1440.

Java/API/БД и миграции не менялись.

## Ревью

Проведено авторское ревью полного diff по требованиям #229, auth/session isolation, read/write gates, обработке ошибок и доступности. Это не независимое ревью другим разработчиком.

Найдено и исправлено до передачи:

1. Failed methods GET раньше мог показать неподключённые способы входа как факт — добавлен gate и retry.
2. Поздняя мутация learner store при смене auth actor — добавлена проверка actor и захват learner id до запроса.
3. Совместимость писем после переноса PasswordSettings — добавлен ранний capture/scrub и маршрут settings, без Java изменений.
4. Потеря клавиатурного фокуса при удалении последнего произведения — фокус возвращается на добавление.
5. Перекрытие навигации инструментами на desktop — скорректирован breakpoint; повторная визуальная проверка.

По итогам повторного просмотра блокирующих замечаний к согласованному frontend-объёму не осталось.
