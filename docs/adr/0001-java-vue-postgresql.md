# ADR-0001 — Java + Spring Boot, Vue и PostgreSQL

- **Статус:** принято для следующего этапа разработки (решение от 18.10.2026)
- **Проект:** Guitar Mentor AI — персональный ИИ-наставник по игре на гитаре
- **Область решения:** основной язык, приложения-клиенты, БД и минимальная инфраструктура

## Контекст

Проект некоммерческий, бюджет на инфраструктуру минимален. Предполагаются один или несколько учеников, упражнения, ноты/табулатуры, история проверок и записи исполнения, обратная связь ИИ. Основной разработчик имеет опыт Java, Spring Boot, JHipster, Hibernate ORM/Criteria API, MVC и немного Vue.js (опыт около 4 лет назад). VS Code доступен, IntelliJ IDEA — нет. Разработка ведётся на Windows 10.

Изначально был создан экспериментальный Python-каркас DEV-01 в [PR #5](https://github.com/roafo1989/guitar-mentor-ai/pull/5). Его **не нужно сливать в `main` как основу нового backend**; PR сохраняется до отдельного решения о закрытии. Старая инструкция сохранена в [архиве](../development/archive/python-workstation-2026-10.md).

## Решение

1. **Основной backend:** Java 21, Spring Boot 4.1.x, Maven с Maven Wrapper, модульный монолит с REST API. Фреймворк Spring AI 2.0.x подключать по мере появления реальных ИИ-сценариев; не создавать агентную инфраструктуру заранее.
2. **Frontend:** Vue 3 + Vite, адаптивный веб-интерфейс. Для локальной разработки возможен dev server Vite, в развёрнутом MVP статические ресурсы фронтенда могут раздаваться одним Spring Boot приложением.
2a. **Структура Vue:** взять знакомые по JHipster принципы организации без самого генератора: разделы `entities/` (компоненты и сервисы по предметным сущностям), `router/`, `shared/model/`, `core/`, `shared/components/`, `stores/` (Pinia), `i18n/ru/*.json` и `i18n/en/*.json` через `vue-i18n`. REST-вызовы выносить в `*.service.ts`, модели — в TypeScript, подписи полей/кнопок — в файлы локализации. Нестандартные пользовательские сценарии (запись исполнения, практика, табулатуры) не принуждать к CRUD-шаблонам. Для frontend использовать Vue 3 + TypeScript + Vite, расширение VS Code `Vue (Official)`, ESLint/Prettier.
3. **Telegram:** дополнительный интерфейс/адаптер к тем же application services и данным, а не второй backend. Возможность Mini App исследовать после появления работающего веб-интерфейса. Не считать Mini App гарантированной заменой мобильному браузеру до проверки записи аудио.
4. **База данных:** PostgreSQL как **единая целевая СУБД** для локальной разработки и размещения. Для Java выбрать Spring Data JPA/Hibernate; схему менять версионированными миграциями Flyway. На продакшене Hibernate `ddl-auto=validate`, не `update`/`create`. Доступ к БД через переменные окружения / секреты.
5. **Тестирование:** JUnit; интеграционные тесты по возможности против PostgreSQL (в CI — контейнер, локальный Docker необязателен). Не полагаться только на H2, чтобы не скрывать различия SQL.
6. **Инфраструктура:** для начала один Spring Boot сервис и один экземпляр PostgreSQL на одной машине; без Kubernetes, брокеров сообщений, микросервисов и отдельного Python API.
7. **Аудио/видео:** временные файлы хранить вне репозитория. Автоматически удалять обработанные исходники с коротким сроком хранения по политике проекта; метаданные, оценки и решения сохранять в БД. При разработке закрепить точный срок и исключения отдельным решением. Python можно подключить позже как специализированную подсистему обработки аудио, только если Java-инструментов окажется недостаточно.

## Почему PostgreSQL, а не SQLite

SQLite **хватит по нагрузке** для небольшого проекта: это надёжная встроенная БД без отдельного процесса. Но в связке Spring Data JPA/Hibernate PostgreSQL проще поддерживать: Hibernate поддерживает `PostgreSQLDialect` в основном модуле, а `SQLiteDialect` — в отдельно подключаемом `hibernate-community-dialects` с более ограниченной поддержкой. PostgreSQL также обеспечивает независимые параллельные транзакции и удобен для возможного роста до нескольких учеников/интерфейсов.

**Издержка:** PostgreSQL требует установки/работы сервера и правильного резервного копирования. Лицензия PostgreSQL бесплатна, однако ресурсы VPS, диск и администрирование не бесплатны. Чтобы не увеличивать бюджет, для MVP не покупать выделенный managed PostgreSQL; по возможности запускать БД на том же хосте. Сравнить эксплуатационные расходы при выборе хостинга.

**Не выбираем SQLite сейчас**, чтобы не тратить время на проверку нестандартного Hibernate-диалекта и не поддерживать две схемы SQL. **Не используем SQLite локально и PostgreSQL в продакшене**, так как расхождения проявятся поздно.

## Правила предметной модели

- Рекомендация ИИ и решение ученика **не одно и то же**. Ученик вправе завершить задание и перейти дальше, даже если критерии агента не выполнены. Отдельно сохраняются: результат проверки, недочёты, решение ученика и причина перехода. Подтверждение навыка не выставляется автоматически только на основании перехода.
- Доменные правила и права на переход реализуются в Java/application service; LLM только предлагает оценку или следующее упражнение. Учитывать повторные попытки и полную историю.
- Web и Telegram должны работать с одной идентичностью ученика (после безопасного связывания учётных записей) и единой историей.
