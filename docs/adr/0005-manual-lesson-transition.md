# ADR0005 — следующее занятие без перезаписи диагностического задания

**Дата:** 25.10.2026. **Статус:** проект технического решения для #216; бизнес-объём одобрен владельцем. Решение внедряется и проверяется в разработке. База main c4bb865.

## Контекст

Уже существуют UNIQUE task/session и UNIQUE active session/instrument. Attempts, learning state, критерии и решения связаны с taskId, evidence intake — с sessionId. Самостоятельное завершение task не освобождает diagnostic session. Переиспользовать start невозможно: он правильно возвращает текущую сессию, а assign запрещает замену существующего упражнения.

## Решение

Для явного next создать новую session и task, архивировать source session в одной транзакции; сохранить все старые связи. Отдельная durable lesson_transitions связь задаёт единственного successor и idempotency/replay. ARCHIVED — техническое состояние сессии после создания successor, не оценка навыка. Новая session минует повторный intake и получает тот же instrument profile; current исключает ARCHIVED, исторический GET продолжает читать его.

Версия упражнения закрепляется в новом task; выбор другой current version без повторного согласия клиента запрещён. Повтор прежнего упражнения допустим с новым task. История занятий читает реальные старые и новые назначения, без backfill искусственных результатов.

## Рассмотренные варианты

| Вариант | Причина отказа |
| --- | --- |
| UPDATE exercise_id существующего task | Смешивает попытки, версии и критерии; уничтожает смысл истории |
| Удалить session key и снова вызвать start | Сервер вернёт прежнее задание; создаёт ложное ощущение перехода |
| Разрешить много task на diagnostic session | Меняет currentTask, upload/history/learning contracts и UNIQUE; значительно расширяет инкремент |
| Новая самостоятельная доменная модель курса целиком | Больше миграций и адаптеров, чем требуется для ручного продолжения |

## Последствия

Нужна аддитивная migration enum/check и таблица переходов; старый код не понимает ARCHIVED. Поэтому backend/frontend поставляются согласованно; после реальных переходов откат только с совместимым читателем либо через проверенный backup, без удаления истории. Конкуренция: learner→session→learning state, проверка graph на тестах. Scope #24 ограничивается будущими персональными правилами/рекомендациями, которые используют этот переход, не создают вторую модель назначения.
