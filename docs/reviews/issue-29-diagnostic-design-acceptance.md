## 3. Фактический MVP и проектная целевая модель — не смешивать

| Аспект | Подтверждённый срез к 19.10.2026 | Целевое продолжение (не является результатом #29) |
| --- | --- | --- |
| Сессия | COLLECTING_EVIDENCE → READY_FOR_TASK → TASK_ASSIGNED, start GET continue; одна активная сессия инструмента | CLARIFYING / ASSESSING / REVIEW_READY / COMPLETED, согласование результата |
| Диагностические задания | Каталог/назначение GM-EB01; версии учебного материала | ≥5 этюдов и метроном (#17), карта навыков/подбор (#16) |
| Отправка | Аудиопопытки назначенного задания, локальная обработка формата/длительности, история (#20) | Свои произведения и ноты *до* назначения (#68); проверка качества исполнения (#14/#15/#31/#22/#23) |
| Отзыв и решение | `PROCESSED` = файл технически обработан, `assessmentAvailable=false` | Версионированная Assessment и StudentDecision, переход без MASTERED (#18/#19), LearningPlan (#24) |
| Медиа | Приватный storage вне БД; safe delete/rollback (#30 принят) | 48 ч от окончания всех проверок, unprocessed 48 ч, cleanup 60 мин — *настроечная целевая политика* #21, а не действующий сервис |
| Безопасность | Проверка связи learner/session/task, без учётных записей/аутентификации | Полная серверная авторизация и доступ только по приглашениям (#38/#42) перед интернет-публикацией |

### Границы доверия и оценивания

1. `SELF_REPORTED` — слова ученика; `INFERRED` — гипотеза агента; `MEASURED` — проверяемое измерение с методом/ограничениями; `NOT_ASSESSED` — данных нет. Не использовать общую численную оценку как замену доказательств.
2. `Assessment` должна относиться к конкретной попытке и критерию. Ранее полученные попытки сохраняются в истории; повтор не стирает сведения.
3. `StudentDecision` отдельно хранит `AGREE`, `RETRY`, `REQUEST_MORE_EVIDENCE`, `ACCEPT_WITH_NOTES` (коды пока предварительные). Ученик вправе продолжить вопреки совету пересдать; подтверждение навыка при этом **не** происходит.
4. Следующий шаг и допустимые переходы определяет детерминированное приложение, а не свободный текст LLM. Не обещать точное распознавание нот/ритма до экспериментов #14/#15/#31.

## 5. Что принимает владелец

**Предмет решения:** одобрить *проектные правила и артефакты #29*, не работу полного диагностического агента. Подтверждаются необязательные собственные записи; выбор коротких проверенных этюдов; объяснимые категории свидетельств; самостоятельное решение ученика и история; временность хранения/недопустимость необоснованных выводов ИИ.

**Не входит в приёмку #29:** автоматическое определение уровня/темпа/нот, штатная очистка медиа, работа с собственными нотами до назначения, полноценная авторизация и общая готовность US-002.

**Решение ревью:** `READY_FOR_OWNER_ACCEPTANCE`. До разрешения владельца не считать #29 завершённой, не закрывать Issue и не сливать этот PR. Пакет PR #64 остаётся самостоятельной зависимостью актуализированных документов.

**Предлагаемый Kanban после публикации ревью:** `Тестирование / Ожидание` (согласование документационного результата); затем после явного утверждения владельцем — `Завершение / Выполнено`. Если прямое изменение GitHub Project недоступно, это предложение не объявляется применённым полем.
