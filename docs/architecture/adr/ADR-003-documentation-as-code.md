# ADR-003 — Documentation as Code

**Статус:** принято (2026-10-18).

## Контекст
Guitar Mentor AI — некоммерческий учебный проект небольшой команды. Требования, Use Cases, архитектура, PlantUML и исходный код изменяются согласованно. Поддержка отдельной базы знаний сейчас добавила бы дублирование, стоимость сопровождения и риск расхождения версий.

## Решение
- GitHub — основной источник истины по технической документации и разработке.
- Документы хранятся в Markdown, схемы — в исходниках PlantUML (`.puml`) в `docs/`.
- Изменения документации проходят через ветки и Pull Requests вместе с зависимыми изменениями кода.
- Задачи и дефекты отслеживаются в GitHub Issues; связь с требованиями и PR указывается явно.
- Оглавление — `docs/index.md`, а `README.md` ссылается на него.
- Если навигации GitHub станет недостаточно, можно собрать локальный портал MkDocs без создания второй редактируемой копии документации.

## Последствия
- Можно ревьюить бизнес-правила, код и тесты в одном PR.
- Ученику-разработчику нужно освоить Markdown/PlantUML и Git workflow.
- Диаграммы с отображением в интерфейсе при необходимости рендерим из `.puml`; изображение — производный артефакт.
- Публичную публикацию сайта документации для приватного репозитория без отдельного решения не включаем.

## Правила актуализации
- При изменении бизнес-правила обновить связанную спецификацию, диаграмму и тесты (если имеются).
- Для архитектурно значимых решений завести ADR с контекстом, решением и последствиями.
- При добавлении нового раздела обновить `docs/index.md`.
