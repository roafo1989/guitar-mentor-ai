# CATALOG-169 research prototype

Synthetic-only research harness. No user uploads, external search, AI, production queue, or user data.

## Pinned tools

- Node.js 22.16.0 (node:22.16.0-bookworm-slim)
- alphaTab 1.8.4
- PDFKit 0.17.2
- svg-to-pdfkit 0.1.8
- Python 3.12.10 for fixtures only
- PyGuitarPro 0.11 + attrs 25.3.0 for independent GP3/4/5 fixture generation only
- Complete npm graph is pinned in package-lock.json generated by the first research workflow run.

## Run

Linux or Windows PowerShell with Docker Desktop Linux containers:

    ./scripts/research/catalog-169/run-linux.sh

    ./scripts/research/catalog-169/run-windows.ps1

The conversion container has no network, 512 MiB memory, 1 CPU, 60-second watchdog, read-only root FS and 100 MiB /tmp tmpfs. Only /out is writable. Docker is the measured container boundary, not a claim of a general OS sandbox.

Outputs: PDF, WAV, SVG systems, event JSON, generated GP7 sample and run manifest in artifacts/catalog-169. CI uploads this evidence.

Static checks:

    node scripts/research/catalog-169/verify-fixtures.mjs
    node --check scripts/research/catalog-169/runner.mjs
    python -m py_compile scripts/research/catalog-169/generate_fixtures.py

GP3/4/5 files are authored synthetic fixtures generated by PyGuitarPro 0.11 and independently imported by alphaTab. GP7 is generated by alphaTab exporter and round-tripped by alphaTab; that is not independent writer interoperability. No third-party or private fixtures are used.
## CI behavior

The research workflow runs on branch pushes and pull requests targeting `main`. It has read-only repository permissions: fixtures and lockfiles are generated only in the runner workspace and are never committed by CI. The run manifest records the SHA-256 of the exact `expected-events.json` file bytes, matching the fixture manifest.
